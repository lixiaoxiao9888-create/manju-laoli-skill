# 观众留存分集规划

> 精编自《灵境AI剧本改编 skill》（6阶段编剧链）

本文件覆盖阶段④的完整规范：分集策划岗位与九遍工作流、观众理解与追看机制、分集边界与长线编排、编剧室分集结构模板与短剧结构速查。

## 一、岗位定位与边界

### 1.1 岗位定义

分集策划是把「已经成立的完整故事」重新组织成「观众可以一集一集理解、获得满足并愿意继续追看」的编剧室岗位。核心不是「把小说切成多少段」，而是同时回答：

1. 观众能否看懂这一集主要讲什么？
2. 观众能否说清谁要什么、受到什么阻挡、如何换策、结果改变了什么？
3. 观众本集获得了什么真实结果或情绪兑现？
4. 观众为什么还要看下一集，而且下一集如何马上兑现？

追看来自清楚的未完成问题、人物或利益投入和可信兑现，不来自故意讲不清或把完整动作腰斩。

分集策划不承诺市场必然爆款，但必须消除可预防的弃看原因：开场不知所云、中段只有解释、结尾没有结果、卡点只截半句话、人物关系无故变化、相邻集重复同一冲突。

### 1.2 与其他阶段的边界

| 阶段 | 核心问题 | 阶段④不能替代的内容 |
|---|---|---|
| ② IP 与角色开发 | 这个人是谁，观众为何记住和喜欢 | 不重新发明人物灵魂、外形和声音 |
| ③ 全剧开发圣经 | 这是什么故事，事实、规则、因果和价值是什么 | 不擅改真相、主线、人物终局和世界规则 |
| ④ 分集策划 | 观众按什么顺序、以什么节奏消费故事 | 不展开正式场次、完整对白和镜头 |
| ⑤ 剧本改编 | 每一集具体怎样演、怎样说 | 阶段④不能用「后面写剧本再解决」掩盖目标和钩子不清 |

阶段④的专业价值是做选择：保留什么、合并什么、哪项先让观众知道、什么事件属于同一集、在哪个不可逆变化后结束、下一集第一步怎样兑现。

### 1.3 为什么不能按章节或字数平均切

小说章节服务阅读节奏，可能包含大量心理、背景、回顾或作者解释；短剧单集服务视听行动和连续追看。两者的最小单位不同。

- 一个小说章节可能只有一个动作，却有大量解释，不能自动成为一集。
- 三个相邻章节可能共同组成一次完整行动，拆开会变成三个片段。
- 一个章节也可能包含两个不可兼得的目标和两次状态变化，需要拆成两集。
- 字数相同的两段，表演时长可能完全不同：争辩、动作、沉默、群体反应和规则首建都需要时间。

正确的分集依据是「不可逆状态变化与观众等待问题」，不是章节名、字数或固定 90 秒。

## 二、模式门禁与上游门禁

只读取已锁定的阶段②和阶段③：`01_IP_BIBLE`、`IP_CANON_MANIFEST.json`、`02_STORY_BIBLE`、`STORY_CANON_MANIFEST.json` 及其交付文件。以下任一情况立即停止并输出 `BLOCKED_REPORT`：

- 任一上游状态不是 `LOCKED` 或存在失败标记。
- `ip_version`、`story_version` 或人物 ID 不一致。
- 阶段③的全源覆盖、事件账本、人物因果、容量诊断或钩子候选未通过。
- 用户指定范围不足以回答所要求的终局问题，又没有授权新增事实。

`STEPWISE` 完成阶段④后等待用户确认；`FULL_SCRIPT_PIPELINE` 自检和校验清单通过后锁定阶段④，再进入阶段⑤。

### 分集方式选择门禁

正式排集前必须先确定 `episode_count_mode`，只允许两种：

1. `SMART_RECOMMENDED`（智能推荐集数，推荐）：根据阶段③的容量区间、事件负荷、完整故事单元、情绪支付和有效断点，自动给出精确集数与理由。
2. `USER_DEFINED`（用户自定义集数）：用户指定目标总集数，系统先核对容量与质量代价，再按该目标规划。

`STEPWISE` 进入阶段④时，若用户尚未选择，先原样提供：

```text
请选择第三步的分集方式：
1. 智能推荐集数（推荐）：系统根据小说容量、每集60—180秒、完整故事单元和钩子位置给出最合适的总集数。
2. 用户自定义集数：由你指定想制作的总集数。

请直接复制下面任意一种格式回复：
- 如果希望系统自动决定集数，回复：1
- 如果希望自定义为60集，回复：2，60集
- 如果希望自定义为80集，回复：2，80集

你也可以直接回复"智能推荐"或"自定义60集"，系统都能识别。
```

用户只选择第 2 项而未给出数字时，回复「请告诉我想制作的总集数，例如：60集」，不得先生成详细分集。接受中文逗号、英文逗号和自然语言表达，不要求用户理解内部枚举名。用户已经明确过选择时不得重复询问。

`FULL_SCRIPT_PIPELINE` 中，用户未指定总集数时自动使用 `SMART_RECOMMENDED`；用户已明确指定总集数时使用 `USER_DEFINED`。若自定义数字低于或高于阶段③容量区间，必须先输出 `CAPACITY_CONFLICT_AUDIT`，说明压缩或扩展代价、`MUST_KEEP` 保护方式与推荐方案；只有用户明确确认仍按该数字执行，才能记为 `CONFIRMED_OVERRIDE`。即使是全流程模式，也不得把未确认的重大容量冲突自动视为同意。

自定义集数是规划目标，不是删除因果、遗漏人物选择、虚构内容或用重复争吵、空场、假反转凑数的授权。若用户坚持的数字无法同时满足 60—180 秒、来源完整性和单集理解门，输出 `BLOCKED_REPORT` 并给出最接近的可行集数，不生成伪合格方案。

### 必须读取的输入

读取 `PROJECT_PROFILE`、目标受众、目标集数或时长要求、`IP_CANON_MANIFEST.json`、`IP_ARC_BINDINGS`、`STORY_CANON_MANIFEST.json`、`ADAPTATION_BLUEPRINT.md`、`SERIES_CAPACITY_REPORT.md`、`HOOK_CANDIDATE_LEDGER.md`、`WORLDVIEW_VALUE_BIBLE.md`、事件/人物/规则账本、信息矩阵、伏笔回收账本和来源追踪。

## 三、九遍策划流程

### 第一遍：消费集数选择并锁定精确集数

先记录 `episode_count_mode`。声明 `source_scope`、闭合类型、60—180 秒时长区间和精确集数。默认约 90 秒，但完整故事单元优先。

- `SMART_RECOMMENDED`：读取阶段③的最小值、推荐值和最大值，在区间内按自然故事单元与钩子质量确定最终精确值；最终值可以因更完整的断点审计而不同于阶段③推荐值，但必须说明差异。
- `USER_DEFINED`：记录 `user_requested_episode_count`，精确集数必须与之相同。若超出容量区间，先完成冲突审计和用户二次确认；无法保住核心因果与 `MUST_KEEP` 时阻断。

无论哪种模式，都要写 `capacity_reference` 和 `capacity_conflict_audit`，不得用空场、重复争吵或假反转凑数。

锁定精确集数时必须记录：`episode_count_mode` 与选择来源；`user_requested_episode_count`（智能推荐为 `null`）；`exact_episode_count` 和明确的选择理由；`duration_range_seconds` 和默认目标时长；阶段③的最小值、推荐值、最大值和来源；容量区间与最终采用值的差异；压缩、合并、扩展分别影响哪些事件和人物弧；为满足数字可能损失的 `MUST_KEEP`、因果、情绪或回收。

冲突状态只允许：`WITHIN_RANGE`（最终集数位于容量区间）、`BELOW_RANGE`（自定义集数低于区间，必须说明合并、降载和无法保留项）、`ABOVE_RANGE`（自定义集数高于区间，必须说明可合法展开的情绪、关系和过程，以及禁止使用的注水手段）。

### 第二遍：标注事件归属与可压缩性

将每个事件 ID 标为 `ATOMIC`、`COMBINABLE`、`MONTAGEABLE` 或 `CALLBACK_ONLY`。所有选定事件必须且只能一次作为 `PRIMARY_EVENT` 落入某集，其他出现只登记为 `CALLBACK`。`MUST_KEEP` 事件不得遗漏。

### 第三遍：建立开篇爬坡与大弧

用 `OPENING_RAMP` 证明题材异常、主角损失与目标、能力及限制、关键关系和长线升级引擎。用 `ARC_MAP` 记录每个大弧的驱动问题、升级逻辑、情绪线、局部兑现、高潮和出口状态。

### 第四遍：建立完整单集故事单元

每集围绕一个主目标和主要行动问题，填写进入压力、主动目标、首次策略、对手或规则反制、策略变化、冲突升级、可见代价、局部结果和新压力。无法写出反制、换策、代价或局部结果时，它通常只是信息片段或过场，必须合并或重排。

### 第五遍：建立观众理解契约

每集先写 `EPISODE_THESIS`、`VIEWER_TAKEAWAY`、`VIEWER_EMOTION` 和 `ONE_SENTENCE_RECALL`，再写 `COMPREHENSION_CONTRACT`（字段见第六节 6.2）。冷启动观众若不能在看完后复述「谁想做什么、遇到什么、怎么改变办法、结果怎样」，本集不通过。

### 第六遍：建立局部兑现与追看契约

先写本集 `local_payoff`，再写 `RETENTION_CONTRACT`（字段见第六节 6.3）。钩子必须是具体行动、选择、证据、到场、危险、身份验证或关系变化。空泛威胁、突然黑屏、重复揭露、无来源巧合和只截断半句话不算有效钩子。非终局集的下一集必须先承接主钩子，不能跳线拖延。

### 第七遍：编排情绪、关系与 IP

每集写 `EMOTION_CURVE` 的进入、累积、转折、情绪兑现和余味。`IP_DRAMATIZATION` 必须填写 `soul_test`、`affection_beat`、`flaw_consequence`、`behavior_anchor`、`voice_rule`、`relationship_signature` 和 `growth_state`，让灵魂选择、喜爱证据、缺点后果、行为锚点、声音规则和关系信号落入本集行动；使用 `PRIMARY`、`VARIATION`、`PAYOFF`、`WITHHELD_WITH_REASON` 控制记忆点密度，禁止机械重复口头禅。

### 第八遍：检查边界、连续性与防重复

每个断点说明故事理由、观众理由和前后承接理由。单集必须在不可逆状态变化之后结束，下一集以新目标、新策略或上集钩子的第一兑现动作开始。

每集写 `CONFLICT_SIGNATURE`：`pressure_pattern`、`resolution_pattern`、`novelty_from_previous`。连续三集使用相同压力模式和解决公式，必须重排。逐集核对日期、日夜、倒计时、知识、资源、伤势、关系和危险状态。

### 第九遍：三种观众终审

- 冷启动观众：是否无需内部术语也能看懂本集？
- 连看观众：是否感到事件、关系或资源真实推进，而非重复上一集？
- 挑剔观众：本集是否兑现了上一集承诺，钩子是否诚实可支付？

结论只能是 `PASS`、`REVISE` 或 `REPLAN`。核心理解、局部兑现、事件覆盖、来源真值或钩子支付失败时不得锁定。

### ★ CAUSALITY_AND_RELATION_TABLE · 因果与关系表（2026-10-12 新增 · 阶段④ 强制产出）

> **由来（粉丝群实测反馈）**：「skill 剧本创作**希望能加入因果关系，还有人情世故这些**，感觉有一些是没有因果关系逻辑的」
> 「有些东西他**理所当然的以为是这样了，但是具体并没有介绍出来**」「**剧情跳的太快了**」。
> **病根**：本引擎此前只有「因果节拍表」与「删减影响审计」两处**检查性**因果记录，
> **没有一张要求"每场戏把前因→触发→后果写出来"的产出件**，也没有"人情世故 / 关系利害"这一层——
> 于是"理所当然"的东西（谁跟谁是什么关系、为什么他会这么做、这事为什么轮得到他）全靠模型自补，一自补就跳。

阶段④ 交付 `03_episodes/` 时必须附本表（每集一张，随稿传下游分镜层）：

```
【因果与关系表 CAUSALITY_AND_RELATION_TABLE · EP__】
  人物关系矩阵（人 × 人）：关系 / 利害 / 亲疏 / 权力方向 / 欠与债
    例：陈舟—站长：同一平台同事→竞争单量；陈舟—女儿：抚养方→唯一软肋
  场次因果链（逐场）：
    场次 X｜前因：（上一场留下了什么条件/后果）｜触发：（谁做了什么）
         ｜后果：（不可逆地改变了什么）｜为什么轮得到他（人情/利害/性格依据）
  人情世故清单（每集 ≥3 条，逐条写"谁凭什么这么做"）：
    例：站长不直接开除陈舟 = 平台工龄折算 + 年会当天曝光成本，扣人会被平台约谈
  ⛔ 理所当然禁令：凡"默认应该发生"却无人解释的设定，一律回填进本表或改写
```

**六条铁律**：
1. **逐场三段式**——每场必须写满 **前因 → 触发 → 后果**；缺任一段即视为该场没交代清楚。
2. **"为什么轮得到他"必写**——这是"人情世故"的落点：把人物行为挂回利害关系/性格/历史，而不是挂回剧情需要。
3. **人情世故清单 ≥3 条/集**——写明"谁凭什么这么做"；没有利害支撑的行为一律改成有代价的选择。
4. **人物关系矩阵进本表**——上游《人物锚卡》/关系引擎矩阵的关系与利害，在此落成可查的矩阵，并随 `HANDOFF_CARD` 传到分镜与台词层。
5. **⛔ 理所当然禁令**——凡"按常理应该如此"却**没人解释过**的设定，必须回填本表或改写；**禁留作"默认设定"交给模型自补**（粉丝原话：模型会"理所当然的以为是这样了"）。
6. **情节点密度下限（治"剧情跳太快"）**：
   - **15 秒投喂段 ≥1 个情节点**（一次意图变化 / 一次关系变化 / 一次信息翻转，任一）；
   - **单集 ≥5 个情节点**，且相邻情节点之间**不得跨过一场戏**——即"这一场的后果必须在下一场被看见"；
   - 一集内情节点 <5，或任一 2 句台词内跨了两次时空跳切，**判 `REVISE`**（不许锁稿）。

### ★ TRANSITION_AS_BEAT · 过渡即戏点（2026-10-13 新增 · 用户实测反馈 · 阶段④ 强制）

> **由来（用户实测反馈 2026-10-13）**：「你这个逻辑没对……事实上是**你的剧本，就是整个剧情设计的问题**，跟分镜这些东西没关系」；
> 「段一是大哥和那个女角色在那儿对话，到段二的时候**一下就是四个人在那儿了**，**它得有一个什么过渡吧**」。
> **病根**：本套此前把「过渡」当成**分镜层的技术补丁**（C17e 人数变化交代、景别承接）——**方向错了**。
> 过渡的本质是**剧本层的一个戏点**：它要么加信息、要么加人物、要么加情绪，**不是填缝**。
> 分镜层只能"补交代"，补不出"戏"；**戏必须在剧本阶段就设计出来**。

阶段④ 交付 `03_episodes/` 时，**每两个相邻场次之间必须指定一个过渡设计**（写进场次卡，随稿传下游）：

```
【场次过渡设计 TRANSITION_AS_BEAT · EP__ 场X→场Y】
  过渡类型（四选一，见下表）
  过渡内容（一句写清"这一下给观众什么"）
  是否承载新信息（是 → 写清是什么信息；否 → 说明为何必须是纯节奏过渡）
  ⛔ 禁止项：不得只写"接着/随后/不久后"这类时间副词当过渡
```

**四种过渡类型（按"加戏量"从高到低，优先选上三种）**：

| 类型 | 写法 | 加什么 | 例（用户原话场景） |
|---|---|---|---|
| **① 动作桥（人物带戏过渡）** | 用某个人物的**一个动作**把观众带过去；动作本身合情合理、且透露状态 | **加人物状态 + 加信息** | 「拍一个他们送外卖那个，**他哒哒哒跑进来**，跑一个这样的声音」——跑进来 = 他迟到了/他刚下班/他不情愿来，一句话不说就把人物立住了 |
| **② 空镜叙事（环境承载过渡）** | 用一个**承载情绪或信息的空镜**扫过，再进新场 | **加情绪 + 加空间** | 「从段一最后结尾的时候**灵堂扫一下**，或者段二开头灵堂那扫一下，然后过渡到他们四个人在那儿商量」——灵堂 = 遗像 + 白花 + 没撤的供桌，直接压住全场的"父亲刚走" |
| **③ 声音桥（画外先声）** | 新场的声音**先于画面出现**（脚步 / 敲击 / 争执 / 电话铃） | **加悬念 + 加节奏** | 段1 末镜句尾「门外由远及近传来两个人的脚步声」；声音必须是**新场里真实存在**的声音，不是音效贴片 |
| ④ 硬接（时间副词） | 直接进新场 | 无 | ⛔ **默认禁止**，仅在"刻意制造突兀/惊吓"时用一次，且须在过渡设计里写明理由 |

**四条铁律**：
1. **过渡必须选①②③之一**——⛔ 默认禁止用"随后/接着/转眼"这类时间副词硬接（④ 需写明理由）。
2. **过渡必须承载新信息**——若一个过渡只起"时间流逝"作用、不给任何新信息，则**它不是过渡、是拖时长**，删掉或加料。
3. **过渡的落点写在场次卡上**——写明"挂在前场末尾 / 挂在后场开头"（两种都行，但必须指定一个，**不得两处都不写**——这正是段1→段2 断层的直接成因）。
4. **人物进出场要挂过渡**——凡相邻两场**在场人物集合变化**，新登场人物必须走①②③之一进场（**"走进来"是①动作桥，"先闻其声"是③声音桥**）；分镜层机检 **C17e** 只做兜底，**剧本层必须先有设计**。

⚠️ **与分镜层的分工（改前必读）**：
- **剧本层 = 造过渡**（本节）：过渡是戏点，要有内容。
- **分镜层 = 落过渡**（`segment-splicing.md` §四·补二 + 机检 C17e）：把剧本层定好的过渡，写成镜行里可执行的画面/声音，并做人数变化的兜底告警。
- **颠倒这个分工 = 本末倒置**：此前把过渡当分镜技术补丁，结果"补了交代、没补戏"——观众看到的仍是一段干巴巴的"人物走进来"。

## 四、观众理解、情绪满足与下一集追看

### 4.1 追看动力公式

观众不会阅读分集表、人物小传和事件账。他们只接触眼前这一集。分集策划不能用「后面会解释」掩盖当前无法理解，也不能把「有悬念」误当成「愿意追看」。

可用一个非数值公式检查追看动力：

`追看欲 = 具体未完成问题 × 人物或利益投入 × 已被证明会兑现 − 理解负担 − 重复感 − 被拖延感`

任何一项接近于零，钩子再大声也可能无效：不知道问题是什么，观众不会等答案；不在意谁承担后果，观众不会关心答案；前面多次不兑现，观众不再相信答案会来；本集什么也没完成，观众感到被截断而不是被吸引。

### 4.1.1 悬念存量配额（★ 2026-10-13 新增 · 治「悬念基本归零」）

> **由来（粉丝系统性实测反馈）**：「**悬念基本归零**」。
> **病根**：本包的悬念机制全是**逐集**的（每集有没有钩子）——「每 15-20 秒一个钩子」只要"本集有个钩子"就能全绿；但**每集钩子当集就兑现 → 整部剧没有任何长期悬着的问题 → 观感上悬念归零**。**逐集机制撑不起跨集悬念。**

三条存量配额（**进入阶段④时与 `ARC_MAP` / `HOOK_PAYOFF_LEDGER` 同批填写，缺任一条即 `REVISE`**）：

1. **同时挂起 ≥2 条未解问题**——任何一集结束时，**"已种下但未支付"的长线问题**至少 **2 条**并存（1 条主线 + 1 条副线/关系线）。⛔ 不得只靠"本集钩子"——本集钩子是**短钩**，长线问题才是**留住观众的绳**。
2. **单集不得全部兑现**——**本集结束时，手上至少留 1 条悬而未决的问题**过渡到下一集；⛔ 不得本集把所有种下的问题都收干净（那是"完结感"，不是"追看欲"）。
3. **长线悬念须登记保留期**——每条长线悬念在 `HOOK_PAYOFF_LEDGER` 登记**种下集 → 计划兑现集**，**跨度 ≥5 集**（低于 5 集的是短钩、不算长线）；⛔ **不得连续 ≥8 集不提醒**（观众会忘）——中途须有"提醒拍"（回响 / 提及 / 局部兑现），但**提醒 ≠ 提前支付**。

**与追看公式的关系**：`追看欲 = 具体未完成问题 × …` 中的「具体未完成问题」**在此变为可核对的存量**——不再只是公式里的一项乘数，而是**逐集可数的条数**。

**与钩子的分工**：**短钩**（本集钩子）负责"这一集看完想看下一集"；**长线悬念**负责"这部剧看到第 30 集还想知道结局"。**二者都要有，缺一不可。**

### 4.2 首次观看理解合同 COMPREHENSION_CONTRACT

- `who`：本集行动中心是谁。
- `wants_what`：他本集想完成的具体目标。
- `obstacle`：谁或什么规则主动阻止。
- `action_change`：第一个办法失效后换了什么策略。
- `result`：本集最后已经改变的事实、关系、资源或危险。
- `new_question`：下一步唯一主要问题。
- `required_prior_knowledge`：看懂本集最低需要记住什么。
- `forbidden_assumption`：不能要求观众自行脑补什么。

**ONE_SENTENCE_RECALL**：用一句「谁想做什么，但是遇到什么，于是怎样换策，结果怎样」的因果句复述本集。


不合格示例：「这一集主要是他们在会议室吵架，并发现事情不简单。」——没有目标、策略和结果，说明单集仍是材料片段。

**理解负荷控制**：一个短集可以引入复杂世界，但不能同时要求观众第一次记住过多新角色、组织、规则、时间条件和道具。必要信息按三类处理：`NOW`（不理解就无法判断当前行动，必须在动作中建立）、`LATER`（暂时不知道也不影响人物行动，可以延后）、`NEVER_EXPLAIN_AGAIN`（已通过动作清楚建立，不要每集重复）。

### 4.3 单集注意力曲线

60—180 秒内不机械套固定秒数，但必须完成四段功能：

1. **定向与在场压力**：尽快让观众知道当前是谁、压力已到哪一步、为什么现在必须行动。承接上集时优先用未完成动作、声音、道具或关系位置，不用长篇回顾。
2. **主动行动与反制**：主角尝试一个可见办法，对手、规则或环境依据自身目标回应。没有反制的方案汇报不是戏。
3. **换策与局部结果**：旧办法失效后，人物因新信息或代价改变策略。结果可以成功、失败或部分成功，但必须改变状态。
4. **余味与下一压力**：让观众看见本集结果如何影响人物，再留下下一项具体动作问题。钩子不是突然切黑，而是结果自然产生的新债务。

对 90 秒默认集可把注意力预算近似看成：前约 15% 完成定向，随后约 45% 行动与反制，约 25% 换策与支付，末约 15% 结果余味与钩子。比例可变，功能不能缺。

### 4.4 局部兑现

局部兑现是观众本集真正得到的东西：一个目标完成或明确失败；一项证据得到验证；一段关系完成站队、拒绝或破裂；一个规则的限制被证明；一次反击产生可见后果；一个危险被暂时解除并产生新代价。

局部兑现不等于全剧谜底。长线可以保持开放，但本集不能只建立问题。

检查问题：1. 删除集尾钩子后，本集仍然有可复述的结果吗？2. 这个结果会改变下一集的行动条件吗？3. 观众等待已久的承诺是否至少部分支付？三项都否定时，应与下一集重新组合。

### 4.5 下一集点击理由

NEXT_CLICK_REASON 必须回答五件事：

1. 等什么：一个具体动作、选择、证据、到场、危险或关系后果。
2. 为什么在意：它会伤害或改变谁的目标、关系、尊严、资源或生命。
3. 为什么现在：危险已逼近、选择已启动、证据刚出现或行动不可逆。
4. 下一集先做什么：第一场具体承接动作。
5. 何时支付：部分或完整兑现集。

有效表达：「她已经把解药递到仇人手里，观众下一集要看他会救孩子还是保住身份；因为两者不能同时保住，下一集先从他伸向药瓶的手接起。」

无效表达：「更大的阴谋即将浮出水面，敬请期待。」

### 4.6 钩子设计与兑现

**钩子七型**：

- ACTION：动作已启动，等待直接结果。
- CHOICE：人物必须在两个有代价方案间选择。
- EVIDENCE：新证据改变判断，等待验证或行动。
- ARRIVAL：已有关系与目的的人进入，立刻改变局势。
- DANGER：已建立危险进入不可回避阶段。
- IDENTITY：身份被怀疑、验证或公开；同一秘密不可反复假揭露。
- EMOTION：承诺、背叛、保护或拒绝改变下一步行动。

完整终局可使用 CLOSURE，支付最后一项行动与情感承诺，不再伪造下一集问题。

**好钩子的四项质量**：具体（观众能用疑问句说出来）、重要（答案影响已建立的人或目标）、临近（下一集可立即推进，不需先绕开三场戏）、可支付（已有来源事件或故事圣经支持答案）。

**部分支付**：下一集可以先回答「发生了什么」，再把「为什么」延后；也可以完成选择，再让后果继续升级。必须在 HOOK_PAYOFF_LEDGER 标记 PARTIAL 和最终支付，不能把同一问题换句话重复种下。

**伪钩子**：角色说「我有一个秘密」后切黑，下一集先闲聊；在一句完整答案说到一半时切断；随机陌生人推门，没有关系和目的前置；对手泛泛冷笑「你等着」；重复已揭晓身份，只换一批围观者震惊；本集没有行动结果，只靠危险音乐结束；下一集用回顾重播上集最后十几秒再给答案。

### 4.7 情绪和关系留存

观众持续追看通常不只为事实答案，也为人物如何选择。每集建立 EMOTION_CURVE：`entry`（进入时的主情绪）、`build`（压力如何让情绪增强或变质）、`turn`（哪次行动改变感受）、`payoff`（本集得到的情绪支付）、`aftertaste`（带入下一集的余味）。

关系场必须改变行动权限、信任、称谓、站位、资源或承担方式。只说「我理解你了」但下一步行动不变，不算关系推进。

长线关系节奏可轮换：试探 → 小额互助 → 暴露缺点 → 真实损失 → 主动站队 → 误解或价值冲突 → 更高成本修复。不能只靠重复吃醋、偶遇和误会维持。

### 4.8 不同题材的追看引擎

| 题材 | 观众每集主要等什么 | 必须支付什么 | 常见伪留存 |
|---|---|---|---|
| 悬疑 | 证据是否改变判断 | 一项验证结果或行动后果 | 不断增加谜团但不验证 |
| 甜宠 | 对方会不会主动选择关系 | 一次有成本的保护、拒绝或靠近 | 无行动的暧昧与误会 |
| 逆袭爽剧 | 主角怎样改变不公局面 | 准备、反击、见证、后果中的阶段闭环 | 换场景重复受辱 |
| 喜剧 | 人物策略怎样因性格反噬 | 笑点同时改变目标或关系 | 可删除的段子拼盘 |
| 生存/末日 | 资源和规则会逼出什么选择 | 真实消耗、损失或能力限制 | 突然出现新怪物 |
| 权谋宅斗 | 谁掌握规则、证据和执行权 | 权力、资源或名分的可见转移 | 全靠嘴赢且对手降智 |

### 4.9 三类观众复审

- **冷启动观众**：不读取前情简介，只看本集入口：能否在短时间内定位人物、压力和目标？若不能，补动作定向，不补百科旁白。
- **连续追剧观众**：检查上集问题是否在本集第一行动中被承接；同一事件是否重复；人物、道具、伤势、时间和关系是否连续。
- **怀疑型观众**：主动寻找编剧作弊：反派为何突然变笨？资源为何突然出现？人物为何知道秘密？代价是否只是口头声称？若答案依赖「观众别细想」，分集不能通过。

### 4.10 观众层失败模式

- EPISODE_THESIS 只能写「本集继续上一集剧情」。
- VIEWER_TAKEAWAY 是抽象主题，不是观众看懂的行动事实。
- ONE_SENTENCE_RECALL 需要三个「然后」才能勉强复述。
- LOCAL_PAYOFF 为空或只是「危机加深」。
- WHY_CARE 只说「很重要」，没有影响对象。
- NEXT_EPISODE_FIRST_ACTION 与钩子无关。
- 同一钩子连续两集仍处在「准备回答」。
- 结构字段全 PASS，但隐藏字段后只剩解释、争吵或半场戏。

## 五、分集边界、容量与长线编排

本节解决三个问题：一集该装多少、为什么在这里断、几十集如何既连续又不重复。分集不是把原文等分，而是把事件重新组织成观众能看懂、能获得局部满足、又愿意继续追看的行动单元。

### 5.1 事件可压缩性标注

给阶段③的每个事件标注一种处理方式：

- `ATOMIC`：因果、选择、代价或情绪兑现不可拆，必须在同一集完成。
- `COMBINABLE`：可与相邻事件合并，只要不损伤知识边界和人物动机。
- `MONTAGEABLE`：重复训练、赶路、积累、准备等可压成蒙太奇或一句可视化结果。
- `CALLBACK_ONLY`：已发生事件只承担回看、证据重现或承接，不再算一次新覆盖。

`MUST_KEEP` 事件至少一次作为 `PRIMARY_EVENT` 落入某集。任何事件只能有一个主归属集，其他集只能作为 `CALLBACK`。

### 5.2 自然边界与错误边界

适合断集的自然边界通常同时满足：

1. 本集行动已有局部结果，不是半句话、半个动作或半场争吵。
2. 目标、关系、信息、资源或危险至少一项发生不可逆变化。
3. 旧行动问题已经回答或阶段性回答。
4. 新行动问题已经具体出现，下一集知道先做什么。
5. 观众已经获得一次情绪兑现，再承受新的等待。

常见错误边界：只因为达到 90 秒就在同一动作中间切断；在基础设定尚未讲清时故意藏信息；本集没有结果，只用一句威胁、冷笑或黑屏拖延；把一个完整反击拆成「准备、开口、宣布」三集；上集钩子在下集开头被忽略，先去讲另一条线；用突然出现的身份、证据、资源或事故制造伪反转。

### 5.3 七问分集决策

对每个候选断点依次回答：

1. 本集观众能用一句话说出主要发生了什么吗？
2. 主角本集的目标、阻力、换策和结果完整吗？
3. 观众已经获得哪一次局部兑现？
4. 与开场相比，什么状态真实改变了？
5. 断点之后出现的是新问题，还是同一动作被硬切？
6. 观众为什么在意这个新问题，为什么现在就想知道？
7. 下一集第一行动能否直接承接并开始兑现？

第 1—4 问任一答不出，优先合并或重排；第 5—7 问任一答不出，说明断点缺乏追看动力。

### 5.4 边界理由卡（每个断点必须说明）

每个边界至少说明三层理由：

1. `story_reason` 故事理由：哪个局部目标已经完成、失败或发生不可逆变化。
2. `audience_reason` 观众理由：观众本集得到什么，又具体等什么。
3. `continuity_reason` 连续性理由：下一集为什么能以新动作、新策略或新局面开始。

可选补充 `production_reason` 制作理由：场景、角色、动作和时长负荷是否可执行。制作理由可以影响组织方式，但不能删除主线或改变人物选择。如果理由只是「这一段够 90 秒」「这里看起来刺激」「原著正好换章」，边界不成立。

### 5.5 时长与信息负荷

单集允许 60—180 秒，默认约 90 秒。时长是结果，不是切割尺。

估算时同时计算：对白朗读、动作反应、空间建立、情绪停顿、信息理解和钩子停顿。一个完整单元 75 秒可直接成立，不要注水；一个必须 110 秒才能完成选择与结果的单元，不要在策略转变处腰斩。

单集若同时出现以下高负荷项目，通常需要拆分或降载：多个新地点、三个以上新角色、新世界规则、复杂时间跳转、重大关系转折和高潮兑现。删减顺序优先是重复解释、同功能场次和背景闲谈，不得删掉因果前提、人物选择与情绪反应。

### 5.6 开篇爬坡与大弧地图

`OPENING_RAMP` 负责让新观众快速建立五件事：题材与异常、主角损失与目标、可用方法及限制、关键关系、后续升级引擎。它不要求固定五集，但每一项都必须由事件证明。爬坡长度随项目调整，不机械规定前三集或前五集。

`ARC_MAP` 对每个大弧记录：驱动问题、入口状态、主事件、升级阶梯、情绪线、承诺兑现、高潮集与出口状态。大弧不是章节目录，而是一段「观众持续等待同一个答案」的区间。

每个大弧结束时至少完成一项外部结果和一项人物或关系变化，同时打开更高层行动问题。若连续三个大弧只有同一种打脸、揭身份或众人震惊，必须改换冲突机制。

### 5.7 信息释放与事件归属

为每集区分：观众已知、主角已知、对手已知；本集新增信息及其证据来源；暂缓信息的戏剧理由；暂缓是否影响本集基本理解。

**存量检查（★ 2026-10-13 · 与 §4.1.1 悬念存量配额配套）**：本集结束时，**未解的长线问题存量 ≥2 条**、且**至少留 1 条过渡到下一集**——逐集核对 `HOOK_PAYOFF_LEDGER` 中状态为 `OPEN`/`PARTIAL` 的长线条目数，**不足即 `REVISE`**。

悬念可以延迟答案，不能延迟看懂当前行动所需的前提。观众不知道终极谜底没有问题，但必须知道角色此刻为什么行动、失败会怎样。

倒序、插叙、混编只在六项审计通过后采用：因果、人物知识、悬念、回到主时间线、情绪累积、来源追踪。呈现顺序变化不等于事实顺序变化（六门定义见 [story-bible-and-ip.md](story-bible-and-ip.md) 第 2.16 节）。

### 5.8 冲突签名与防重复（★ 2026-10-13 升级：从「连续三集滑窗」升级为「全剧配额 + 阶段升级 + 基线差异」）

每集记录 `CONFLICT_SIGNATURE`：

- `pressure_pattern`：压力来自人、规则、时间、资源、关系、知识差还是自我缺陷。
- `resolution_pattern`：本集靠选择、博弈、证据、牺牲、合作、技能、忍耐还是拒绝获得结果。
- `novelty`：相对前两集新的压力组合、关系位置或解决方式。

**四条去重铁律（按严格度递增）**：

**① 滑窗去重（原有）**：连续三集的压力模式和解决模式完全相同，判定为机械重复。即便事件名称不同，只要仍是「被轻视—公开证明—众人震惊」，也算同一公式。

**② 全剧公式族配额（★ 新增 · 治「后面疲劳、可预判」）**：以 `pressure_pattern × resolution_pattern` 组合为**「公式族」**——**全剧同一公式族出现不得超过 3 次**，且**每 10 集内不得超过 2 次**。超限判 `REPLAN`。

> **病史（粉丝实测）**：此前去重窗口**统统是「连续三集」滑窗**。粉丝描述的恰是**非连续重复**——「第 1-10 集公式 A（可行），第 11-20 集仍是公式 A，但中间插几集 B 打断连续性 → 滑窗扫过去『连续三集同公式』始终不成立 → 全绿通过 → 观众第 11 集起就能预判」。**滑窗去重 ≠ 全剧去重。**

**③ 阶段升级义务（★ 新增）**：每满 10 集（EP010 / EP020 / EP030…）**必须引入新的冲突层级**——至少升级下列一档：**对手级别 / 代价级别 / 信息层级 / 冲突维度**。⛔ 不得沿用首 10 集的公式族。

**④ 新鲜度衰减检查（★ 新增）**：以**首 10 集的 `CONFLICT_SIGNATURE` 集合为基线**，此后每批必须**证明与基线的差异**（写出本批与基线不同在哪里），⛔ 而非只与「前两集」比。

⚠️ **与反派强度联动**：公式之所以能重复，**本质是对手强度没升级**——同一个弱对手换个名字再来一遍。故 ②③④ 与「反派能力基线」（`six-stage-pipeline.md` §6.5）**必须同时达标**。

变化不等于随机；每次变化仍必须来自锁定人物能力、缺点、关系和世界规则。

### 5.9 人物关系与 IP 长线分布

不能要求每集重复同一口头禅或标志动作。按功能分布人物记忆点：

- `PRIMARY`：本集由核心选择或行为锚点主导。
- `VARIATION`：在新压力中展示同一人格逻辑的变体。
- `PAYOFF`：早期人格、关系或缺点铺垫在本集回收。
- `WITHHELD_WITH_REASON`：本集刻意不使用，并说明节奏理由。

人物弧必须通过选择和后果推进；关系弧必须通过共同经历、试探、保护、背叛、拒绝或修复推进。不能只用称呼变化或旁白宣布关系升级。

### 5.10 跨集连续性

每集记录入口和出口的目标、关系、信息、资源、危险与时间。相邻集检查：日期、日夜、倒计时、流程耗时是否相容；标注「连续」时是否真的从同一动作和情绪接上；若时间跳转，下一集正文是否能可视化建立；上集钩子的第一兑现动作是否进入下集开场；伤势、道具位置、人物知识与资源是否凭空重置。

### 5.11 交付范围与闭合类型

先声明当前交付属于：`SERIES_OPENING`（只完成系列开篇小弧）、`SERIAL_BATCH`（长线中的连续一批）、`CLOSED_MINI_ARC`（来源支持的闭合小弧）、`FINALE`（来源支持的最终闭合）。

局部完整不等于虚构谜底。来源没有提供身份、真相、证据、规则或胜负答案时，只能闭合角色当下的行动问题，相关事实继续登记为 `OPEN_ITEM`。

### 5.12 全局终审十二问

1. 每集一句话能否说清主要事件？
2. 每集是否有完整行动链与局部结果？
3. 每集钩子是否有具体等待问题、在意理由和兑现集？
4. 下一集开场是否承接上一集等待？
5. 所有必须事件是否且仅一次作为主事件覆盖？
6. 是否存在按章节、字数或固定秒数机械切割？
7. 是否连续三集使用同一冲突和解决公式，或同一公式族全剧超配额（>3 次 / 每 10 集 >2 次，见 §5.8）？
8. 是否有未兑现钩子或重复揭露同一秘密？
9. 关系、资源、知识、危险和时间是否连续？
10. IP 行为、声音和关系记忆点是否自然分布而非机械重复？
11. 分集方式是否已选择，精确集数是否有容量理由，自定义集数是否完成冲突审计，而不是先定数字再凑内容？
12. 冷启动观众能否看懂，连看观众是否觉得有进展，挑剔观众是否感到承诺被兑现？

任一核心问题失败，结论为 `REPLAN`；局部字段或承接可修正时为 `REVISE`；全部通过才能 `PASS` 并交给阶段⑤。

4. 是否先有 `local_payoff` 再有钩子。
5. `waiting_question`、`why_care`、`urgency` 是否缺一不可。
6. 下一集第一动作是否真实承接。
7. 时间、知识、关系、资源和危险是否连续。
8. `CONFLICT_SIGNATURE` 是否与前两集形成有效变化。
9. IP 选择、缺点、行为、声音和关系是否参与剧情。
10. 来源未提供的谜底是否仍保持开放。

## 七、短剧分集结构速查

- **单集最小完整单元**：每集至少包含进入压力、主动目标、首次策略、有效反制、策略变化、可见代价、局部结果和新压力或闭合。只发生谈话、准备、说明、争吵或半个动作，不构成完整一集。
- **观众理解**：看完后，首次观看者应能用一句话回答——谁想完成什么？什么阻止了他？他如何改变做法？最后什么状态变了？下一步要解决什么？悬念可以隐藏答案，不能隐藏看懂当前行动所必需的前提。
- **情绪与局部兑现**：每集都要支付一个真实结果：目标完成、部分完成、失败但获得信息、关系作出选择、资源改变或危险被确认。观众可以等待更大答案，但不能整集只得到「还没结束」。
- **分集边界**：在局部结果和不可逆状态变化后断开；下一集以新目标、新策略或钩子的第一兑现动作开始。不要按章节、字数、固定秒数或场景长度机械切割。
- **追看理由**：有效钩子必须同时具备具体等待问题、人物或利益的在意理由、此刻发生的紧迫性、下一集可见的第一行动和明确兑现位置。空泛威胁、冷笑、黑屏、重复揭露和无来源巧合都不是可靠钩子；禁止机械反转。
- **升级与防重复**：升级来自代价增加、信息变化、关系选择、时间压力、规则限制、资源冲突或人物缺点。**同一公式族（`pressure_pattern × resolution_pattern`）全剧 ≤3 次、每 10 集 ≤2 次**（§5.8）；连续三集不能使用相同的压力与解决公式；每满 10 集必须引入新冲突层级（对手级别/代价级别/信息层级/冲突维度）；尤其禁止反复「被轻视—亮身份—众人震惊」。
- **时长**：单集允许 60—180 秒，默认约 90 秒。完整故事单元优先于整齐时长。通过合并重复功能、压缩说明和可视化信息控制负荷，不删因果前提、人物选择和情绪兑现。
- **长线连续**：每集都要对齐目标、关系、信息、资源、危险和时间。上集的主钩子应在下集开场先得到承接；伏笔可以延迟支付，但必须登记兑现集与来源事件。

## 七·五、平台节奏矩阵与节奏档位

> 融合自 script-writing-studio 01b 节奏矩阵。**核心原则：不是所有东西都变快，而是让慢有价值。**

### 7.5.1 节奏档位四档（必须记录并传给下游）

分集规划时必须同时记录**节奏档位**，后续传给分镜/投喂环节。用户未指定时由 AI 自动判定，用户不满意可只改某一组。

| 节奏档位 | 使用时机 | 写作提醒 |
|---|---|---|
| **电影感中速** | 情绪交锋、仪式感、悬疑凝视、单镜调度 | 慢镜头必须承担信息、情绪或关系变化 |
| **短视频中高密度** | 默认短视频、竖屏短剧、红果、抖音、小红书 | 每段要有可见动作、信息增量或反应点 |
| **高密度动作或强钩子** | 前 3 秒/前 15 秒钩子、打斗、追逐、爆点、强反转 | 用动作链和短反应推进，不写空泛铺垫 |
| **慢节奏但高信息** | 用户指定或命中强情绪压迫、重要台词白名单 | 必须写清慢的功能，避免被误判拖沓 |

⚠️ **横屏/竖屏/21:9 只是画幅选择，不自动等于慢节奏或快节奏**；节奏由平台、目标时长、内容类型和完播目标共同决定。

### 7.5.2 平台时长层级

| 时长层级 | 节奏要求 | 写作策略 |
|---|---|---|
| 15-30 秒极短视频 | 0-3 秒直接给钩子，7 秒内给反差，结尾留互动 | 不写完整三幕，只写动作链和爆点 |
| 30-90 秒短视频 | 每 10-15 秒一个新信息/情绪点 | 场景极少，动作和台词都要压缩 |
| 90 秒-3 分钟短剧/短片 | 前 5 秒强钩子，每 15-20 秒推进 | 可有小三幕，但不允许空转铺垫 |
| 3-10 分钟平台微电影 | 可有电影呼吸，但前 15 秒必须给留人理由 | 慢镜头集中放在情绪峰值前后 |
| 10-30 分钟微电影 | 允许更完整的铺陈，但每 30-60 秒要有有效推进 | 主题留白保留，重复信息压缩 |

### 7.5.3 呼吸镜头合法条件（★ 关键）

慢镜头、空镜、沉默、长停顿、静止画面**只有满足下列至少一项时才保留**：

```
① 情绪变化：角色从一种状态进入另一种状态
② 悬念加深：观众获得"为什么会这样"的追问
③ 人物关系变化：视线、距离、称呼、肢体反应发生变化
④ 关键信息释放：画面里出现必须被看见的信息、道具、环境线索
⑤ 视觉记忆点：形成可做封面、标题、切片传播的画面
⑥ 动作蓄力：为下一次爆发、反转、决定做准备
```

**这一条与「尾帧锚定法」口径一致**——静止必须是为了被截图/强调，不是为了被观看。

### 7.5.4 平台节奏红线（违反即重写）

```
❌ 开场 3 秒内只有风景、天气、慢走、背影、环境铺垫，且没有悬念或反差
❌ 连续两场都在重复同一情绪，没有新信息
❌ 角色长对白解释设定，却没有动作或关系变化
❌ 为了"电影感"写长空镜，但观众不知道该看什么
❌ 微电影结尾有留白，但没有情绪回响、主题回扣或讨论点
```

## 九、阶段自检与校验清单

在锁定前先人工核对：每个事件 ID 是否唯一归属；每集主目标、反制、换策、局部结果是否完整；观众是否能一句话复述；本集是否先完成情绪兑现；集尾钩子是否有在意理由与兑现集；相邻集前后承接是否直接；时长预算是否等于目标时长；连续三集是否避免同一冲突公式；所有 IP 字段和上游版本是否一致。

校验失败先修订一次；仍失败则输出 `BLOCKED_REPORT`，禁止交给阶段⑤。

### 交付和退回标准

- **PASS**：首次观看能复述、主角主动、对手有效反制、本集有局部结果、钩子可兑现、关系和信息连续、时长可执行。
- **REVISE**：故事单元成立，但时长、信息密度、情绪顺序、钩子措辞或个别事件归属需要调整。
- **REPLAN**：集数与故事容量冲突、单集只是片段、连续场机械拆分、三集重复同一公式、事件遗漏或重复、钩子无兑现、观众无法说清本集讲什么。此时必须重新分集，不能交给阶段⑤靠台词补救。

## 附：题材通用性速查

方法不绑定单一题材：

- 悬疑：每集支付一项验证结果，再打开更深证据问题；不能只不断增加秘密。
- 甜宠/关系：每集让关系位置因行动改变，不能只靠误会拖延告白。
- 逆袭/爽剧：每集支付准备、反击、见证或后果中的完整阶段，不能连续重复公开打脸；**反派须达能力基线**（首战占上风 / 反杀前 ≥3 轮博弈 / 被击败前至少赢 1 次 —— 见 `six-stage-pipeline.md` §6.5 反派能力基线）。
- 生存/末日：每集明确资源、规则、危险与选择代价，不能用无来源新怪物充数。
- 喜剧：笑点必须来自目标受阻、人物策略和关系反差，同时推动状态变化。
- 群像：单集仍需一个主行动轴，其他人物线围绕同一价值或后果汇合。

长篇重点增加重复机制、状态和伏笔审计；短篇重点确保有限集数闭合主问题。方法的骨架保持一致。


## 九、文戏道具物理因果链与 AIGC 反穿模剧本设计铁律（2026-10-14 实测拉片新增）

> **病根复盘（用户实测「车内递伞穿模」案例）**：
> 原稿写作：`后座车窗降下，沈叙坐在车内，西装领口一丝不乱，右手把一把黑色长柄伞递出车窗，伞尖悬在雨里；他目光隔着雨看林晚。`
> **翻车后果**：视频模型看到「雨里 + 长柄伞 + 递出车窗」，由于既无动作因果链、又未交代伞的开合状态，模型直接在半降的车窗上渲染出一把**完全撑开的大黑伞**往窗外乱伸，把车门和玻璃穿模得一塌糊涂！
> **核心症结**：**这是剧本设计层面的物理常识与 AIGC 算力边界失察**——在车内隔着狭小车窗递长柄雨伞（哪怕递出去再让女主在雨里撑开），在 3 秒视频生成里都是必然穿模的废戏设计！

### 剧本层三大物理因果铁律（P1 写剧本时必须前置规避）
1. **禁设计「跨狭小窗口/孔洞递送长柄或大体积道具」**：
   - ❌ **错误剧本设计**：男主坐在车里把长柄伞从车窗递给雨里的女主 / 隔着窄窗递长剑或大托盘。
   - ✅ **正确剧本因果链**：**女主原本就在雨里撑着伞站定**（进屋或上车前在门外收拢伞），车内男主**只降下车窗露脸对视开口**；若一定要男主给女主撑伞，必须是**推开车门迈下车，手里已撑开黑伞走到女主头顶**。
2. **可开合/变形道具（雨伞/折扇/长卷轴/外套）遵循「状态前置锁死 · 切镜换态」**：
   - 严禁在同一个 3~4 秒镜头里让角色完成“接过收拢的伞→当场撑开”或“边走边收伞进车门”（伞骨变形极易穿模成蜘蛛网）。
   - **正解**：用切镜（Cut）跨镜交代状态变化——镜 A 车外女主右手握着**已撑开的黑伞**立于雨中 → 镜 B 车内男主降下车窗说“上车” → 镜 C 女主站在开启的车门旁、右手已握着**收拢捆好的黑伞**弯腰上车。
3. **道具动作必写「持握部位 + 开合状态 + 物理落点」，禁写无根局部悬空词**：
   - 严禁写 `伞尖悬在雨里`、`剑尖停在咽喉前`、`西装领口一丝不乱` 这类小说式装逼废词；必须写成相机能直接拍到的物理事实。
