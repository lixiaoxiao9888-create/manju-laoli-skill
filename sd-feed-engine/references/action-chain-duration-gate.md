# 动作链时长门（C-act）· 套装补丁规则 · 2026-10-21

> **由来**：《汴京谜卷》第01集实拍暴露的体系缺口——全集三层审核（分镜自检／六道闸门／validate_prompt 26+ 机检码）都只检查**台词时长**（6 字/秒语速），没有任何一层检查**动作量与镜长的物理匹配**。段6镜1（9 个动作拍塞 4 秒）等 16 个镜动作没演完，机检全部放行。本规则把动作的物理速度约束规则化，堵死这个盲区。

## 一、物理口径（动作的「6 字/秒」）

| 动作类型 | 单拍耗时 | 识别特征 |
|---|---|---|
| 表情/微动作（瞳孔缩、眉挑、眨眼、目光落点） | 0.3s | 眼/眉/睫/瞳 + 变化 |
| 单一肢体动作（插闩、拍灰、摊掌、递钱、捻物） | 0.6s | 手/臂/肩/头 + 施动动词 |
| 复合位移动作（回身蹲下、撞翻连退、跨步出棚、翻身掠窗） | 1.2s | 走/跑/冲/退/跨/扑/掠/返 + 位移 |
| 转场遮挡（门板掠过、垂席晃过、人潮合拢遮没） | 1.5s | 遮住/掠过/移开/合拢 |
| 光线/环境展示（灯亮扩散、雾中层次、晨光斜切） | 0.5s/项 | 照亮/浮出/层次（每镜封顶 2 项） |

**台词时间**独立计算（6 字/秒最快档＋标点停顿补偿，同闸门2 口径）。

## 二、判定

```
镜内总需求 = 动作链时间 + 台词时间
比率 = 总需求 / 镜长
比率 > 1.5        → FAIL（严重超载：必然砍动作或砍停顿）
比率 > 1.1        → WARN（超载：复核加时或删动作拍）
全景/远景/大远景镜  → 阈值放宽 15%（多主体并行动作）
```

## 三、两层落点

1. **P3 分镜层**：定镜长时按本表核算（剧情倒推时长后，逐镜过一遍动作拍数——**无台词镜恰恰是纯动作镜，时长依据就是动作链**）。
2. **P4 投喂层**：出稿后跑 `check_action_chain.py <投喂稿.md>`——与 gate_check.py（台词时长门）**并列互备**：闸门2 管嘴，本门管手脚。

## 四、机检脚本

```
python .zcode/skills-patches/check_action_chain.py <投喂稿.md> [--strict]
```

- `--strict`：WARN 也计入退出码（交付门禁用）。
- 输出：逐镜 动作拍数/估算时间/台词时间/镜长/比率/判定，末尾汇总。
- 算法：子句切分（句号/分号/破折号/逗号）→ 动作动词表匹配计拍 → 排除环境静态子句 → 加权求和。

## 五、更新守护（本目录存在的意义）

本目录 `.zcode/skills-patches/` **在技能仓库同步范围之外**（仓库同步 = rm+cp 整个技能目录，本目录不受影响）。每次从 GitHub 更新技能套装后：

```
python .zcode/skills-patches/apply_patches.py
```

该脚本扫描更新后的技能库：若 validate_prompt.py／闸门文档已原生包含动作链时长检查（关键字 `动作链 / C-act / action_chain / 动作时长`）→ 报告「官方已收录，补丁层可退休」；若仍无 → 报告「补丁层继续生效」，并提醒 P3/P4 工作流把本门加入交付自检清单。
