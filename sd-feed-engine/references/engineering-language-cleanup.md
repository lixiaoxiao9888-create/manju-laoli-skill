# 工程语言清洗规则（Engineering-to-Visual Translation）

> **本文档是交付层核心规则库 · 权威文件**
> 融合来源：script-writing-studio 06-core-format 适配原则 21/22/23/24（工程语言转画面语言）
> 定位：分镜稿里的"给人看的工程语言" → 投喂稿里的"给模型看的画面语言"。

---

## 〇、为什么需要清洗

分镜稿里可以有轴线、锚点、点位表、调度编号——**这些是给人看的**。但 AI 视频模型**不理解**这些内部术语。如果不清洗，模型看到"180度轴线""A2点位""参考MAP001"只会一脸茫然，甚至生成错误画面。

**本文件职责**：把工程语言逐条翻译成模型能识别的**画面事实**。

---

## 一、工程语言 → 画面语言 对照表

| ❌ 工程语言（给人看） | ✅ 画面语言（给模型看） |
|---|---|
| 180度轴线 / 不要越轴 | 摄影机始终在两人连线的同一侧；<br>角色A 在画面左侧、角色B 在画面右侧 |
| A2 点位 / B1 站位 | 角色A 站在窗边、角色B 站在门口（**用具体空间描述**） |
| 参考 MAP001 | 人物站位如 图7 所示：角色A 在左前、角色B 在右后（**用图号+空间描述**） |
| 以沙盘为锚点 | 角色A 站在沙盘左侧一步远的位置 |
| 窗内外 / 柜台内外 / 车内外 | 角色A 位于窗内，角色B 位于窗外；或"隔着柜台相望" |
| 内外侧 / 侧别锁定 | 摄影机在走廊右侧拍摄，角色面向画面左方 |
| 摄影机安全区 | 摄影机保持在角色行进路线的右前方，不穿越两人之间 |
| 前景 / 中景 / 远景层 | 画面前景是茶杯（虚化），中景是角色A，远景是窗户 |
| 移动方向 | 角色A 向画面右侧移动 / 朝摄影机方向走来 |

## 二、摄影机行为锁 — 必须写成可执行句

❌ **不能只写**："固定 / 手持 / 跟拍 / 退拍"

✅ **必须写清六要素**：
```
① 摄影机类型（手持/稳定器/固定三脚架/滑轨/摇臂）
② 位置（在哪、距主体多远）
③ 高度（与人物视线平齐/略高/俯视/仰视）
④ 运动方向（推/拉/摇/移/环绕，朝哪个方向）
⑤ 稳定程度与速度（缓慢/匀速/急促）
⑥ 起止状态 + 禁止项
```



### 2.1 Lubezki × Deakins 物理运镜与光学锁焦转译表（2026-10-14 与 C20m 互锁修订：严禁摄影机理论废话进 P4 镜行）

> ⚠️ **防「补丁打补丁」铁律（与 `validate_prompt.py` `C20m` 互锁）**：
> 早期将 `shotlist-builder` 的长篇摄影师说明书（如 `85mm F1.4极浅景深（背景散焦为柔和色块与微光，焦平面全程死锁面部无漂移）`、`保持平稳克制的极细微规律呼吸式微动`、`毫米级构图补偿`、`画面线条笔直构图平整`）直接塞进 2~4 秒的短剧镜行正文，实测会严重稀释人物动作 Token 权重并诱发画面无故晃动！
> **正确分流**：光学焦段（`35~85mm 中浅景深`）与光比（`1:5~1:8 单侧光`）统一收敛进段首 `【画幅风格】` 栏；**P4 投喂镜行正文只写「镜行头三要素 + 单人/群像纯物理动作 + 句尾6~10字背景光影锚」**！

| 分镜层写法 | ❌ 严禁塞入 P4 镜行的摄影机废话（C20m 阻断） | ✅ P4 投喂镜行极简纯动作 + 句尾环境锁正例 |
|---|---|---|
| `特写 · 固定`（文戏对话） | ❌ `85mm F1.4极浅景深（焦平面全程死锁面部无漂移），保持极细微规律呼吸式微动，毫米级构图补偿` | ✅ `00:05-00:08 [镜头3] 特写 · 微仰 · 固定。单人入画，@CHR-沈青梧 眼神骤冷，下颌微收，目光盯住画右前方；身后云海夜雾冷蓝。` |
| `近景/特写 · 缓慢推镜` | ❌ `镜头前0.5秒严格静止冻结，随后纯物理缓慢推进10~15厘米（速度慢到几乎察觉不到）` | ✅ `00:00-00:03 [镜头1] 中景 · 平视 · 缓推。画面主体：@CHR-沈青梧 单人入画，负手立于台缘，侧首望向画右前方开口；身后蟠龙石柱清晰。` |
| `全景 · 固定/建立镜` | ❌ `35mm广角F4深景深阴影侧取景（画面线条笔直构图平整）` | ✅ `00:00-00:03 [镜头1] 全景 · 微俯 · 固定。画面主体：@CHR-玄诚长老 端坐于画面中后方高台蒲团上，台下左中右一字并排站立三人面向高台。` |

## 三、风格 / 色彩 / 负面词 — 禁止直接复制编号

❌ **禁止**：只写 `ST001 / CL001 / NP001 / 继承 ST`

✅ **必须翻译成自然语言**：
```
项目风格：<具体描述——媒介质感、人物审美、场景审美、画面质感>
当前镜头光影：<光源来源、主光方向、亮区、暗区、色温、明暗反差>
风格禁止项：<具体说明禁止什么——如"不要塑料感皮肤""不要万能雾"">
```

**规则**：风格/色彩/负面词包可以出现在**代码框外的投喂信息或素材管理说明**里用编号；但**代码框内的最终提示词必须翻译成自然语言**。

## 四、风格光影冲突时的融合规则

**如果风格包/色彩包的默认光影与当前分镜的真实光源、剧情时段或角色位置冲突**：

```
✅ 以当前镜头的真实光源和剧情时段为准
✅ 同时保留项目风格的媒介质感、明暗反差、颗粒/渲染方式、人物审美和禁止项
❌ 不要在同一提示词里同时写两套互相打架的光影系统
```

## 五、光影字段必须可见可执行

❌ **不能只写**："电影级布光 / 高级光影 / 氛围感"

✅ **必须写清**：光源来源、主光方向、亮区、暗区、脸部受光、轮廓光或背景分离、色温、明暗反差

**如果写丁达尔光效**，必须写**光束来源、介质和落点**。

---

## 六、情绪表演必须拆成微动作

❌ **不能只写**："悲伤 / 愤怒 / 害怕 / 心动"

✅ **必须写眼神、眨眼、嘴部、呼吸、肩颈、手部或身体重心的可见变化**

**限制字段必须写清禁止过度表演**：
```
不要假哭、不要夸张皱眉、不要咆哮、不要突然失控
（除非剧情明确爆发）
```

## 七、人群 / 道具 / 场景角度 — 三个易错点

### 人群密度

❌ **不能只写**："CR001 / 同上一段人群 / 保持之前人流"

✅ **直接写清**：本段可见的**人数、层次、类型、移动方向、遮挡规则**

⚠️ 场景母版如果是空场图，**只作为空间结构/灯光/透视/固定物参考**；启用人群时直接写本段可见人群，**不写"不继承空无一人状态"这类管理说明**。
⚠️ 无路人需求时，**不新增人群密度字段**，只在限制里写"不允许出现额外人物、路人、群演"。

### 道具单实例锁

❌ **不能写**："添加一个道具"

✅ **必须写**："图4 只作为已存在那一件道具的外观参考，**不新增第二个实例**"

必须包含：**数量限制、绑定位置、移动后原位置变化、禁止复制项**——避免桌上一个、手里一个、背景又一个。

### 场景角度图

❌ **不能只写**："SCV001 / 使用角度图"

✅ **必须写**："本段使用 图5（V02 角度），只参考**拍摄方向、空间透视、门窗/家具相对位置和固定光源**"

⚠️ 不得让角度图替代场景母版、调度图或首帧图。

## 八、官方符号使用规范

| 用途 | 符号 | 说明 |
|---|---|---|
| 台词 | `{台词}` | 有明确文字/音频生成需求时可用 |
| 音效 | `<音效>` | 同上 |
| 字幕/标题 | `【字幕/标题】` | 同上 |

- **默认不生成 BGM**（BGM 交给 `sd-qc-engine` 后期声音设计）。
- **没有文字生成需求时**，默认写"保持无字幕，避免生成任何文字或字幕"。

## 八·补、画面内文字与系统面板规则（2026-10-10 并入）

**默认：不生成文字。** 普通背景字、招牌字、无来源的界面文字一律**不可读**——可转写为模糊符号、文字状光痕、发光纹路、光点排列或不可辨识的书写痕迹。

**唯一例外 · 系统面板。** 当原文**明确提供**系统面板 / 界面字段、数值、等级、增益或惩罚时，它是**剧情依赖的 in-world 界面元素，不是字幕**——必须在本段画面内以**面板、界面光层或悬浮信息框**完整、逐项、可读地呈现，**不得省略、改写、模糊化或补造**。

| 项 | 处理 |
|---|---|
| 有来源的系统面板 | **必须可读**：写清面板位置与层级，数值 / 等级 / 名称**逐项列全** |
| 无来源的背景文字 / 招牌 / 说明字 | **不可读化**：模糊符号 / 文字状光痕 / 光点排列 |
| 字体细节 | 只呈现**原文提供**的字段，**不得**替原文补造面板数据（与角色 / 道具 / 台词同源保真） |

- 与"不制作字幕"的约束**不冲突**：字幕约束针对**无来源**的台词/说明文字；有来源的系统面板不受此约束。
- 系统面板**必须可读**，与"背景文字不可读化"是两条相反的处理——**不得把面板当字幕糊掉，也不得把无来源文字当面板写清**。

**自检**：(1) 本段是否有原文提供的系统面板？有 → 是否逐项完整可读？(2) 无来源的背景文字是否已做不可读化处理？(3) 有没有把面板当字幕糊掉、或把无来源文字当面板写清？

## 九、清洗流程图

```
分镜稿（含工程语言）
        ↓
① 扫轴线/点位/编号/内外侧 → 逐条转画面事实
② 扫摄影机描述 → 补全六要素
③ 扫风格/色彩/负面词编号 → 翻译成自然语言
④ 扫光影字段 → 补来源/方向/色温/反差
⑤ 扫表演描述 → 拆成可见微动作
⑥ 扫人群/道具/角度图 → 按 §七 三易错点改写
⑦ 扫符号 → 按 §八 规范
⑧ 扫分镜层专用字段（状态/重音/清单/面板号/卡ID） → 按 §十一 剥离
        ↓
可投喂提示词（纯画面语言）
```

## 十一、分镜层专用字段 —— 投喂前必剥离（2026-10-11 并入）

分镜稿里有几样东西是**给作者、给机检、给团队看的**，模型读不懂、也不该读。它们**必须停在分镜稿层**，封装投喂时逐条剥除：

| 字段 / 产物 | 为什么不能进投喂 | 剥离后由谁承担 |
|---|---|---|
| `状态：{前}→{后}`（`sd-storyboard-engine` 单镜头模板） | 描述的是**镜与镜之间的关系**，不是本镜的画面事实——同类工作流标注（C12 对工作流规则名词告警） | 本镜「画面内容」里写清人物的姿态与持物 |
| `重音：{字}`（同上） | 是**设计标注**，模型的配音不吃这个记号 | 落进发声描述（"『修』字重读"）＋画面内容里的表演描写 |
| **台词精简建议清单**（分镜稿文末） | 是**与用户的对话**，不是提示词内容 | 剥离后再封装；精简与否由用户裁定（`sd-storyboard-engine` §二·8） |
| **故事板面板号 / 出口帧六项** | 执行稿标注，面板号是给人看的 | 逐格落进镜行后剥离；出口帧只作段缝画面锁依据 |
| **机长时码 / 卡 ID**（SHOT_TEXT） | 时码已有【时间轴分镜】承载 | 时码进镜行；卡 ID 不进投喂 |
| **神态-动作供给库 / 锚点表 / 节拍表** | 创作脚手架，不是画面 | 只把**结果**（具体神态与动作）写进画面内容 |

**一句话判据**：**凡是"描述镜头之间关系"或"给创作者看的标注"，一律不是画面事实**——要么按 §一 对照表转成"画面里看得见、听得见的东西"，要么直接删。

**自检**：投喂正文里搜一遍 `状态：` `重音：` `面板` `出口帧` `卡 ID`——命中即剥离。
