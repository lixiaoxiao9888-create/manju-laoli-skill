# 投喂输出模式与投喂层闸门（Feed Mode & Gates）

> **本文档是交付层核心规则库 · 权威文件**
> 融合来源：script-writing-studio 06-core-format 第六节（A/B/C 输出模式 + 输出前投喂层闸门）
> 定位：分镜稿 → 可投喂提示词的**最后一关**。

---

## 〇、定位与边界

**解决什么问题**：有七段式格式规范，但缺**"投喂前的质量控制流程"**——写完提示词直接发，容易出现：字数超限、台词念不完、写了模型执行不了的交接话术、引用图超过平台上限、图号混用。

**本文件提供**：A/B/C 输出模式选择 + 输出前**投喂层闸门**逐项校验。

**边界**：本文件不定义七段式字段写法（那是总控 `short-drama-director/references/model-adapters.md` 的权威）；本文件只负责**"输出模式怎么选"**与**"发出去之前必须过哪几道关"**。

---

## 一、A/B/C 三种输出模式

每次用户要求生成 Seedance 提示词包时，先用 2-5 行**推荐输出模式**，并允许用户指定 A/B/C。**用户不指定时，默认使用 C 导演轨纯净版。**

### 模式对照表

| 模式 | 全称 | 适用场景 | 默认倾向 |
|---|---|---|---|
| **A** | 标准字段化详细版 | 完整展开字段，适合 1-3 镜头高精度控制、镜头审查、教学拆解、用户明确要求完整字段 | 按需使用 |
| **B** | 导演执行增强版 | 一镜到底、强运镜、人群、动作戏、遮挡转场、强声音叙事、复杂表演 | 命中高难镜头时推荐 |
| **C** | 导演轨纯净版 | **默认成品格式**，适合 4-7 镜头直接投喂，保留硬锁并控制字数 | ⭐ 默认优先 |

### 用户可见模式提示（模板）

```
本段可以用三种输出模式：
A 标准字段化详细版：完整展开字段，适合 1-3 镜头高精度控制、镜头审查或用户明确要求完整字段。
B 导演执行增强版：适合一镜到底、强运镜、人群、动作戏、遮挡转场、强声音叙事和复杂表演。
C 导演轨纯净版：默认成品格式，适合 4-7 镜头直接投喂，保留硬锁并控制字数；命中高密度动作或强钩子时可容纳 8-10 个短镜头，但必须过闸门。
我建议本段使用：____，原因：____。如果你不指定，我会按推荐模式继续。
```

### 输出原则（三种模式共通）

1. **信息底座不变**：无论 A/B/C，都必须保留素材、场景、人物位置、焦点、摄影机、动作、台词、光影、限制、衔接和段末状态。C 用导演轨合并表达；A 才展开完整字段；B 在 C/A 基础上叠加增强。
2. **增强按需启用**：视频延长、首帧、调度图、场景角度、人群密度、道具单实例锁、复杂运镜增强——只在命中条件时加入，普通段落不默认全压。
3. **用户可见但不啰嗦**：代码框外简短说明推荐模式和命中的增强项。
4. **字数红线（★ 2026-10-13 按模型分档 · 2026-11-03 整档上移 1000）**：单个可投喂单元 **Seedance 2.0 默认 ≤2900 字、3000 硬上限；Seedance 2.5 ≤3600 字、4000 硬上限**（2.5 对长提示词服从更好；两档软硬间距保持原设计——2.0 差 100、2.5 差 400）。细则见下方闸门 3。
   > ⚠️ **别把两个阈值混成一个（口径统一）**：本闸门是**段级**——逐投喂单元计（2.0：≤2900 通过 / 2901–3000 先压一轮 / >3000 必压；2.5：≤3600 / 3601–4000 / >4000），由 `sd-feed-engine/scripts/gate_check.py`「闸门3」判；机检 `validate_prompt.py` 的 **C4** 是**篇级兜底**——单个投喂稿文件 ≤6000 字符（按整份文件的字符数计，含标点与格式符），判据全集见 `sd-qc-engine/references/machine-check-manual.md`。
   > 一个文件 = 一个投喂单元时，两者是「**自律线按模型分档**（保念得完、渲染稳）／**兜底线 6000 字符**（防单文件过大被截断）」的关系，**不冲突**；把多个单元合成一个文件时会超 6000，此时**以本闸门的段级判定为准**。
5. **强度保护**：不得为压字数删除素材用途、人物锚定、场景位置关系、景深焦点锁、摄影机行为锁、台词语气、可执行光影、段末状态。
6. **重复去除**：全局约束（人物锚点/字幕水印/全局风格/光线连续性）只集中写一次，不在多处反复展开。

## 二、★ 输出前闸门（核心）

每个投喂单元输出前**必须先过闸门**。**P14 起判据级去重：一条判据只留一处实现，出稿只跑一次质检。**

### ★ 闸门分工表（谁管什么 · 唯一实现 · 2026-11-03 用户裁定）

| 闸门 | 管什么 | 唯一实现 | 说明 |
|---|---|---|---|
| 闸门 1 | 节奏档位（10s 以上只有 1~2 镜） | `gate_check.py` | C1b 管段长区间、C2 管镜数下限，**均不等价**，故此条留在投喂层 |
| 闸门 1b | 镜长雷同 | **机检 C13** | 同段 ≥4 镜、同值占比 ≥70%——原 `gate_check` 的双实现在 P14 摘除 |
| 闸门 2 | 台词缺语气位 | **机检 C16b** | 原 `gate_check` 的双实现在 P14 摘除 |
| 闸门 2·时长 | 字数÷语速＋停顿 vs 镜长 | `gate_check.py` | 语速档解算独有；C16 系只管语气位有无/质量 |
| 闸门 3 | 段级字数（2.0 2900/3000 · 2.5 3600/4000） | `gate_check.py` | **C4 是篇级 6000 字符兜底**，与段级不同粒度，两者都要过 |
| 闸门 4 | AI 交接话术残余 + 参数行位置 | `gate_check.py` | C12 管"否定式硬删除/工作流规则词"，不含"以下是/希望对你有帮助"这类 |
| 闸门 5 | 单段图号上限（2.5→30 / 2.0→9） | `gate_check.py` | — |
| 闸门 6A | 稿内图号越项目资产库 | `gate_check.py` | — |
| 闸门 6B | 素材形态 M0/M1/M2 一致性 | `gate_check.py` | — |
| 闸门 0·结构 | 【】配对闭合 / 镜号连续性 | `gate_check.py` | **C 系不管这两项**（C7 只管七段缺栏、C11 只管接续状态残留）——逐条实查后**保留在本层** |
| 闸门 0·缺栏 | 七段式缺必备栏 | **机检 C7** | 原双实现已摘除 |
| 闸门 0·废止栏 | 【接续状态】残留 | **机检 C11**（FAIL 级） | 原双实现已摘除 |

**执行口径**：`python gate_check.py <稿.md> --model 2.5 --aspect 16:9` **一条命令跑完全部**——
投喂层闸门自查 + 自动调用总控 `validate_prompt.py` 拿 C 系结果，合并成一份报告。
⛔ 不再需要"先跑闸门、再跑机检、最后跑契约核销"三遍（同一个语气位/镜长问题被查三次的时代结束了）。
单独安装 `sd-feed-engine` 时找不到机检引擎，脚本会明确提示"本次只跑了投喂层闸门"，此时必须另跑机检——不得当成全绿。

### 闸门 1 · 节奏档位闸门

**目的**：防拖沓，不是强行切碎镜头。

```
检查项：
① 先继承或补判节奏档位：
  电影感中速 / 短视频中高密度 / 高密度动作或强钩子 / 慢节奏但高信息
② 按建议时长检查镜头密度
③ 10 秒以上只有 1-2 镜时 → 判断是否命中慢节奏白名单
   · 命中 → 保留原节奏并写清慢镜头功能
   · 未命中 → 补动作标点/道具信息/反应/空间关系/段末钩子镜头
```

### 闸门 2 · 台词时长闸门

**目的**：防"台词念不完"。**注**：本闸门只管时长；「台词缺语气位」由机检 **C16b** 负责，不在此重复检查。

> 📐 **画幅分档（P6.4 · 2026-10-23）**：**16:9 横屏半精品**按标准对白 **3.5~5 字/秒** 写，句间留 0.5~1s 停顿做情绪落点；**9:16 竖屏快节奏**按快念 **5~6 字/秒** 写，几乎不停顿（停顿只在"憋住/被打断"时出现）。**分档的是写稿语速，不是判据**——"念不念得完"仍按最快档 6 字/秒 判，判据不因画幅变成两套。档位定义见 `short-drama-director/references/blooper-prevention-playbook.md` §十·10.0（画幅-剧型分档）。

> ⚠️ **（2026-10-08）**：真人快念 **5.5~6 字/秒** 完全做得到（短剧常态即在此区间）。**判定"念不念得完"必须用最快档 6 字/秒**，不得拿 4~4.5 字/秒 的中值硬卡——后者会把大量能快念完的台词误判成"念不完"，是本包此前误触发"精简台词"的根因。

```
语速基准（判定看最快档）：
  强情绪慢速/低声耳语 → 2.5-3.5 字/秒
  标准对白           → 3.5-5 字/秒
  快速（争吵/逼问）   → 5-5.5 字/秒
  高速（短剧常态快念）→ 5.5-6 字/秒   ← 完全可行、不是极限
  超过 6 字/秒       → 需授权（抢话/急辩/快嘴喜剧，仅短句且须写明快念）

停顿补偿：
  逗号/顿号        ≈ 0.2 秒
  句号/问号/叹号   ≈ 0.4 秒
  省略号/情绪停顿  ≈ 0.6-1.0 秒
  开口前后反应承接 ≥ 0.5-1.5 秒

检查：先按**最快档 6 字/秒**算 `字数÷6 + 停顿` = 最短可行时长
      → 镜长 ≥ 此值 = 念得完，合规，**不得判超载/不得建议精简**
      → 只有连 `字数÷6 + 停顿` 都塞不进，才是真念不完
      → 再按 3.5~5 字/秒算舒适时长作参考，据此决定建议生成时长
```

### 闸门 3 · 字数闸门（★ 2026-10-13 起按模型分档）

```
Seedance 2.0（及未注明模型）：        Seedance 2.5：
≤2900    → 通过                       ≤3600    → 通过
2901-3000 → 必须先压缩一轮             3601-4000 → 必须先压缩一轮
>3000    → 继续删除低收益内容          >4000    → 继续删除低收益内容
          （见下方压缩顺序）                     （见下方压缩顺序）

⚠️ 禁止因为字数超限就压扁单镜头字段
```

> ⚠️ **分档依据（2026-10-13 粉丝实测反馈）**：「用 2.5 模型出视频，但字数还限制在 2000」——2.5 对长提示词的服从与稳定性明显好于 2.0，旧的单档 2000 把 2.5 的容量浪费掉了。故 2.5 曾放宽到自律线 2600 / 硬上限 3000。**2026-11-03 字数额度整档上移 1000**（用户裁定）：2.5 → **3600/4000**、2.0 → **2900/3000**，软硬间距按原设计保留；若后续实测在新区间出现丢字段/漂移，再回调。**机检同步**：`sd-feed-engine/scripts/gate_check.py` 闸门3 按 `--model` 分档（2.5 → 3600/4000，其余 → 2900/3000）。

**固定压缩顺序**：

```
① 删除管理话术和解释说明
② 删除默认不输出的低收益后缀项
③ 合并重复限制
④ 缩短空泛形容词
⑤ 缩短非末镜可见转接
⑥ 把同一控制点集中到 硬锁/声音轨/段末状态
⑦ 用更短但完整的摄影机行为句和光影句表达同一控制
```

仍超限 → 优先用 C 模式；若 5-7 完整镜或高密度 8-10 短镜仍超本档硬上限（2.0 = 3000 / 2.5 = 4000）→ **按镜头边界拆成连续单元**（拆分点必须落在镜头之间，用段末状态承接下一单元第一帧），**不在单个镜头内部硬拆**。

### 闸门 5 · 单组图片数量闸门（按模型分档 · 2026-10-12 修订）

```
按 A 锁模型取上限，**不得把 2.0 的 9 张套到 Seedance 2.5 上**：

  Seedance 2.5（全能参考）   图 ≤ 30 / 视频 ≤ 10 / 音频 ≤ 10 / 总数 ≤ 50
  Seedance 2.0               图 ≤ 9（单参考图锁形象、无首尾帧；平台侧多锚点实测可挂 3~4 张）

（含人物、场景、道具、首帧、调度图、位置参考图、场景角度图等所有图片）

⚠️ 项目资产库可以超过上限，但单组代码框内不得引用超过该模型上限的图号
超过时 → 先保留当前段必需图片，把低风险参考合并、转文字约束或拆到下一组
```

> **为什么改**：原闸门写死「每组 ≤9 张」且未分模型——**9 张是 Seedance 2.0 的上限**，被误当成全模型通用值，直接压制了 Seedance 2.5（官方支持 30 图 / 总数 50，权威见总控 `model-adapters.md` §5 与 `SKILL.md` §二）。2.5 用户本可多投图锁一致性，却被人为卡到 9 张。口径现与 `sd-storyboard-engine/references/storyboard-sheet-template.md` §参考图数量红线（Seedance 2.5 ≤30 / 2.0 图 ≤9）对齐。

### 闸门 5·补 · 分组三重门槛（★ 2026-10-17 新增 · 粉丝「森林」实测反馈并入）

> 📌 **来源**：粉丝「森林」2026-10-17 反馈——「分完让 AI 组装，3 条门槛：1. 小于 15 秒；2. 资产不能超过 9 个；3. 重复资产必须新起分组，不能合在一起，因为同个角色不同资产可能会影响或误导视频，也就是所谓的污染」。
>
> **裁定**：① 时长门槛**方向对、数值需分档**（15s 是 2.0 的上限，不是全模型值）；② 资产 9 个**不能照收**（9 是 2.0 上限，2026-10-12 已专门修过「把 9 套到 2.5」——收它等于把修复推回去）；③ 资产隔离**属真空缺，已收**（原文无此规则）。故本节按「分档 + 分层」重写，不照抄原话。

**术语对齐**：粉丝说的「分组」= 本包的「投喂单元 / 段」= `## 【投喂单元 N/M · 段K】` 一个代码框。三者同义，本节统一叫「组」。

**门槛顺序固定**：**先按剧情断点切组，再逐条过三关**；任一关不过 → 拆组或换组，**不得硬塞**。

| # | 门槛 | 判据 | 不过怎么办 |
|---|---|---|---|
| **A** | **时长** | 单组 ≤ A 锁单段上限（**2.0 = 15s / 2.5 = 30s **）；下限见 §〇 ⑦（2.5 禁 16~24s 碎段区） | 按剧情断点拆，⛔ **不在句子中间切**（台词跨组 = 口型断裂） |
| **B** | **资产数** | 单组实际引用的**图号 + `@` 锚点**合计 ≤ 模型上限（**2.5 = 30 / 2.0 = 9**）；**实操建议 ≤9 更稳**——超过 9 个后每多一个都在稀释注意力 | 低风险参考**转文字约束**、合并同源素材，或拆到下一组（低风险项才可拆） |
| **C** | **资产隔离** | **同一角色的不同形态 / 不同年龄 / 不同服装版本，不得出现在同一组** | 按形态**新起一组**（编号仍保持相邻，见下） |

**门槛 C 的病根与边界（必须读懂，否则会跟「同角色多形态相邻编号」打架）**：

- **病根**：一组里同时挂「知夏-4 岁」与「知夏-成年」，模型会把两张脸**揉成一个人**——不是"两个角色"，是"一个角色长了两张脸"，比缺人更难修。粉丝原话「同个角色不同资产可能会影响或误导视频，也就是所谓的污染」，**机制成立**。
- **与「同角色多形态相邻编号」的关系（分层不冲突）**：
  - **相邻编号**（`asset-mapping-and-rules.md` §二 铁律 4）管**《素材接线单》的排序**——让模型建立"同一主体的两个形态"关联；
  - **门槛 C** 管**投喂单元的切分**——一次生成里**只能出现一个形态**。
  - ⛔ **不是二选一**：**编号照样相邻，组必须分开**。
- **正确写法**：`组1 = 4 岁知夏 + 温良 + 破屋` / `组2 = 成年知夏 + 温良 + 破屋`
  **错误写法**：`组1 = 4 岁知夏 + 成年知夏 + 温良`（同组双形态 = 污染）
- **⚠️ 别读成「同角色不能跨组」**：同一角色**连续出现在多组是正常且必须的**（组 1/2/3 全是 4 岁知夏 = 完全合规）。门槛 C 禁的只有**同一组内多形态并存**，不是"重复出现"。

**机检兜底**：`gate_check.py` 闸门 5 按 `--model` 分档（2.5→30 / 2.0→9 ，`--img-limit` 可覆盖）；门槛 C 目前**只做人工判据**（形态识别依赖资产卡命名，机检易误报），出稿自检时按组核对「本组是否出现同一角色的两个形态版本」。

### 闸门 6 · 素材编号一致性 ＋ 素材形态一致性闸门

> **前置**：本闸门以**素材形态声明**为准。形态三档 **M0 纯提示词 / M1 编号占位（默认）/ M2 已入库**，权威 = 总控 `short-drama-director/references/asset-delivery-modes.md`。

```
A · 编号一致性（原）
① 镜头轨中出现的每个 图N / 视频N / 音频N 是否已在素材锚定 / 映射表中定义？
② 角色/场景/道具/首帧/调度图/视频/音频职责是否混用？
③ 发现图号混用 → 先修正或提示用户确认，不直接交付

B · 素材形态一致性
④ 交付首行是否已声明素材形态（M0 / M1 / M2）？未声明 = 形态未定 → 不得交付
⑤ M0 稿内出现任何图号 → 形态违约（FAIL）：图号槽位与 M0 声明互斥
⑥ M1 稿内有图号但未附《素材接线单》 → 形态违约（WARN）：接线单是 M1 交付必备件
⑦ 稿内图号 ∉ 接线单图号集合 → FAIL（用户会去挂一张不存在的图）
⑧ 接线单每行是否写明"只控制什么 / 不控制什么"？缺项 → WARN
⑨ 是否出现"已与《资产图册》核对一致 / 已核验"之类断言？M0/M1 下本包看不到图 → 一律 FAIL（虚假核验）

机器化：python scripts/gate_check.py <投喂稿.md> --mode M0|M1|M2
```

## 三、增强触发规则（按需启用）

| 命中情况 | 默认处理 |
|---|---|
| 普通剧情段 / 常规连续段 | 推荐 C；不强行加入高级增强 |
| 用户明确要求完整字段、审查漏项、1-3 镜头高精度控制 | 推荐 A |
| 同场景顺延，下一段像继续拍 | 建议视频延长启动句；默认 C |
| 必须首帧 / 建议首帧 | 加入首帧参考，说明只锁第 0 秒 |
| 多人站位、轴线、遮挡、摄影机安全区高风险 | 加入调度图参考或侧别约束；复杂时推荐 B 或 C |
| 核心场景、反打、回切、复杂空间或高穿帮场景 | 加入场景角度参考，说明只锁拍摄方向和空间透视 |
| 公共空间、街道、商场、车站、学校、医院、营业餐厅等需路人真实感 | 加入人群密度，写清人数、层次、类型、移动方向和遮挡规则 |
| 同一道具已在场景/角度/首帧可见且又引用道具图，或道具会被拿起/移动/跨段延续 | 加入道具单实例锁 |
| 一镜到底、复杂运镜、动作戏、强遮挡转场、强声音叙事 | 推荐 B |
| 长对白单元（同一说话人连续 ≥3 句，或单句 ≥20 字） | 可选启用**台词气口标记**（§三·1）——把停顿位置与秒数写出来；不启用亦合规，闸门不判缺 |
**多增强叠加超字数时**：优先用 C，删除低收益后缀、压缩管理话术、合并重复约束，把字数留给镜头轨关键控制。**不得删除关键控制信息。**
**§三·1 台词气口标记（可选槽位 · 非必填）**

给长对白的停顿一个显式槽位：闸门 2 的「停顿补偿」是**算**停顿，本槽位让停顿**写出来**，让模型按气口表演，而不是一口气念完。

写法——**追加在台词行 `】` 之外**（引号内一个字都不许动）：

```
台词：【柳娘（压着怒·低语）："你走吧，别回头。"】 〔气口：句尾停顿约 0.8 秒〕
```

四条铁律：

1. **可选**：不写 ＝ 合规；只在长对白单元建议补，闸门**不判缺**。
2. **零改动台词**：标记写在 `】` **之外**，引号内台词文字一个字符不许变——「台词零丢失」优先于本条。
3. **禁写进 `【】` 内**：写进去会破坏 `台词：【角色（语气）："…"】` 的解析，闸门 0/闸门 2 与 `script_feed_diff.py` 都会**漏检该句**。
4. **不新设字段**：气口是**行内注解**，不是新栏；七段式字段名不变（C7 不受影响）。只写「停顿位置 + 秒数」，**禁写「切镜/转场/接下一段」类工作流词**（会被闸门 4 与 C12 拦）。

秒数口径沿用闸门 2：逗号/顿号 ≈0.2s、句号/问号/叹号 ≈0.4s、省略号/情绪停顿 ≈0.6~1.0s、开口前后承接 ≥0.5~1.5s。
