# 短剧信源分级清单（source-ladder）

> 本文件回答一个问题：**去哪儿找，以及找到的东西能信到什么程度。**
> 配套：[intel-card.md](intel-card.md)（按什么格式交）· [recon-evidence.md](recon-evidence.md)（怎么才不出错）

## 〇 · 怎么用这份清单

1. 先按**目标类型**（§五）选 3~5 个源；
2. 按**分级**（§一）决定每个源的结果怎么采信；
3. 检索时**逐源记录**：源名 / 分级 / 拿到什么 / 时点；
4. 列表中的 **【实测可用】** = 本包实际检索验证过能拿到内容；**【待验证】** = 行业常见但未验证，用时须自行确认，不得当成已知事实。

**禁止**：把本清单当成"必须全查一遍"的作业单——**按目标选源**，不要为了"查全"耗尽预算。

## 一 · 三级分级判定口径

| 分级 | 判定标准 | 采信方式 | 写进情报卡时的措辞 |
|---|---|---|---|
| **T1 一手** | 数据由**平台或官方自己公示**，无第三方加工 | 可直接当事实引用 | 「据〈平台〉〈日期〉公示：……」 |
| **T1.5 准一手** | 专业方**基于官方数据的加工/汇总**（指数、周榜、排行） | 可引用，须标加工方 | 「据〈数据方〉〈日期〉榜单（基于〈原始来源〉）：……」 |
| **T2 二手** | 媒体解读、自媒体转述、观众讨论 | **只作旁证**，不得当数据 | 「有报道称（未核实原始数据）……」「观众讨论中（据〈平台〉）……」 |

**分级的唯一依据是"数据的产生方式"，不是"看起来专业不专业"。**
一个排版精美的自媒体榜单文，它仍然是 T2。

## 二 · 国内信源

### 2.1 T1 · 平台官方

| 源 | 能拿到什么 | 取用方式 | 状态 |
|---|---|---|---|
| **抖音官方短剧数据中心** | 短剧热播排名、播放量、完播率、搜索量、互动量综合出的**热播指数** | 通常不直接开放，**经数据站转引**；引用时必须写「经〈数据站〉转引，原始来源标注为抖音官方短剧数据中心」 | 【实测可用·经转引】 |
| **红果官方热榜** | 真人短剧榜 / AI 短剧榜 / 漫剧榜，前 N 名 + 公开热度 | 同上，多经行业周榜或解读文转引 | 【实测可用·经转引】 |

**⚠️ 口径提醒**：抖音的**「热播指数」不是播放量**——它是播放量、完播率、搜索量、互动量的综合值。把热播指数写成"播放量"是**事实性错误**。

### 2.2 T1.5 · 数据指数站与行业周榜

| 源 | 能拿到什么 | 取用方式 | 状态 |
|---|---|---|---|
| `duanjugongcheng.com`（短剧工程 · 红果短剧榜） | 单剧页：**历史最高排名 / 在榜天数 / 当周热播指数 / 环比 / 同题材对比 / 排名走势日线**；页面自标「数据来源：抖音官方短剧数据中心（每日更新）」；另有"剧本心电图"（加工产物） | 引用时标「据短剧工程〈日期〉榜单走势，原始数据来源标注为抖音官方短剧数据中心」；**"剧本心电图"属该站加工，不得当官方结论** | 【实测可用】 |
| `shortdramacast.com`（周更 · 热播短剧精选） | **每周热播短剧 18 选**：按红果真人/AI 剧/漫剧官方热榜 + ReelShort TOP Verticals 选片；每剧给集数、主演、一句话简介、公开热度（万）、题材标签 | 是**汇总型 T1.5**——它整合了多个官方榜，引用时写「据 SceneTrace〈周期〉周选（选片口径：红果官方热榜 + ReelShort TOP Verticals）」 | 【实测可用】 |

### 2.3 T2 · 媒体解读与讨论

| 源 | 能拿到什么 | 采信方式 | 状态 |
|---|---|---|---|
| 今日头条 / 百家号等**榜单解读文** | 榜单前 N 名的解读、看点、槽点、争议 | 只作旁证；**文中的数据仍须回溯到原始榜单**；可用来**发现线索**（"哦原来有这部剧"），再用 T1.5 求证 | 【实测可用】 |
| 抖音 / 微博 / 小红书 / B 站 讨论与拉片 | 观众真实反馈、争议点、名场面 | 只作 §⑨「观众反馈」栏；**注明平台与采集时点** | 【实测可用】 |
| 豆瓣 / 剧评 | 长评、评分 | 同 T2 | 【待验证】 |

## 三 · 外网信源

| 源 | 能拿到什么 | 分级 | 状态 |
|---|---|---|---|
| `verticaldrama.tv` | **独立指数**：4,000+ 部竖屏剧目录，覆盖 DramaBox / ReelShort / NetShort / FlareFlow / GoodShort 等 12+ 平台；**周榜**（周二 00:00 UTC 同步）+ Talent Index（演员影响力）+ **分国家市场数据**（带 Omdia / Deloitte / Sensor Tower 等出处）；行业新闻 | T1.5 | 【实测可用】 |
| `cherrybowl.io` | **CherryBowl Weekly Chart**：按"独立来源点名数"排序的周榜；**方法公开**——只在原文中**逐字出现**的剧名才算（「a title a model invented cannot chart」），下榜理由必须逐字引用原文 | T1.5（**方法最透明，优先采信**） | 【实测可用】 |
| `trysonar.app` | **App Store / Google Play 应用榜周报**（周二更新）：短剧 App 的排名变化（ReelShort / DramaBox / BlinkDrama / PineDrama / DramaWave 等），iOS 与 Google Play 分开 | T1.5 | 【实测可用】 |
| 行业媒体（Deadline / Variety / The Straits Times 等） | 投资、政策、制作动向 | T2（若为其独家调查可升为准一手） | 【实测可用·经转引】 |
| Reddit / TikTok / YouTube 讨论 | 海外观众反馈、名场面 | T2 | 【实测可用】 |

**⚠️ 外网与国内不可直接比较**：外网指数覆盖的 App 与国内平台是两套生态，**排名不可跨生态换算**（"ReelShort 第 1" 与 "红果第 1" 之间没有可比性）。

## 四 · 各目标类型的选源速查

| 目标类型 | 首选源（按顺序） | 建议检索词形态 |
|---|---|---|
| **单剧对标**（国内） | ① 短剧工程单剧页 → ② 周选站 → ③ 平台搜索 → ④ 解读文/讨论 | 「〈剧名〉 短剧」「〈剧名〉 榜」「〈剧名〉 热度」 |
| **单剧对标**（海外） | ① verticaldrama.tv → ② CherryBowl → ③ Sonar App 榜 → ④ 外网讨论 | 「〈剧名〉 ReelShort / DramaBox」「〈剧名〉 vertical drama」 |
| **题材扫描**（国内） | ① 周选站当期 → ② 短剧工程同题材对比 → ③ 榜单解读 | 「短剧 周榜 〈当前年月〉」「短剧 〈题材〉 火」 |
| **平台扫描** | ① 周选站 → ② 单剧页走势 → ③ 解读文 | 「红果 短剧 热榜 〈当前年月〉」 |
| **外网扫描** | ① verticaldrama.tv 周榜 → ② CherryBowl 周榜 → ③ Sonar → ④ 行业媒体 | 「ReelShort top trending 〈当前年月〉」「vertical drama ranking 〈当前年月〉」 |

**⚠️ 检索词必须带当前时点**：搜"短剧周榜"会拿到任意年份的结果；**必须带年月**，否则极可能引到过期榜单（这是本引擎最高频的翻车点）。

## 五 · 独立信源数怎么数（轻量版唯一的热度参考）

轻量版**不算热度分**。若确实需要一个"有多火"的参考，只数：

```
独立信源数 = 点名提到该剧的【不同来源主体】个数
```

三条数法铁律：

1. **同一篇文章被转载十次 = 1 个来源**（按**原始发布方**去重，不按链接去重）；
2. **同一媒体的不同文章算 1 个**（"一家媒体说了三次"不是三个来源）；
3. **只有逐字点名该剧的才算**——评论里顺带一提、合集里罗列的不算。

> 这套数法来自外网公开周榜（CherryBowl）的方法论：**用"有几个独立主体在说"替代"某个平台给了多少分"**，因为前者更难伪造。

## 六 · 拿不到的东西（如实告知，不要硬编）

| 拿不到 | 原因 | 正确做法 |
|---|---|---|
| 平台 App 内的完整榜单 | 需登录 / 客户端内 | 用 T1.5 转引并标注 |
| 精确播放量 | 平台不公示绝对值 | 用公示的**相对指标**（排名、热度指数），**不要换算成播放量** |
| 付费卡点位置 | 需实际观看 | 写「未找到」，或据公开讨论标注为**推测** |
| 完整分集剧情 | 需实际观看 | 只写公开可见的故事骨架 |
| 未公开的完播率 / 成本 | 商业机密 | 写「未找到」 |

**铁律：拿不到就写「未找到」。** 一份诚实标着三个「未找到」的卡，比一份全填满但有两处编造的卡**有用得多**。

## 七 · 维护纪律

新增或改动信源时：

1. 更新本表 + 标注分级 + 标注状态（实测可用 / 待验证）；
2. **状态不得越级标注**——没实测过的源只能标【待验证】；
3. 外网来源与本表分级口径一致，新增外网源按同一分级标注，**不得另立一套清单**。
