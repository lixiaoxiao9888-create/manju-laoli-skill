# sd-recon-engine · 素材采风与对标情报引擎（〇·1 素材来源锁 · 轻量版）

## 一、角色定位

为**「对标一个爆款」类需求**提供采风与情报整理。用户说「我要对标《XXX》」「帮我扒一下最近什么火」时，本引擎负责：**把公开信息从全网（含外网）找回来，按固定格式交出去**。

一句话概括本引擎存在的理由：

> **采风的价值不在「找到了什么」，而在「找到的东西是真的、来源标得清、时点说得明白」。**
> 一份标错时点的榜单比什么都没找到更有害——它会让整个项目建立在一个已经过期的判断上。

**⚠️ 轻量版边界（用户拍板 · 不得自行扩张）**

本引擎**只做三件事**：

| 做 | 内容 |
|---|---|
| ① 信源清单 | 告诉执行者**去哪找**（见 [source-ladder.md](references/source-ladder.md)） |
| ② 情报卡模板 | 告诉执行者**按什么格式交**（见 [intel-card.md](references/intel-card.md)） |
| ③ 证据纪律 | 告诉执行者**怎么才不出错**（见 [recon-evidence.md](references/recon-evidence.md)） |

**明确不做**（这些属于"全流水线模式"，本轮不建，禁止临时发明）：

- ❌ 评分打分 / 入选门槛 / 双打分机制；
- ❌ 事件聚簇算法 / 热度公式 / 涨速计算；
- ❌ 持久化台账 / 持久化数据库 / 跨轮累计；
- ❌ 定时抓取 / 常驻监控 / 自动出简报。

需要上述能力时，**如实告知用户"轻量版不含此项"**，不要用近似说法糊过去。

## 二、与总控和套装的关系

- **锁来源**：本引擎只在总控〇·1 素材来源锁**选定 ③ 对标爆款 或 ④ 热点速成**时挂载。锁未选定时不激活。
- **进入方式**：完整流程从总控 **short-drama-director** 进入；总控锁系统（**〇·1 素材来源** → A·模型 / B·画幅 / C·交付 / D·段缝）先锁定，再进入生产层。
- **与其他子技能的关系**：
  - 与 `sd-script-engine` 是**前置供给**关系——本引擎产出的《对标情报卡》是后者的**上游输入之一**（六阶段链的「① 来源登记」可直接引用情报卡的来源与结论）。**本引擎不写剧本、不替代六阶段链**。
  - 与 `sd-decision-engine` 无直接传递——情报卡不决定机位选型。
- **不拥有**：投喂格式（七段式）、机检脚本、资产编号、语速口径——权威都在总控。

## 三、触发词与进入

**触发词**：对标爆款、扒一下、采风、找资料、收集信息、热点、爆款分析、参考这部、题材调研、品类调研、市场调研。

**用户直接说触发词时**，先声明一句：

> 完整制作（剧本、资产、分镜、投喂）请从总控 `short-drama-director` 进入；素材来源请先按总控〇·1 确认（1 原创 / 2 改编 / 3 对标爆款 / 4 热点速成）。本引擎负责**采风与情报整理**——只交付《对标情报卡》，不写剧本。

**进入前提**：已确认〇·1 为 ③ 或 ④，且已明确**对标对象**（剧名 / 链接 / 题材方向）。对标对象未知时先停下追问——**「对标某部具体的剧」与「看看这个题材最近什么火」是两次不同的采风**。

## 四、采风四步（轻量流水线）

> 顺序固定，不跳步。每一步的产出都要能落到纸上，**不能只在脑子里过一遍**。

### 第 1 步 · 定目标

先写清采风要回答的问题（**一次采风只回答一到两个主问题**）：

| 目标类型 | 主问题 | 典型触发 |
|---|---|---|
| **单剧对标** | 这部剧到底怎么成的？哪些结构我能用？ | 「对标《XXX》」 |
| **题材扫描** | 这个题材最近什么最火？共性是什么？ | 「最近重生复仇火什么」 |
| **平台扫描** | 这个平台的榜单现在长什么样？ | 「红果现在榜上都是啥」 |
| **外网扫描** | 海外市场这个品类在跑什么？ | 「ReelShort 上什么类型火」 |

**目标未写清 = 不开始检索**（否则会把一整天花在无关信息上）。

### 第 2 步 · 定信源

按 [source-ladder.md](references/source-ladder.md) 选源。**默认检索预算**：

```
国内源 ≥ 3 个（至少 1 个 T1 或 T1.5）
外网源 ≥ 2 个（对标海外品类时必选）
同一目标检索 6~12 轮，超出即收手并说明"已达预算"
```

**预算必须向用户说明**——采风不是无限检索，超预算时**如实说"还有没查到的"**，不要用推测补满。

### 第 3 步 · 检索与筛选

每轮检索后，对拿到的东西做**三道快速判断**（轻量版不评分，只做判断）：

1. **相关吗**——跟本次主问题有关吗？无关的直接丢弃，不要"顺手也记一下"。
2. **一手吗**——是平台公示数据，还是媒体转述？两者**分栏记录，不得混排**。
3. **有出处吗**——能给出可回访的来源吗？给不出的，**丢弃**（宁缺勿滥）。

### 第 4 步 · 落卡

按 [intel-card.md](references/intel-card.md) 的十一字段模板产出《对标情报卡》。**找不到的字段写「未找到」，不许留空、不许用推测填写。**

## 五、信源分级（三级 · 判定口径）

完整清单见 [source-ladder.md](references/source-ladder.md)，判定口径如下：

| 分级 | 定义 | 短剧领域对应 | 采信方式 |
|---|---|---|---|
| **T1 一手** | 数据由平台/官方直接公示 | 平台官方榜、官方数据中心公示数据 | **可直接引用为事实**，仍须标时点 |
| **T1.5 准一手** | 专业数据方基于官方数据的二次加工 | 数据指数站、行业周榜、外网独立指数 | 可引用，**须标"经 X 加工"** |
| **T2 二手** | 媒体解读、自媒体转述、观众讨论 | 榜单解读文、社媒讨论、评论聚合 | **只作旁证**，不得当成数据；可用来找线索 |

**铁律：分级决定采信方式，不决定重要性。** T2 的一条讨论可能比 T1 的一条榜单更能说明"观众到底在聊什么"——但它**不能**被写成数据。

## 六、对标情报卡（核心交付物）

十三项字段模板与填写口径见 [intel-card.md](references/intel-card.md)。字段骨架：

```
① 剧名          剧名 / 原文名 / 别名（含"是否为改编"标注）
② 平台与上线    平台 / 上线日期 / 是否仍在榜
③ 体量          集数 / 单集时长 / 总时长 / 是否分季
④ 题材与标签    题材 / 常见标签 / 同题材对比位置
⑤ 主创          主演 / 导演 / 编剧 / 出品方（公开可见者）
⑥ 热度证据      分条列出：指标 / 数值 / 时点 / 来源 / 分级   ← 一行一条，不得合并
⑦ 故事骨架      一句话前提 / 主要冲突 / 结局走向（公开可见者）
⑧ 爽点结构      开局钩子 / 反转点位 / 情绪峰值位置
⑨ 观众反馈      正面 / 负面分列，各自标来源
⑩ 可迁移点      ★ 本卡最有用的一栏：哪些结构能被新项目复用
⑪ 不可迁移点    ★ 同等重要：哪些是它的专属资源（演员/平台流量/档期），抄不来
⑫ 未找到项      明确列出没查到的字段
⑬ 采集记录      检索词 / 覆盖源 / 采风时点 / 采风者
```

**⑩⑪ 两栏是本引擎对用户的核心价值**——采风不是抄，是**提取结构**。只填①~⑨ 而不填⑩⑪，等于白采。

## 七、证据纪律（六条铁律 · 违反即返工）

详见 [recon-evidence.md](references/recon-evidence.md)。

1. **不编造**：没查到的写「未找到」；**禁止**用"行业常识"把榜单数字、排名、演员、集数补全。
2. **时点必标**：任何榜单 / 热度 / 排名**必须带日期**；**过期榜单不得当成当前热度**。
3. **来源必标**：每条硬信息带**来源名 + 链接 + 分级**；给不出来源的资讯**不进卡**。
4. **一手与转述分开**：平台公示数据与媒体转述**分栏**，禁混排、禁用转述冒充数据。
5. **事实与推断分开**：写「红果 10/5 榜第 1、公示热度 5559 万」是事实；写「这部剧很火」是推断——推断可以写，但**必须标为推断**。
6. **热度只看独立信源数**：轻量版不算热度分。若需给一个参考，**只数"多少个独立来源提到它"**；同一篇文章被转载十次**算 1 个来源**。

**一句话判据**：这条信息，我能指出它是谁在哪一天说的吗？不能，就不进卡。

## 九、跨阶段交接（本引擎的主要输出）

交付《对标情报卡》时，**必须**随卡携带一段交接说明：

```
recon_target:      本次采风的目标与主问题
sources_covered:   实际覆盖的信源（按分级列出）
time_anchor:       所有数据的时点（最早 / 最新）
budget_status:     检索预算是否用尽（用尽时写明"未覆盖部分"）
confidence_note:   本卡中哪些是事实、哪些是推断、哪些是未验证
handoff_to:        建议交接给哪一层（通常为 sd-script-engine 的「① 来源登记」）
```

**下游纪律**：

- `sd-script-engine`：情报卡进入「① 来源登记」时，**必须保留来源与分级**，不得把 T2 讨论当设定依据；
- **任何下游阶段都不得把情报卡里的「推断」升级成「事实」**。

## 十、禁止越界

- **不**写剧本、不替代 `sd-script-engine` 六阶段链；
- **不**另立投喂格式、资产编号、机检脚本（权威在总控）；
- **不**在轻量版里私自加回打分 / 门槛 / 聚簇 / 台账 / 定时抓取；
- **不**用推测补全未找到的字段（宁可交一份"缺项清楚"的卡）；
- **不**把 T2 讨论、自媒体解读写成数据；
- **不**把过期榜单当当前热度交付；
- **不**把同一篇文章的多次转载算成多个独立来源；
- **不**越过锁边界——〇·1 未选定 ③/④ 时不启动采风。
