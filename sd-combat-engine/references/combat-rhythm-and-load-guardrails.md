# 打戏节奏与渲染负载护栏

> **本库定位**：C21（激烈度护栏）管「不许躺平」，本库管「不许躺平得太用力」。
> 二者缺一，打戏必然在「呆板站桩」与「小孩打架」两档之间来回摆。
>
> ⚠️ **本库是「参考护栏」，不是凌驾于打戏引擎之上的硬闸**：当本库量化口径与
> `sd-xuanhuan-engine` / `sd-real-engine` / `sd-combat-engine` 自身规则库冲突时，
> **以打戏引擎本档规则为准**（详见 §七「档位豁免与放行条款」）。
> 机检侧 C22a~d 一律为 **WARN**，**永不作为 P0 FAIL 阻断交付**。

---

## 〇、为什么建这份库（病根档案 · 勿删）

出片实测（UE5.5，15 秒玄幻打戏稿，机检 `PASSED / 0 error / 0 warning`），
出片观感 = **「太呆滞，两个人撞来撞去，拿手在那动，像小孩打架」**。
逐秒抽帧复盘后定位三条病根，**全部是"规则存在但没进执行链"或"规则缺可机检口径"**：

### 病根① 一镜塞多动作 —— 规则写了，量化口径挂在别的引擎里
- **既有规则**：`combat-iron-laws.md` 铁律26 第 7 条已明写
  **「一个 2 秒节点只主攻一个主爆点写透、每 2 秒主动作 ≤3（单秒绝不超过 3）」**；
  铁律0 第1步 亦有 **「一镜一主任务，不贪多」**。**规则不缺。**
- **实测违反情况**：15 秒稿 V2 四镜的主任务数 = `1 / 2 / 4 / 3` 个（镜头3 一次塞了
  捅入 + 角力 + 拽倒 + 滚地互殴 = 4 个主任务），**逐镜违反铁律0 第1步**。
- **★ 真正病根在接线**：打戏引擎的「六步流程」末端第 5 步自检挂的是
  `combat-iron-laws 铁律45 五维交替检验 + combat-intensity-guardrails（C21）`，
  **铁律26 第 7 条这条"动作数上限"从未被抬进自检闸口**；
  而实际交付走的是**总控七段式投喂链**——那条链上没有任何一站接这条上限。
  → **规则在 A 引擎，执行在 B 链，A 的硬约束在 B 上失效。**
- **机检盲区**：C1~C26 全 35 条 C 码中，唯一带"上限"语义的是 C14（OS/VO 配额），
  **打戏域零条上限型判据**。→ 稿子动作越密，C21 越容易满足，**护栏在方向上反向鼓励内卷**。
  *（※「35 条」为 2026-10-09 建库时口径；该盲区已由本库 §五 新增 **C22a 上限型判据**修复。2026-10-10 六维审计后全包机检口径为 **C1~C26 · 子检查码共 104 条**（2026-10-24 补 C40a~d 群像行为缺失；2026-10-11 复核实测补 **C7b 镜行解析元检查** 与 **C7c 站位人物账解析元检查**；2026-10-11 补 **C18m 段缝景别落差**；2026-10-12 补 **C26a~d 锚点继承门**；2026-10-13 补 **C27a~d 对话戏节奏与台词密度下限**；**2026-10-13 项目体检补 C18n 人物特写占比**），见 `sd-qc-engine/references/machine-check-manual.md` §二。）*

### 病根② 单镜匀速 —— 只有"镜与镜之间"的节奏维度，没有"镜内"维度
- **既有规则**：铁律45 五维交替之「④速度节奏交替」要求
  `超高速连段↔凝滞冲击帧↔短暂蓄势↔高强度爆发↔短暂收势喘息，每5-8镜做一次节奏波`。
- **★ 真正病根**：① 该条判据是 **"禁止任何一维连续 5 镜不变" = 下限型**，
  只管"不许一直不变"，**没有"一镜内部必须有速度层次"的概念**——
  于是**全片四镜都写成匀速位移，它完全查不出**（实测该稿五维交替全部合规）。
  ② 铁律26 九要素（①镜头空间起点 ②高度朝向 ③人物动作 ④能量生命周期 ⑤特效尺寸
  ⑥参照物 ⑦命中反馈 ⑧环境结果 ⑨镜头落点）**九项全是空间/材质/静态结果，
  零项是"时间拍"** → 写作清单层面，"一镜匀速"是合法产出。
- **实测**：V2 稿「蓄力/预备」命中 **0 次**（出手即最快、匀速到底）。

### 病根③ 缺全身景别 —— 规则要求"交替"，没规定"必须含全身"
- **既有规则**：铁律45 ③景别机位交替要求 WS/EWS/FS/MS/CU/ECU 六档交替。
- **★ 真正病根**：只要求"交替"，未要求"**必须含全身档**"。
  V2 稿景别序列 = `中近景→近景→特写→大远景`，
  **从贴身档一步跳到超远景，全片无任何全身入画的中景/中全景**
  → 贴脸时看不见重心与位移幅度，位移只剩"撞来撞去"的读感。

### 病根④（底层）"模型渲染能力上限"从未被写下来
全包 129 份规则库中，**"视频模型 3 秒内可靠渲染约 2~3 个独立动作单元"这条硬约束零命中**。
没有这条，任何"动作数上限"都只是无根之木——写规则的人不知道上限从哪来。

## 一、渲染负载硬上限（病根①④ 的唯一口径）

### 1.1 独立动作单元（Independent Action Unit, IAU）
**定义**：一次**独立可命中的打击或位移动作**。判定词表（机检 `COMBAT_IAU_RE`）：

```
撩斩 斩中 劈中 劈碎 劈开 挑刺 刺中 捅入 横扫 竖劈 剪斩 扫腿 扫堂 踢中 踹中
顶中 肘击 膝顶 点中 拍中 砸中 撞中 撞碎 扑击 砸在 撞在 劈在
抓住 揪住 扼住 勒住 擒住 抓住脚踝 抓住手腕
格挡 架住 架开 格开 磕开 硬接 硬扛 对撞 交击 兵器相击 拳掌相交
```

**同一次接触的多写只算 1 个**（例：`格挡 + 硬接` 是同一次架住，`拍中 + 撞中` 是同一次命中）。
机检按**去重后的词频**计数，不按分句数。

### 1.2 上限（**上限型判据 = 不许过载**）

| 镜长 | IAU 上限 | 依据 |
|---|---|---|
| ≤ 2s | 2 | 铁律26「单秒绝不超过 3」的保守化 |
| 3s | **2** | 实测：3s 内塞 5 个 → 模型只渲染第一个，其余丢失 |
| 4s | 3 | |
| 5s | 3 | |
| ≥6s | 4 | 每 +3s 放宽 1 个 |

> **为什么 3s 只能是 2 而不是我原来以为的 3**：实测模型在 3 秒内可靠渲染 **2~3 个 IAU**，
> 但**一旦超过 2 个，第 3 个之后保质率骤降**。留 1 个冗余 → **3s 定为 2**。
> 违反此条的症状是**可辨识的**：多动作稿出片必现"贴脸互殴 + 后半段动作消失"。

### 1.3 一镜一主任务（铁律0 第1步的量化落地）
每镜只能有 **1 个主任务**，取自铁律0 第1步六选一：
`证规模 / 证力量 / 证速度 / 证招式 / 证招式轨迹 / 证情绪`。
判定：若某镜 IAU 中属于**不同动作类型**（拳脚/兵器/投技/摔擒拿/突刺/反弹/暗器/大招）的
**≥3 类**，即判"一镜多任务"。机检 `C22a` 同时查这两项。

## 二、镜内速度四拍（病根② 的唯一口径）

### 2.1 四拍定义
**每一镜内部**必须具备下列节拍，**顺序不可颠倒**：

| 拍 | 语义 | 时长占比 | 判定词表 |
|---|---|---|---|
| **① 起（慢）** | 蓄力/预备/重心下沉/微调站位 | 15~30% | `沉肩 压低重心 碾碎 绷紧 屏息 蓄 预备 屈膝 后仰 重心下压` |
| **② 爆（快）** | 蹬地暴起/骤出/疾掠 | 极短 | `暴起 骤然 猛地 瞬间 陡然 疾掠 扑上 冲出 甩出 弹射` |
| **③ 顿（停）** | 命中瞬间画面时停 | 2~3 帧 | `顿住 时停 顿帧 定格 凝固 压在 静止` |
| **④ 收（慢）** | 卸力/稳住/滑步/落地缓冲 | 20~35% | `卸力 稳住 侧滑 滑退 收势 滑步 落地缓冲 后撤 站定 单膝` |

> **顿拍是全片最关键的一拍**：命中瞬间画面定住 2~3 帧，是"打到了"的唯一视觉证据。
> 缺顿拍 = 观众没看见"击中" = 再多动作也读作"在乱动"。

### 2.2 逐镜判定（**不是全片总数**）
- **必须逐镜各含 ≥1 处四拍**。
- ⚠️ **禁用"全片总数 ≥ 镜数"口径**：该口径下"镜头1、4 全空 + 镜头2、3 各塞两处"
  总数照样够，**一处写满、一处全空能蒙混过关**（构建期实测该缺陷，
  改为逐镜判定后立即咬出两处真缺口）。
- ⚠️ **节拍统计须剔除纯结构标注**：`（起手拍，慢）`这类括号标签是给人看的结构说明，
  计入命中 = **护栏被自己的标注喂饱**，删掉真实描述反而照样通过。
  但**不得连坐含实写正文的括号块**（如`（命中瞬间画面顿住两帧，命中点炸开一圈冲击波）`——
  这是正文，必须保留）。正法：**只剥离 ≤6 字的纯结构标签**。

### 2.3 速度层次作为景别之外的第五维
铁律45 的速度维度管"镜与镜之间"，本条管"**镜内**"。两者叠加才构成完整节奏：
- 镜间：铁律45 ④速度节奏交替（每 5~8 镜一个节奏波）
- 镜内：本节四拍（每镜都有）

## 三、全身景别下限（病根③ 的唯一口径）

### 3.1 硬下限
**每 2 镜至少 1 镜为全身入画**（`中全景 / 中景 / 全景 / 大远景` 中，
须**至少 1 镜能看清身体重心与双脚位置**）。
- 全片 `中景+中全景` 合计 **≥ 半数镜数**。
- ⚠️ **贴脸档（特写/近景/中近景）连续不得超过 2 镜** —— 第三镜必须切回全身档，
  否则观众丢失空间参照，动作读作"原地乱动"。

### 3.2 为什么这条不可省
打戏的说服力来自**身体力学**：蹬地、转胯、腰、肩、手的完整发力链，以及重心转移。
全身档是**唯一能同时看见"重心"与"位移量"**的景别。
贴脸档只能看见接触点，看不见"谁把谁推到哪里" → 观感即"撞来撞去"。

## 四、机检载体

| 子码 | 判据 | 方向 | 阈值 |
|---|---|---|---|
| **C22a** | 单镜独立动作单元（IAU）超上限 | **上限型** | 按 1.2 表 |
| **C22b** | 一镜多任务（动作类型 ≥3 类） | **上限型** | ≥3 类 |
| **C22c** | 镜内速度四拍逐镜缺拍 | **下限型** | 逐镜 |
| **C22d** | 全身景别不足 / 贴脸档连续 >2 镜 | **下限型** | ≥半数；≤2 连 |

- **触发门**：与 C21 共用 `--combat on|off|auto`（默认 auto，打戏信号词达阈值即启用），文戏稿跳过。
- **不改 C21**：C21 管激烈度（不许躺平），C22 管负载与节奏（不许过载/不许匀速），二者独立。
- **C22c 的统计实现**：必须走 `strip_struct_annot()` 剔除纯结构标注后再逐镜计数（见 2.2）。

## 五、写作期自查（挂在打戏引擎第 5 步，与 C21 并列）

出稿前逐镜问 6 问，任一为"否"即返工：
1. **这一镜有几种独立动作？**（>2 → 拆镜或删动作）
2. **这一镜的动作类型是否 ≤2 类？**（≥3 → 只留 1 类）
3. **这一镜有没有"起—爆—顿—收"四拍？**（缺任一拍 → 补）
4. **命中瞬间画面定住了吗？**（无顿帧 → 观感必然糊）
5. **这一镜能看见身体重心吗？**（贴脸档 → 检查是否连续超 2 镜）
6. **抽掉全部特效后，剩下的纯动作连得成一段打得起来的武打吗？**（C21 护栏⑥，本条不替代）

### ⚠️ 与铁律26 第 7 条的口径差异（必读，避免误判）
- 铁律26 原文：**「每 2 秒主动作 ≤3（单秒绝不超过 3）」** —— 这是**打戏引擎内部**的节点口径。
- 本库 1.2 表：**3 秒镜 ≤2 个 IAU** —— 这是**投喂稿**的口径，**比铁律26 更严**。
- **两者不冲突**（本库更严，取严者）；差异原因：投喂稿的单镜是"直接渲染单元"，
  而铁律26 的 2 秒节点是"编织单位"，后者还要熔进同一条长句、可被后续节点稀释。
- **判罚以本库（投喂稿口径）为准**，因为出片质量由投喂稿决定。

## 六、出片复盘义务（本库独有 · 反向约束）

**任何投喂稿出片后，必须抽帧复盘并回填本库**：
1. 抽帧：`-vf "fps=1"` 每秒一帧 + `tile` 拼网格图，**逐帧看**，不听描述。
2. 回填三问：
   - 出片是否**每镜都看得见身体重心**？（否 → §3 阈值需下调）
   - 出片是否**每镜都有命中顿帧**？（否 → §2.1 顿拍需加严到"必须显式写帧数"）
   - 出片是否**出现"动作消失"**？（是 → §1.2 上限需下调）
3. ⚠️ **机检 PASSED ≠ 出片好看**。稿子机检 `PASSED / 0 error / 0 warning`，
   出片仍是"呆滞"。**报告护栏结论时，必须同时给出机检数据与出片抽帧结论，两者不可互替。**

## 七、档位豁免与放行条款（★让行 · 打戏引擎规则优先 · 2026-10-12 用户裁定）

> **一句话**：**本库让行于打戏引擎本档规则**。本库 §一~§六 提供的是**通用工程参考线**；
> 打戏档（R1 写实 / R2 通用高燃 / R3 玄幻）持有完整领域规则库，**冲突时以引擎本档为准**。
> C22a~d 是 **WARN 参考**，**不是 P0 FAIL**；⛔ **不得为消除告警而把打戏改呆**。

### 7.1 为什么必须让行（病根⑤：单样本外推）

本库 §一~§六 的量化口径——`3s 镜 ≤2 个 IAU` / `逐镜四拍` / `全身档 ≥ 半数镜` / `贴脸档连续 ≤2 镜`——
**全部来自 2026-10 一次 UE5.5、15 秒、单场"一对一贴身对拆"稿的逐帧复盘**（见 §〇 病根档案）。

- 单样本对「一人一场、近身互殴」有效；
- 但**外推**到「近景机枪对招连招段 / 枪战狙击 / 追车 / 暗杀 / 多人围杀 / 万剑归宗 / 对军清场 / 术法对轰 / 巨兽法相」
  会**反向压制**：把本该连排的近景对招拉开成远景、把连招拆成单招、给每镜硬塞慢动作 → **观众读到的就是"呆板"**。
- 这不是"护栏不够严"，而是**把单一戏型的量化线当成了全戏型的法规**。

### 7.2 豁免表（先判档 · 再决定是否采纳告警）

| 场面类型（先定档） | 豁免/放宽项 | 放行口径（改按什么执行） |
|---|---|---|
| **R1 写实 · 近景机枪对招 / 连招段**（序列化招式链） | C22a 上限、C22c 逐镜四拍、C22d 贴脸档连续上限 | C22a 改按 `combat-iron-laws.md` 铁律26 节点口径（每 2 秒主动作 ≤3）；C22c 改为「**段落层面**至少完整出现一次起-爆-顿-收」，**不再逐镜强制**（**镜间**速度交替仍以铁律45④ 为权威）；C22d 贴脸档连续上限放宽至 **≤4 镜**——机枪对招本就是贴身档连排，这是本档设计而非缺陷 |
| **R1 写实 · 枪战 / 狙击 / 暗杀 / 追车 / 儿童向** | C22d、C21 §二·①③⑥ | 允许**一方静止**、允许**全程零实体接触**；「贴身缠斗 ≥ 片长 1/3」不适用 |
| **R1 写实 · 多人轮转**（1v2 / 1v3 / 2v2 / 3v3） | C22d | 景别策略一律按 `sd-real-engine/references/multi-opponent-rules.md` §六（人越多镜头越收紧） |
| **R3 玄幻 · 大场面档**（万剑归宗 / 剑阵 / 法阵 / 法相 / 法天象地 / 巨兽 / 对军清场） | C22a、C22d、C21 §二·①③ | 大场面本就是**宏观调度**：允许整段大远景/全景，允许"站定施展术法"——**这是"施法"不是"躺平"**；尺度四件套（`sd-xuanhuan-engine/references/grand-scale-domains.md`）优先 |
| **R3 玄幻 · 术法对轰 / 远程法术** | C21 §二·①③⑥ | 对波/对轰是玄幻档的**合法主武器**，不按"用特效冒充激烈"处理；只保留保底条（§7.3） |

### 7.3 保底（豁免之后仍然成立的两条）

无论哪一档，以下两条**不放行**：

1. **不得整场零接触、零位移、无收束**（"对峙 → 站着发光 → 对峙"的空转模板）；
2. **相邻区间的机位不得完全相同地连排 ≥3 段**。

即：**豁免的是"量化上限"与"几何模板"，不是"打得起来"本身。**

### 7.4 执行口径（写进《改动复验报告》）

- 机检 `--combat on|off|auto` 输出的 C21/C22 是 **WARN 参考**；出稿时**先判档、再逐条决定采纳或豁免**，
  采纳或豁免的理由写进《改动复验报告》（`sd-qc-engine`）。
- ⛔ **禁止**为了消 C22 告警而：拆掉引擎的招式序列、把连续的近景对招拉开成远景、
  给每一镜硬塞一段慢动作、或把大场面写成一镜一动作——**那是把"呆板"当合规**。
- 豁免不影响 §7.3 两条保底；也不影响 C21/C22 之外的门（结构门 / 语义风险门 / 画风锁门照旧）。
