> 🔗 **流程位置：P3 分镜·图形化环**（在导演稿与文字分镜之后、投喂封装之前）。精编自《灵境AI漫剧制作流 V3.9.0》`manju-storyboard-designer`，并按本包"出图资产"体系落地。

## 〇、先划清：本文件管的是"故事板图"，不是另外三样东西

本包此前**有四种容易与"故事板"混淆的产物**，必须先区分，否则一定会做重、做歪：

| 产物 | 是什么 | 形态 | 归属 |
|---|---|---|---|
| **文字分镜** | 逐镜的文字镜头序列（景别/焦段/机位/运镜） | Markdown 文本 | `sd-storyboard-engine/SKILL.md` |
| **九宫格场景图** | **纯场景** 3×3（多机位/多子区域），**画面禁人物** | 生图提示词 → 1 张图 | `sd-asset-engine/references/scene-grid-template.md` |
| **分镜看板** | md → 单文件离线 **HTML**，双击即开，供人查看 | HTML 文件 | `short-drama-director/references/storyboard-board-lite.md` |
| **15 格动作 PREVIS** | **打戏**专用 15 格动作预演 | 生图/预演 | `sd-combat-engine/` |
| **★ 故事板图（本文件）** | **带人物 + 带动作相位 + 带镜头信息**的多面板图，**每段一张**，作为**视频生成的视觉依据** | 生图提示词 → 1 张图（含 N 个面板） | **本文件** |

**一句话**：九宫格管**场景长相**（无人），故事板管**这场戏怎么演**（有人、有动作相位、有镜头）。

> ⚠️ **「四宫格」歧义提醒（2026-10-11）**：用户说「**四宫格故事板**」= **本文件**管辖的 **2×2 四面板故事板图**（**一段**的 4 个动作相位：起始/过程/反应/出口）；说「**四宫格推演 / 剧情分镜格 / 推演宫格**」= `plot-deduction-grid.md` 管辖的 **2×2 四格剧情推演图**（**一场**戏的 4 个叙事瞬间）。**同名不同物；用户说不清就两件都出。**

## 一、六条硬规则（先记这六条）

| # | 规则 | 说明 |
|---|---|---|
| **1** | **每段一张** | 以**段**（投喂的生成单元，≤15 秒或按 D 锁段缝切成的一个单元）为单位，**一段出一张故事板图**。跨段共用同一张＝违反（每段动作相位不同）。 |
| **2** | **格数由动作复杂度决定，不机械九宫格** | 3 格、5 格、6 格、8 格都可以；**动作复杂就多拆格，文戏静态就少拆格**。**禁止为了版式好看强行凑 9 格**（这是本文件与九宫格的本质区别）。 |
| **3** | **面板边界 ≠ 剪辑点** | 一个面板 = 一个**动作相位**，不是一个镜头。**面板变多不意味着要切镜**；切不切由导演稿的镜头策略模式决定（见 §七）。 |
| **4** | **面板必须能回溯到导演稿** | 每格的面板 ID、站位、动作相位，必须能在导演稿（`short-drama-director/references/blocking-direction.md`）与文字分镜里找到对应项；**不允许故事板自行新造动作或镜头**。 |
| **5** | **版式与格数下限（★2026-10-22 修正：「下限」已废止，格数改为 = 该段镜数）** | **格数 = 该段镜数，不设固定值**：一段有几镜就几格，4/6/9/12 格都正常。**版式是排版结果、不是格数来源**：4 格→**2×2 四宫格**、5 格→单行 5 或 2+3、6 格→**2×3 六宫格**、8 格→2×4、9 格→3×3、12 格→3×4。⛔ 禁止把"文戏 4 格"当作硬性下限去砍镜——下限与镜数冲突时，**永远是格数服从镜数**；确需合并时用 `〔镜K+M〕` 并在段首写理由。（旧口径「文戏 4 格起 / 打戏 6 格起」废止） |
| **6** | **交付清单必列（禁静默跳过）** | P3 收尾必须逐段在交付清单写「**故事板图：段N ✅ {格数}({版式}) / ⛔豁免（理由）**」；**不列清单又没出、或只写「略/同上/按需」= P3 未完成，禁止进 P4**；用户点名要时**必出、不适用豁免**。 |

## 二、面板链：一张图里装什么

```
【故事板图 · 段{n}】 场景 SCN-{编号} · 模型 {A锁} · 画幅 {B锁} · 面板数 {N}
  面板 1  [起始]  镜1 · 中景 · 起势    @A（北窗下·朝南·垂手）        ← 见 §四 入口帧
  面板 2  [过程]  镜1 · 中景 · 拔剑    @A（重心前压·右手上抬）
  面板 3  [接触]  镜1 · 中近景 · 交击  @A⇄@B（双剑相交·衣摆外翻）
  面板 4  [顶点]  镜2 · 近景 · 极限    @B（被压至柜台角·后仰）
  面板 5  [结果]  镜2 · 小全景 · 落定  @B 撞翻酒坛 · 道具瓶碎
  面板 6  [反应]  镜3 · 全景 · 接收    @C（门口·惊愕后退半步）
  面板 7  [出口]  镜3 · 中景 · 承接    @A 收剑侧立（左A右B·未越轴）   ← 见 §四 出口帧
```

**每格必带 5 项**（缺项＝该格没做完）：

| 项 | 内容 |
|---|---|
| **面板 ID** | `段{n}-P{k}`，连续编号，不跳号 |
| **动作相位** | 见 §三 七态之一 |
| **镜头信息** | 景别 + 机位角度（由文字分镜给出，故事板只搬运不新造） |
| **站位与视线** | 人物在本格的坐标 + 朝向 + 视线落点（由导演稿给出） |
| **资产引用** | 用到的人物/场景/道具对应的「图N」编号（**P4 投喂层据此写三族行内锚点 `@CHR-` / `@SCN-` / `@PRP-`——道具与场景并列在【场景资产】栏**；本层是"图N 编号"，投喂层是"`@` 锚点"，两套并存的换算见 `model-adapters.md` §5） |

## 三、action_phase 七态（动作拆格的唯一依据）

| 相位 | 含义 | 拆格建议 |
|---|---|---|
| `起始` START | 动作开始前的稳定状态（也是本段的**入口帧**） | 必出（1 格） |
| `过程` PROCESS | 动作进行中，可见的中间过程 | 动作复杂时 1~2 格 |
| `接触` CONTACT | 动作落到对象/物上（打击、抓握、推开、递交） | **有接触必出** |
| `顶点` APEX | 最大幅度 / 最强张力的一瞬 | **必出**（打戏高潮） |
| `结果` RESULT | 受力/位移的结果状态（摔倒、破碎、移位） | 有结果必出 |
| `反应` REACTION | 受影响对象的可见反应 | 有第三方必出 |
| `出口` EXIT | 段末稳定状态（也是**出口帧**，下段的入口） | 必出（1 格） |

**文戏最小集**：`起始 → 过程 → 反应 → 出口`（4 格）；
**打戏最小集**：`起始 → 过程 → 接触 → 顶点 → 结果 → 出口`（6 格起）。

---

## 四、出入口帧继承（跨段不穿帮的关键）

**铁律**：**本段的【出口】面板 = 下段的【起始】面板**（画面状态必须一致）。

- **入口帧**：本段第 1 格必须**继承上一段的出口**——人物位置、手位、道具状态、光影、轴线、姿态连续；
- **出口帧**必须写全六项：`人物 / 手位 / 道具状态 / 光影 / 轴线 / 未完成动作`；
- 段与段是**独立生成的剪辑关系**（见 `short-drama-director/references/asset-spatial-ledger.md` §三·6 跨段蒙太奇默认）：**跨段切、同段连**——跨段用蒙太奇直切时，出口帧只需写明两端画面；**同段内**才要求严格走位继承。

## 五、两版输出：CLEAN_GRID 与 TECHNICAL_ANNOTATED

| 版本 | 用途 | 内容 | 必出？ |
|---|---|---|---|
| **`CLEAN_GRID` 干净版** | **实际生图用**（这是"标准性的图"） | **无任何文字**：无面板序号、无对白框、无箭头、无技术标签、无水印；纯画面 + 留白分隔 | ✅ **必出** |
| **`TECHNICAL_ANNOTATED` 标注版** | **给团队看**（沟通用） | 可用**短英文标签**（`P3 CONTACT`）+ **图外中文批注**（图下留白区写导演说明）；**不依赖模型生成长文字** | 可选 |

**硬规则**：

1. **干净版严禁文字**——模型生成的"画面内文字"必然糊成伪文字，且会污染参考图；
2. **标注版不进投喂**——标注版只用于人工沟通，**不得作为视频生成的参考图**；
3. 两版**共用同一套面板结构**（格数与内容一致），只是标注层有无之别。

## 七、面板边界 ≠ 剪辑点（最容易被误读的一条）

**这是必须写进产物说明的一句话**：

> 故事板的面板表示**动作相位**，**不表示剪辑**。面板变多 ≠ 要多切镜；面板只有 4 格 ≠ 只能 4 镜。

对应关系由导演稿的**镜头策略模式**决定（权威在 `sd-qc-engine/references/editing-transition-gate.md` §一）：

| 镜头策略模式 | 故事板的面板边界意味着什么 |
|---|---|
| `TRUE_ONE_TAKE` | 所有面板**同属一个镜头**，面板之间**不得暗示反打/插入/切镜** |
| `SIMULATED_ONE_TAKE` | 只有导演批准的**隐藏缝**位置可以成为面板断点，其余同样不切 |
| `CUT_COVERAGE` | 面板断点**可**对应切点，但切点必须来自导演的 `cut_directives` / `allowed_cut_windows` |
| `HYBRID` | 不可切段按长镜头规则，其余按切镜规则 |

**禁令**：**不得用"多画一格面板"来暗示未获授权的反打、插入或切镜**——故事板是**执行稿**，不是**再创作**。

## 八、与投喂层的交接：按故事板生成视频

故事板图的**用途是驱动 P4 投喂**，交接方式有三条：

1. **面板 → 镜行**：故事板的每一格，对应投喂稿【时间轴分镜】里的镜行内容（动作相位 + 站位 + 视线），**逐格落进镜行**，**一格都不许漏**（漏格＝该动作相位在成片里不存在）；
2. **故事板图 → 参考素材**：`CLEAN_GRID` 故事板图**可作为参考图入册**（登记《资产图册》，编号 `图{STB}-{n}`），在投喂时按官方语法标注用途；
   - ⚠️ **参考图数量红线**：Seedance 2.5 参考素材上限 30 张、2.0 图 ≤9（见 `short-drama-director/references/model-adapters.md` §5）——故事板图**按段入册**，**不是每镜一张**，入册前先算总量；
   - ⚠️ **2.5 / 2.0 差异**：`first_frame`/`last_frame` **仅限 Seedance 2.5**；2.0 参考图**仅用于锁定形象**，不得当首尾帧用；
3. **出口帧 → 跨段接力**：故事板的出口帧，作为 D 锁段缝**画面锁**的依据（末帧截图优先；【接续状态】文字腿 2026-10-09 废止）（见 `short-drama-director/references/segment-splicing.md` §二 §三）。

## 九、入库与命名

- **编号**：`图{STB}-{段号}`（如 `图STB-4`），与角色/场景/道具图**并列进《资产图册》**，另立"故事板图"栏目；

## 十一、SHOT_TEXT 卡版式（分镜线稿卡 · 2026-10-09 增补）

> 形态样张：用户提供的实拍式分镜预演卡——**顶部俯视走位平面图（机位+轨迹+图例）+ 下方逐镜卡（线稿画面 + 摄影参数 + 台词逐句 + 摄影调度段）**。
> **定位**：给人看的**预演/沟通件**（导演自查、团队交接、甲方过目），是 §五 CLEAN_GRID（给生图）与 §六·2 标注版（图外批注）之外的**第三种形态**——**不进投喂、不作生图参考图**（线稿画风会污染视频模型的风格参考）。

### 11.1 三形态分工（防止做混）

| 形态 | 一格 = 什么 | 谁看 | 进投喂/入册？ |
|---|---|---|---|
| CLEAN_GRID 故事板图（§五） | 一个**动作相位** | 生图模型 | ✅ 图可用作参考素材 |
| 标注版（§五） | 动作相位 + 图外批注 | 团队 | ❌ |
| **★ SHOT_TEXT 卡（本节）** | **一整镜**（线稿 + 参数 + 台词 + 调度） | 人（预演） | ❌ |

### 11.2 两个部件

**部件① 俯视走位平面图（每段一张，置顶）**：

| 要素 | 要求 | 数据来源（搬运，禁新造） |
|---|---|---|
| 底图 | 该场景的**鸟瞰线稿**（铅笔稿质感，同场景资产 图{SCN} 的空间结构） | 导演稿平面图（`blocking-direction.md`）——**同一坐标系、同一方位称谓、逐字同源** |
| 摄像机位 | 按镜号摆位（机位图标 + 镜号），移动镜画轨迹箭头 | 文字分镜的机位/运镜列 |
| 角色走位 | **逐角色一色**的虚线箭头（起点→终点） | 导演稿走位路径 |
| 图例框 | **必须出**：人物名→颜色 / 摄像机 / 摄像机移动 / 角色走位 四类 | — |

**部件② 逐镜卡（每镜一张，纵列）**——五要素：

1. **线稿画面**：该镜**起始构图**的铅笔线稿（人物可留面部细节简化，构图/站位/视线必须与分镜表一致）；
2. **参数行**：景别 · 角度 · 运镜｜镜头焦段（由 A 锁/导演稿搬运；2.0 无机型绑定则写「等效焦段」）｜**机长**（时码，**逐字取自投喂稿镜行**）；
3. **台词逐句**：`角色名：台词`——**从上游剧本搬运，零改动零删减**（台词完整性对照的基线红线）；
4. **摄影调度段**：谁从哪走到哪、视线落点、动作细节、焦点变化——从导演稿与分镜表搬运；
5. **卡 ID**：`段{n}-S{k}`（注意与相位面板 `段{n}-P{k}` 区分：S=镜，P=相位）。

### 11.3 文字怎么进图（工程口径，二选一）

1. **主推 · 图模分工**（同 §五「中文批注图外叠加」纪律）：模型只生成**无文字线稿**（部件①底图 + 部件②画面格），参数/台词/调度/图例由**排版工具图外叠加**——零伪文字风险；
2. **备选 · 整卡直出**：接受模型渲染中文的错字风险（适合快预演，不适合交付）。

### 11.4 出图提示词模板（图模分工 · 主推）

**部件① 俯视图**：

```text
生成一张 16:9 横版铅稿线稿俯视图，画的是 {场景名}（与 图{SCN} 空间结构完全一致），铅笔线稿质感、无上色、无渲染、无任何文字。
图中以小矩形图标标出 {N} 个摄影机位，旁标镜号①~{N}；{移动镜}的机位画黄色虚线箭头表示移动轨迹。
角色走位：{@A角色名}画{色A}色虚线箭头（从{起点坐标}到{终点坐标}），{@B角色名}画{色B}色虚线箭头（{路径}）。
禁止：上色、渲染、文字、水印、多余人物。
```
> 图例框由排版叠加（图模分工）；走位坐标称谓**逐字取自导演稿平面图**。

**部件② 逐镜画面格**：

```text
生成一张 16:9 横版铅稿线稿分镜画面，铅笔线稿质感、无上色、无任何文字。
{景别 · 焦段 · 角度}。{场景一句话，与 图{SCN} 一致}。@A（{坐标·朝向·姿态}）{本镜起始动作}；@B（{位置}）。
构图要求：{视线落点 / 光位方向（只标明暗素描关系，不上色）}。
禁止：上色、文字、字幕、水印、未点名人物。
```

### 11.5 硬规则

1. **搬运不新造**（同 §一规则4）：机位、走位、台词、时码任何一处与导演稿/分镜表/投喂稿矛盾 = 废卡重出；
2. **不进投喂、不入《资产图册》**：SHOT_TEXT 卡登记在项目主文件的「预演件」栏即可，**不占素材槽**；
3. **台词零改动**：逐句照抄上游剧本，一个字都不能动；
4. **时码逐字同源**：机长列 = 投喂稿【时间轴分镜】镜行时码；
5. **不必全剧都出**：与 §九同口径——跨 2 镜以上叙事段/打戏段/重场戏建议出，单镜过场段可跳过。

## 十二、分镜变更后的「故事板重出」纪律（★ 2026-10-20 实战回写）

> **由来**：一集 6 段 24 镜，分镜在四轮返工中改了台词与镜序，故事板**只被人手改了其中一句**就交付了。用户翻完发现：段1 第 3 格还停在「窗外冰封大远景」（分镜早已改成「抬眼望监控屏」），第 6 段第 3 格还写着「双唇抿紧」（那一镜她正在说台词）。用户原话：「你故事版改没改？你故事版里面不是还之前老的东西吗？」

### 12.1 铁律：分镜动过，故事板**整份重出**，不许补丁式改字

| 上游改动 | 故事板必须做什么 |
|---|---|
| 只改台词内容（镜头不变） | 改该格「口型状态」，**其余不动** |
| 改镜序 / 换镜 / 增删镜 | **整份重出**——相位标号（起始/过程/反应/出口）与镜号绑定，牵一发动全身 |
| 改景别 / 角度 / 运镜 | **整份重出**——格头是从分镜搬运的，搬运不许手抄 |
| 改站位 / 视线 / 轴线 | 重出，并复核出口帧六项 |

**禁止**：目检式比对。人眼看不出「大远景 vs 中景·变焦」这种差异，必须跑脚本（12.3）。

### 12.2 格序 = 镜序（本包默认口径）

- **1 格 1 镜**：4 镜段 → 4 格，第 N 格必须取第 N 镜的关键帧。**不许按「起始/过程/反应/出口」重新分配镜头**（那会让格与镜错位，出图后无法回查分镜）。
- 相位名**并列**写在格头：`面板 3（反应 · 镜3）`——**相位是标签，镜号是身份**。
- 段内镜数与格数不等时（3 镜或 6 镜），按 §一规则5 的下限补齐/拆细，并在格头写明「镜X 的 A/B 两瞬」。

### 12.3 逐镜检查（新增 · 出图前必跑）

```python
# 比对：分镜镜行的「景别 · 视角 · 运镜」 vs 故事板格头，逐条相等
import io, re
md = io.open("<交付稿>.md", encoding="utf-8").read()
sb = io.open("<故事板文件>.md", encoding="utf-8").read()
shots  = [l.split("]",1)[1].strip().split("。")[0]
          for l in md.split("\n") if l.startswith("00:") and "[镜头" in l]
panels = re.findall(r"面板 \d（[^）]*· 镜\d）：([^。]*)。", sb)
assert len(shots) == len(panels), (len(shots), len(panels))
bad = [(i+1,a,b) for i,(a,b) in enumerate(zip(shots,panels)) if a != b]
print("不一致：", len(bad)); [print(x) for x in bad]
```

**合格线**：`不一致 = 0`，且 `镜数 == 格数`。

### 12.4 口型纪律（对白密集型项目必加）

台词密度高的集（≥4 字/秒），故事板必须逐格标注口型状态，否则模型会画一排「安静凝视镜头」的人，用户拿到图分不清谁在说话。

| 该格情况 | 格内必须写 |
|---|---|
| 这一镜有人开口说话 | `嘴唇张着在说话`（画外对白则写 `嘴唇闭合`） |
| 这一镜无人说话 | `嘴唇闭合` |
| 该格是空镜/纯物特写 | `本面板为纯…特写，画面内无人物` |

> **图内仍零文字**：口型状态是**提示词侧**的说明，不是要渲染到图上的标签。图上依旧不出现任何文字。

### 12.5 与主稿交付清单的联动

主稿 `## P3 图形化交付清单` 的「四格覆盖」列，须与故事板**同步改写为「镜N 内容」的格式**（例：`镜1 门板被砸凹（空镜）/ 镜2 后拉进客厅…`）。该表是人工目检的唯一入口——表错了，后面所有核对都是错的。
