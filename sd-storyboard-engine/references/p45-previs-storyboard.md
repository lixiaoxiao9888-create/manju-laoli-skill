## 四、叙述体怎么写（四条铁律）

1. **每格回答六问**：谁在哪 / 朝哪 / 看哪 / 做什么 / 镜头在哪 / 光从哪来。缺一项，AI 就要自己编。
2. **⛔ 禁写本包术语**：不写「九宫格 / CLEAN_GRID / SHOT_TEXT / action_phase / D 锁 / R1 / 图STB」。这张图是给图像模型和人看的，术语只会让它画出一堆标签（"九宫格"被认成场景图的坑已复发多次）。
3. **抽象词翻译成可见物**：「压迫感」→「A 站在门框内侧，影子压在 B 脸上」；「犹豫」→「手停在半空，指尖离门把三厘米，视线落在门把上」。
4. **格数 = 该段镜数，不设固定格数**（2026-10-22 二次修正）：**4 格、6 格、9 格、12 格都可以，由段落分镜的镜数决定**——一镜一格，投喂稿这一段有几镜就出几格。⛔ 禁止把格数写死成 3~4 格 / 3~6 格，也禁止为"四宫格好看"硬凑或硬砍，更禁止写"同上"占位。
   > **版式随格数自动选**：4 格 → 2×2 ／ 6 格 → 2×3 ／ 9 格 → 3×3 ／ 12 格 → 3×4 ／ 5 格 → 单行 5 格或 2+3 ／ 8 格 → 2×4。版式是**排版结果**，不是格数的来源。
   > **确实要合并时才合并**：一格合并多镜写 `〔镜K+M 景别〕`，并在该段前写一句合并理由（如"镜7、8 是同一次动作的连续两拍，合并为一格"）。
5. **★每格必须标投喂稿镜号**（2026-10-22 新增 · 治「故事板与投喂稿各写各的」）：格式 `第N格：〔镜K 景别〕…`，K 就是投喂稿该段的镜头号，景别必须与该镜一致。**一格合并多镜时写 `〔镜K+M 景别〕`**。
   > **病根（实测事故）**：旧口径文戏上限 **4 格**，而文戏段常是 **6 镜**——6 塞不进 4，规则又不要求标镜号，于是"4 格故事板"和"6 镜投喂稿"各自成立：段落数一样、景别对不上（故事板写近景、投喂稿是特写）、主体也不同（故事板画苏念写卷子，投喂稿那一镜的主体其实是沈甜在爆料）。**读者拿故事板去验收，验的是另一部片。**
   > **现在**：格数**优先等于该段镜数**（6 镜就 6 格，2×3 排列）；确实要合并时才用 `镜K+M`，并在段首写清合并理由。机检 `P459`（缺镜号）+ `P45A`（景别/镜号/覆盖交叉核验，需 `--feed`）拦。

**提示词骨架**：
```
画一张分镜故事板，{N} 格，{排列方式}，{画幅}，{画风}，画面中没有任何文字、数字、水印或边框标注。
统一人物设定：{角色名}：{年龄/发型/服装/体型，逐项写死}。
场景：{一句话写清空间结构与光源方向}。
第 1 格：{六问填满}。
第 2 格：……
第 N 格：……
要求：各格人物服装与发型完全一致；动作逐格递进、不可跳跃；相邻格空间关系连续，不越轴。
```

## 五、看图之后怎么改（改的是稿，不是图）

用户看完预演图，会指着某格说"这里不对"。这时**不要重画图**，回到 P4 投喂稿定点改：

**三条铁律**：
1. **唯一 ID 寻址**：`段{n}-格{k}` → `镜{nn}` → `图{类型}-{编号}`。⛔ 禁"把那段改一下""整体再优化下"——无 ID 必然整段重写，**改一处坏三处**。
2. **只改指定项**，其余逐字不变，附《改动回执》：
   ```
   【改动回执 · 段{n}】
   改动：镜{nn}【时间轴分镜】第 3 句 —— 「A 站在门内」→「A 站在门框内侧，右肩贴框」
   未动：本段其余 7 条镜行、全部【核心人物】【场景资产】【强制禁止项】逐字未变
   ```
3. **改法分三级**：L1 改描述（默认，最便宜）→ L2 用户重新出图（提示词不动）→ L3 回 P3 改分镜（**须先告知用户**）。

> **经验建议（非官方能力断言，比例未经统计验证）**：优先检查 L1 描述歧义；若空间或调度本身不成立，应回 P3 修正，不能保证仅改一句即可解决。

## 六、盲区（写进附件开头，别让人误以为验过了就万事大吉）

**预演图能看**：构图、景别、机位、站位越轴、人物一致性、道具位置、光源方向、叙事顺序。
**预演图看不出**：跨帧连贯、运镜轨迹、转身/出手的高速瞬间、接触点物理、多主体互动。

→ 打戏与长镜头，预演图过了也照样可能抽卡。补法是给该段预留抽卡预算（≤2 次），或改用 `storyboard-sheet-template.md` §三 七态拆格 / 首尾帧对（仅 Seedance 2.5）。**⛔ 禁止承诺"看完预演图就一次成"。**

1. **不替代 P3 故事板图提示词**（那份进投喂体系，这份不进）；

## 八、机检门（★ 2026-10-21 合并保留 · FAIL 清零才交付）

> **背景**：P1 只把 P4.5 接进「契约层 CT5-P45」（命中不附即 FAIL），**没有结构机检**——少段、少格、漏六问、术语混入、写「同上」仍能过。本仓保留专用检查脚本。

**命令**：

```bash
python sd-storyboard-engine/scripts/check_p45.py <项目名>-预演故事板.md --segments <段数>
```

- `--segments N`：与投喂稿段数对齐；缺段且无 ⛔ 豁免说明 → FAIL；
- `--m2`：仅形态 M2 时使用，放开「已核验 / 看图」类表述；
- `--self-test`：跑 6 个内置用例自检脚本本身。

**11 条规则**：P450 命名 · P451 段结构四件套 · P452 格数/格号 · P453 六问 · P454 术语污染 · P455 占位引用 · P456 图片声明 · P457 段覆盖 · P458 交付清单行 · **P459 格内镜号** · **P45A 与投喂稿交叉核验（景别/镜号/覆盖）**。

**门禁口径**：ERROR 清零才算 P4.5 完成；WARN 须逐条处理或书面说明。本检查只验 P4.5 附件，**不替代** P5 的投喂稿机检。
