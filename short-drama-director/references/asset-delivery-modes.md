## 〇、 一句话定位（先读这段）

**本包默认交付的是"提示词 + 接线说明书"，不是"图"。** 图由用户在外部平台自行生成并持有，**本包不持有图、不要求交回图、不以"没有图"为由阻断任何阶段**。

> **病灶复盘（2026-10-08 用户实测反馈）**：本包融合自"工作室制"生产包（原包上游设有出图岗），因此继承了「资产图册 = 唯一事实来源」与「无图不进分镜」两条结论，**却没有继承产生它们的出图工序**。同时本包自身有「默认只出提示词，不调出图工具」铁律。三条规则并存 → 执行者要么卡死，要么假装通过。**本文件就是为消除这个矛盾而设。**

**真实工作流（本包必须匹配的形态）**：

```text
本包出提示词 → 用户拿去即梦/Seedance/豆包等平台自己跑图 → 图留在用户平台侧 → 本包只负责让提示词里的图号"对得上"
```

即：**图这个实体，从不进入本包的上下文。**

## 一、 三种存在形态（M0 / M1 / M2）

| 形态 | 名称 | 图在哪 | 提示词写法 | 一致性靠什么 | 门禁可核验性 |
|---|---|---|---|---|---|
| **M0** | 纯提示词 | **哪儿都没有** | **不出现任何图号 / 参考图槽位** | 全量文字锁（§三） | 不可核验图像，只核验文字 |
| **M1** | **编号占位（默认）** | 在**用户平台侧**；本包只有编号与用途 | 出现 `图N` 槽位 + **必附《素材接线单》** | 文字锁（主）+ 编号一致（辅） | 可核验"编号是否对得上"，不可核验图像 |
| **M2** | 已入库 | 用户**主动交回**，登记《资产图册》 | 出现 `图N` 槽位，可标注"已登记" | 文字锁 + 编号 + **图像级核验** | **可做图像级核验** |

### 1.1 默认形态 = M1（用户裁定 2026-10-08）

- **不写死默认值，执行者就会各写各的** —— 因此默认形态**明确定为 M1**；
- 用户明确表示"我没有图 / 不要图号 / 只要提示词" → **降级 M0**；
- 用户主动把图交回（贴图、给文件路径、说"图在这/已经出好了"）→ **升级 M2**；
- **形态切换必须显式**：禁止静默切换（M0 交付里夹带图号、M1 交付里漏掉接线单，都属于**形态违约**）。

### 1.2 形态声明纪律（每次交付首行必写）

交付稿首行必须声明本次形态，让用户知道一致性靠什么保障：

```text
> 素材形态：M1（编号占位 · 图号 3 个 · 接线单见文末）
> 素材形态：M0（纯提示词 · 未使用参考图 · 一致性靠文字锁）
> 素材形态：M2（已入库 · 图3/图5 已登记 · 可图像级核验）
```

**未声明的稿子视为形态未定，机检告警，不得交付。**

## 二、 门禁分级生效（覆盖 `asset-first-pipeline.md` 第三章）

> **原则**：门禁不是废除，而是**按形态改判**。同一道门在不同形态下检查不同的东西。

| 门禁 | 原规则 | M0 纯提示词 | M1 编号占位（默认） | M2 已入库 |
|---|---|---|---|---|
| **门禁 1** P2b→P2c | 资产清单未确认禁出图 | **改判**：角色/场景**文字档案**确认（可选，不阻塞） | **原样**：清单 = 编号 + 用途 + 外观要素 | **原样** |
| **门禁 2** P2c→P2d | 分批资产图未锁定禁进分镜 | **不适用**（本包不出图，也无可锁定对象） | **不适用**（图由用户在平台产出，不由本包产出） | **原样** |
| **门禁 3** P3 | `@锚点` 无对应已锁定资产图 → 阻断 | **改判**：锚点指向的**文字档案**是否存在 | **改判**：图号是否已在**《素材接线单》/素材映射表**登记 | **原样** |
| **门禁 4** P4 | 投喂引用未锁定资产 → 阻断 | **不适用**（无图号可引） | **改判**：镜行图号槽位与接线单**逐条对应** | **原样** |
| **门禁 5** P5 | 画幅/脸型/服装与资产图不一致 → P0 阻断 | **改判**：与**文字档案**一致（发/服装/体态/年龄感/标志物逐项可比） | **改判**：同 M0 + 编号一致性 | **原样**（可图像级核验） |
| **门禁 6** P5 修改类 | 未跑三步复验 → 阻断 | 原样 | 原样 | 原样 |

**门禁 6 不受形态影响**——它与素材无关，始终全量适用。

## 三、 文字锁（Text-Lock）：M0 / M1 下的一致性保障路径

> 没有图，跨镜/跨段/跨集一致性依然要有保障。答案是**文字锁**——把一致性锚在**可复述的文字**上，而不是锚在**本包看不见的图**上。

| # | 铁律 | 理由 | 权威文件 |
|---|---|---|---|
| 1 | **外观档案复述块（核心）**：某角色在某段首次出现时，**必须完整复述外观要素**（发/服装/体态/年龄感/标志物），**禁止写"同上 / 同前 / 照旧"** | 模型**每段零记忆**——"同上"等于没写；这是"没有参考图时一致性下降"的唯一真实病根 | 本条（`asset-spatial-ledger.md` §二 提供要素清单） |
| 2 | **编号只承担接线职责**：M1 下 `图N` 只负责"告诉用户该挂哪张"，**不得把一致性全部押在图号上**——复述块照样要写 | 图号可能挂错/未挂/被平台忽略，复述块是唯一不依赖用户操作的保险 | 本条 |
| 3 | **场景锁**：坐标系 + `SET_STATE` 状态变体，跨集复用**一字不改** | 场景一致性靠参数化描述，不靠图 | `asset-spatial-ledger.md` §四 |
| 4 | **摆位锁**：人物账连续 · 摆位必入画 | 跨段穿帮的第一来源是"人凭空消失" | 法则 20 / `model-adapters.md` §5.0.1 |
| 5 | **段缝锁**：末态继承 + 尾帧锚定法 | 段缝一致性靠"上一段真实末帧"，不靠重出图 | `segment-splicing.md` |
| 6 | **命名锁**：同一角色全篇**同一名字**，禁"青年男子 / 黑衣人 / 他"混用指代同一人 | 名字是模型唯一可靠的跨镜指代手段 | 法则 20 / C20b |

> ⚠️ **本节的定位**：文字锁是 **M0/M1 的替代路径**，不是"降级方案"。执行者不得因为"没图"就放宽 §三 任何一条。

## 四、 素材接线单（Wiring Sheet）

> **这是「图片入库」的正向替代物**：用户不需要把图交回来，只需要按单子把图挂上。

### 4.1 模板

```markdown
## 素材接线单

> 用法：本单是你**在平台侧挂图**的说明书。提示词里出现的每一个图号，本单都有一行。
> 你只需在平台的参考图/素材区，按「你该挂哪张」把图挂上——**不需要把图发回给我**。

| 图号 | 类型 | 用途（只控制什么） | 你该挂哪张 | 不控制什么 |
|---|---|---|---|---|
| 图1 | 角色参考 | 锁定 林越 的脸型/发型/服装/体态 | 你出的「林越」已确认的角色基准图 | 姿态、表情、场景、光线 |
| 图2 | 场景参考 | 锁定 客栈大堂 空间结构/固定家具/光源方向 | 「客栈大堂」场景母版图 | 人物、剧情动作、第 0 秒构图 |
| 图3 | 道具参考 | 锁定 玉佩 外观/材质/颜色 | 「玉佩」道具图 | 手持姿态、光效、镜面反射 |
| 视频1 | 动作参考 | 只参考 出刀节奏与运镜 | 上一段成片 | 角色外观、场景、画风 |

**未挂图会怎样**：平台上未挂 `图1` 时，模型仍按提示词中的**外观复述块**渲染——一致性下降，但**不会报错、不阻断交付**。
**数量上限（按模型分档 · 2026-10-12 修订）**：**MiniMax H3** 图 ≤9 张 / 视频 ≤3 / 音频 ≤3 / 总素材 ≤12；**Seedance 2.5** 图 ≤30 / 视频 ≤10 / 音频 ≤10 / 总数 ≤50；**Seedance 2.0** 单图绑定（1 张，仅锁形象）。⚠️ 9 张是 **H3** 的上限，**不得套到 Seedance 2.5**（2.5 官方支持 30 图，权威见 `model-adapters.md` §5 / 总控 `SKILL.md` §二）。
**挂错比不挂更糟**：图号与用途必须一致——`图2`（场景）被当成角色图挂上，会直接污染形象。
```

### 4.1.1 参考图六类分工

挂图时按**六类**归位，**每张图必须写明用途（只控制什么）**——编号以实际提供的图片为准，一图一职：

| 类别 | 控制范围 | 不控制 |
|---|---|---|
| **人物参考** | 脸型 / 发型 / 体态 / 五官 | 姿态、表情、景别 |
| **道具参考** | 外观 / 材质 / 颜色 | 手持方式、光效 |
| **场景参考** | 建筑结构 / 固定陈设 / 光源方向 | 人物、剧情动作 |
| **环境参考** | 天气 / 时段 / 氛围基调（雾·雨·晨昏） | 具体建筑与陈设 |
| **服装物料** | 服装款式 / 面料质感 / 配饰细节 | 人物长相与体态 |
| **站位参考** | 构图 / 机位 / 人物相对位置与朝向 | 人物外观、场景样貌 |

> 与既有硬约束的关系：六类分工是硬约束 3「只控制什么 / 不控制什么」的**分类速查版**，冲突时以接线单逐行写明为准；`动作参考`（视频类）不在六类内，沿用上表原行。

### 4.2 硬约束

1. **图号只能有两个来源**：① 用户提供；② 本单在本次交付中**显式定义**。**禁止凭空写图号**（对齐 `sd-feed-engine/references/asset-mapping-and-rules.md` 红线 1）。
2. **接线单与提示词图号必须双向一致**：提示词里出现的每个图号，接线单必须有行；接线单里的行，提示词必须至少引用一次（未引用的行标"本次未使用"）。
3. **每个图号必须写明"只控制什么 / 不控制什么"**——这是防"一张图被当四张用"的关键（对齐红线 9）。
4. **M1 交付必附**：形态为 M1 而未附接线单 = 形态违约，机检告警。
5. 接线单**不写内部 ID**（`@CHR-` / `asset-xxx` / `CH001`）——用户看不懂，且违反红线 11。
   > ⚠️ **历史存量说明（2026-10-12 审计补注）**：本包 12 个文件（含 `model-adapters.md` / `seedance-render-engine.md` / `h3-adapter.md` / `sd-real-engine/references/storyboard-example.md` 等规范与官方示例）的示范稿长期写成 `@CHR-老周` / `@SCN-地下拳房` **编号式**，与本条红线自相矛盾。处理口径：
   > - **新稿一律写 `@人名` / `@场景名` / `@道具名`**（`@周慕` / `@SCN-雨夜后巷` 中的 `SCN` 属场景类型提示可保留，`CHR-` 不得用；**关键道具写 `@PRP-道具名`，与 `@SCN-` 并列落在【场景资产】栏**——2026-10-13 新补，见 `model-adapters.md` §5「道具锚定纪律」）；
   > - 机检 `ZW_PERSON_RE` 已做**前缀剥除兼容**（`@CHR-老周` 与 `@老周` 等价解析），存量示例不会误报；
   > - 读旧示例时请把 `@CHR-xxx` 按 `@xxx` 理解，**不要照抄前缀**。

### 4.3 M2（已入库）时的差异

用户交回图后：接线单升级为《资产图册》的**素材引用表**（`sd-qc-engine/references/continuity-ledger.md` §资产引用表），增加 `asset_id / 版本 / 生产状态 / 参考图路径` 字段，**此时门禁 5 才可做图像级核验**。

### 4.4 出图提示词配套纪律（M1 交付完整性 · 2026-10-09 用户实测退回后增补）

> **病灶（2026-10-09 用户实测）**：某次 M1 交付只出了《素材接线单》，**漏掉了「你该挂哪张」列所指向的全部出图提示词**——角色提示词、场景九宫格、道具图全部缺失，只剩一份自创的旧「三视图 / 九宫格 · 无文字无标注」瘦身版（与权威模板冲突）。用户拿到接线单后**无从生图**：接线单是「挂图说明书」，出图提示词才是「图的来源」，两者缺一不可。

**铁律：M1 交付物 = 《素材接线单》 + 全套 P2.5 出图提示词，缺任一类 = 交付不全。** 接线单「你该挂哪张」列引用的每一类图，都必须有对应的出图提示词段落，且**必须走权威模板、禁止自创瘦身版**：

| 接线单行类型 | 必配出图提示词 | 权威模板 |
|---|---|---|
| 人物 | 角色基准独立文生图提示词，按 `asset-spatial-ledger.md` 四字段（画幅/排版结构/服装与身体材质/面部特写）编写；五官10项与服装6项写入描述。亲缘推导、声纹图和音色标签均非必需交付项 | `references/asset-spatial-ledger.md` + `references/character-extraction.md` |
| 场景 | **两类都要出、互不替代，并按下述顺序**：① **场景母版**（必出 · 第一张 · 16:9 · 无人）；② **九宫格**（必出 · 第二张 · 模式A/B，含标注降级条款）；③（**⛔ 仅复杂场景按需**）文戏机位调度版（CAM1~4）/ 武戏战斗站位版（一律 16:9） | `sd-asset-engine/references/scene-grid-template.md` ＋ 总控 `asset-spatial-ledger.md` §四 |
| 道具 | 道具设定图（**全图共 4 格**：① 正面视图 / ② 45° 侧视图 / ③ 顶部俯视图 / ④ 关键细节特写；**不设独立大主图、同一视角不得重复、不出第 5 格** + 尺寸比例 + 状态轨迹；保留「左上角标注：〔道具名〕」） | `sd-asset-engine/references/prop-template.md` |
| 段缝参考图（重绘路径） | 「首镜起手态」重绘提示词（由段首镜行 + 角色/场景外观要素组合） | `segment-splicing.md` §二 |

**逐行自检（交付前必做）**：把接线单「你该挂哪张」列逐行读一遍——每一行都必须能在交付包里找到对应的出图提示词段落；找不到即补齐后再交付。**同场景跨集/跨段延续时**（如同一咖啡馆的夜与晨），延续版必须按 `scene-grid-template.md` §四「锁参考图开关＝开」出延续拍摄声明，不得另起炉灶重写场景。

## 六、 与「资产依赖分级 A0~A3」的关系（两条正交轴）

- **A 轴（任务复杂度）**：`asset-first-pipeline.md` §〇 第 6 条 —— 决定**要不要走资产链**；
- **M 轴（图在不在手里）**：本文件 —— 决定**门禁怎么判、一致性靠什么**。

两者**正交**，组合合法：

| | 建议形态 | 说明 |
|---|---|---|
| **A0** 纯文字/单镜 | M0 | 无跨镜一致性要求，图号反而增加噪声 |
| **A1** 单角色单镜 | M0 或 M1 | 有图更稳，无图可用文字锁 |
| **A2** 跨镜角色/场景一致性 | **M1**（默认） | 图号 + 接线单收益最大 |
| **A3** 多人/多场景/连续剧集 | **M1** 或 **M2** | 建议 M2：连续剧集值得建图册 |

> **M 轴由用户的**实际条件**决定，不强制**：用户手上没图就 M0，不要为了"合规"逼用户出图。A 轴判不清按 A3 处理，但 M 轴判不清**按用户实际条件处理**（不是按最高档）。

## 八、 机检与自检钩子

- **落点**：`sd-feed-engine/scripts/gate_check.py` **闸门 6「编号一致性」**（**不新开 C 系编号**——素材形态属投喂交付契约，归投喂层闸门，`validate_prompt.py` 的 C1~C26 体系保持不动）。
- **闸门 6 判定**：
  - `--mode M0` 而稿中出现图号 → **FAIL**（形态声明与实际不符）；
  - `--mode M1` 而稿中出现图号但**无《素材接线单》段** → **WARN**；
  - 稿中图号 ∉ 接线单图号集合 → **FAIL**；
  - 图号不超出 `--assets` 声明范围 → 原样保留。
- **包级自检**：`scripts/check_package.py` 设「素材形态权威完整性」域，校验本文件存在且含三形态定义、门禁分级表、接线单模板、三不一要。
