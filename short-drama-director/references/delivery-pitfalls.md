# 交付翻车清单（实战回写 · 2026-10-19）

> 来源：《兽瞳》第01集全流程实跑（国内剧 · 原创 · Seedance 2.5 · 9:16 · 90 秒/集 · 东方神话3D · M1）从立项到交付的完整踩坑记录。
> 定位：本文件**不重新定义任何规则**，只把已发生过的翻车固化成「症状 → 病根 → 硬规则 → 检查手段」四段式，供**交付前逐条自查**。
> 用法：P2 资产出稿、P4 投喂封装、交付打包前，各过一遍对应章节。规则本体仍以各权威文件为准。

---

## 一、交付形态：件数、分层、命名

### 1.1 交付件数爆炸（最严重 · 一次性产出 15 个文件 / 10 个目录）

**症状**：用户只要一份东西，交付出一整个目录树——IP圣经、故事圣经、分集规划、资产包、导演稿、情绪锚点表、分镜稿、投喂稿、质检报告、连续性台账各占一个文件。

**病根**：**把「引擎工作文件」当成「交付物」**。本包是多引擎流水线（剧本 / 资产 / 分镜 / 投喂 / 质检），每个引擎按自己的规范产出一个中间件——那是**引擎之间的协作接口**，不是给用户的东西。逐个落盘并交付 = 把工厂流水线当成品卖。

**硬规则（件数上限 3）**：

| 件 | 内容 | 何时出 |
|---|---|---|
| **① 主文档**（md 或离线看板，二选一按 C 锁） | 全部对外内容合一 | 必出 |
| **② 看板 HTML** | 由主 md 编译，双击即开 | 仅 C 锁含看板时 |
| **③ P4.5 预演故事板** | 只出提示词、不出图 | 仅场景复杂 / 用户点名 |

- ⛔ **超过 3 件即视为交付层违规**。中间件一律并入主文档或留在内部档案，不单独交付。
- 合并顺序建议：总控 → IP → 故事圣经 → 分集规划 → 剧本 → 资产提示词 → 审核 → 制作全案 → 质检；合并后**内部交叉引用改成「第X部分」**，不再保留下游文件名引用（否则删掉中间件就断链）。

### 1.2 内部内容外泄（C 锁 = 只要 md 时的正文边界）

**症状**：用户要的是「拿去生图、生视频的东西」，交付稿里却是 IP 圣经、世界锚卡、人物锚卡、分集规划、圆桌审核、质检报告、情绪锚点表。

**病根**：把「说服自己写对了」的过程材料，当成「用户能用的东西」交出去。

**硬规则（正文只放两样）**：

- **md 正文 = 资产提示词 + 分镜提示词**。这两块是用户唯一真正要动手用的内容。
- 其余全部归**内部档案**：单独文件、文件名前缀 `_内部_`、**不放桌面**、不进交付包。
- 判据：交付稿里出现「世界锚卡 / 人物锚卡 / 分集规划 / 圆桌 / 质检 / 情绪锚点 / P0A / M1 / C27 / 六道闸门自检」这类内部术语 = 泄漏，改写或删除。
- 例外：**出看板时**才承载完整内容（看板是「给人看全貌」的形态），此时分层规则不适用。

### 1.3 英文命名与代号残留

**症状**：目录叫 `shoutong`、文件叫 `EP001_SCRIPT.md`、标题写 `EP001`。

**硬规则**：目录、文件名、正文标题**一律中文**；集数写「第01集」「第01-03集」（区间末尾不再补零写三位）。技术标识保留原文（Seedance 2.5 / 9:16 / M1 / 图号），改掉会与机检指纹对不上。

## 二、提示词自包含：五条铁律

**症状**：单条提示词复制到生图/生视频平台后不成立——「同规格」「见母版」「同图2」「降级条款同图2」「按第三部分」。

**病根**：写作时站在「整份文档」视角，用了跨条引用做压缩。**提示词的投喂单位是单条，不是整份文档。**

1. **禁跨条引用**：`同上 / 同规格 / 见母版 / 同图N / 同前 / 按上述 / 参见X / 见第X部分 / 降级条款同图N` 全部禁止。
2. **禁省略式占位**：写「②③④ 格同规格无脸全身」→ 必须把②③④每格内容逐条写死。
3. **每条自带上下文**：画幅、格数、无脸规则、负向词、图底细节条要求，**逐条重复写**，不靠上文继承。
4. **降级条款要完整**：不能写「降级条款同图2」，要写全「中文崩字 → 格内编号 1~9 + 图外对照表 + 重试上限 2 次 + 降级后仍保留 9 格」。
5. **图号 ↔ 提示词 ↔ 槽位自洽**：接线单里的「参考图 N」必须指向本册已存在的图号；改了图号要同步接线单与分镜里的槽位。

> 自检：`python scripts/check_asset_blocks.py <交付稿.md>`（规则 A1）

## 三、资产提示词：结构与格数

### 3.1 角色出成 5 格（最常见的废图）

**症状**：要 4 格，出图是 5 格，正面被画了两遍。

**病根**：提示词里**同时出现「立绘 / 全身完整入画」与「四格」**，或用了旧称「主图」。模型按「1 张主图 + 4 格」做加法。

**硬规则**：
- 一条提示词 = **一张 16:9 四格纯图板**，开头显式声明「**全图共 4 格，横向并排……不设独立大主图、不重复任何视角、不出现第 5 格**」。
- ⛔ **禁止「主图」二字**（正向用法）；要指代正面那张，写「正面格」。
- 三格全身必须**无脸但保留头**（不许砍头，否则头身比失真）、**头顶至鞋完整入画**。
- 负向词必须含：`fifth panel`、`extra panel`、`different face`（或 `second face`）、`text`、`watermark`。
- 图底细节条 = 声纹波形 + ≤8 词音色标签，**不计入格数**。

### 3.2 九宫格缺字段（出图后无法定位机位）

**症状**：九宫格出来了，但不知道哪格对应哪个机位；建筑还漂了。

**病根**：八字段只写了五个，缺 **【场景定位】【九宫格内容分配】【参考场景锁定模式】**。

**硬规则（八字段，缺一即不合规）**：
【场景定位】（含空间类型，决定摄影机矩阵取哪张表）→【场景画面描写】→【九宫格内容分配】（模式A 单场景多机位 / 模式B 多子区域）→【参考场景锁定模式】（A 档「仅允许摄影机移动」/ B 档「允许按子区域切换机位」，**按模式选档、不得混用**）→【摄影机矩阵】→【摄影机参数】→【光照曝光】→【标注要求】。
- 必须显式写「**全图共 9 格，不多不少**」。
- **机位名与空间类型必须匹配**（室内 / 室外独立建筑 / 自然场地三张表），禁硬凑。
- 标注降级条款写全：中文崩字 → 格内编号 1~9 + 图外对照表，**禁止无标注裸格交付**，重试 2 次仍失败也要保留 9 格。

### 3.3 道具字段名不统一

**症状**：道具图和角色图混淆，或四格写成了「正面/45°侧视/顶部俯视」，模型不知道出设定板。

**硬规则**：
- 开头必须写「整板固定 16:9 横版的**道具设定图**（单张，不拆图）」。
- 四格字段名用模板原名：**正面视图 / 45° 侧视图 / 顶部俯视图 / 关键细节特写**。
- 必须禁手持、禁人（`禁止人物、人手、肢体、剪影`），必须有尺寸参照物。
- 左（或右）上角标注道具名属允许文字，其余文字禁止。

> 自检：`python scripts/check_asset_blocks.py <交付稿.md>`（规则 A2~A7）

## 四、分镜与投喂：容易被人工目检漏掉的红线

| 症状 | 病根 | 硬规则 | 判据 |
|---|---|---|---|
| 段内几乎没有人物特写 | 全写中景/全景铺信息 | **段内人物特写占比 ≥25%** | C15 |
| 一个镜头 7~9 秒 | 拉长镜凑满剧本标注时长 | 单镜按内容倒推，**≤6s**（一句≤40 字动作行）；总时长允许短 25% | C10 |
| 相邻两镜机位描述完全一样 | 拆镜时复制未改 | 同段内**机位表述不得重复**（改越肩/反打/大特写） | C15/C10 |
| 画面段缺背景与光线 | 把「背景/光线」写在「台词：」之后 | **背景元素 + 光线方向必须写在「台词：」之前**（画面段内） | C32 |
| 运镜词报错 | 用了不在词表的词（如「快摇」） | 用词表内词：**横摇 / 平摇 / 摇镜 / 推 / 拉 / 跟 / 升降 / 固定** | C18g |
| 群像人数被判错 | 写「画面中没有其他人」 | 用**肯定式人数句**：「殿内共五人：A、B、C 与两名弟子」 | C26/C17 |
| 镜号跳号/重号 | 增删镜后没重编号 | **每段镜号从镜1 起算**；增删后整段重编，分镜稿与投喂稿同步 | 人工 |
| 同段首尾镜机位撞车 | 段缝只用「换机位」未换景别 | 段缝首镜**换景别 + 换机位**（如末镜特写 → 首镜大远景） | D 锁 |

> 判据编号对应 `scripts/validate_prompt.py`；`--by-segment` 见下节。

## 五、机检口径：多段稿必须分单元跑

**症状**：一段 30 秒的文戏稿，机检报「打戏位移不足 / 贴身对招占比低（C21/C22）」，看了半天稿子里根本没有打戏。

**病根**：**整份文档送检**。90 秒 = 3×30 秒的稿子被当成「一段 90 秒 / 17 镜」解析，镜密度与动作密度双双超标，被判成打戏档；同时按段口径的 C10 单镜时长、C15 特写占比也跟着失真。

**硬规则**：
- **凡一稿含 ≥2 段，一律加 `--by-segment`**：
  ```
  python scripts/validate_prompt.py <交付稿.md> --model 2.5 --by-segment
  ```
- 该模式按「段N/M」标题切段，逐段独立跑判据，输出带 `[段N]` 前缀，末尾给「段数3（分单元校验）」。
- 整份模式仍保留用途：**资产契约（C31/CT2）与结构指纹按全文核销**。
- 报告里要写清用哪种口径出的结论；**不许拿整份模式的 C21/C22 去改本没有打戏的段**。

## 六、改动同步纪律

**症状**：交付稿修好了，内部档案还是旧版；下次复用拿到的是旧稿。

**硬规则**：
- **单一真相源**：交付稿是唯一对外真相；内部档案里同一段落必须**同步为同一版本**（改完立刻回写，别等）。
- 改图号 / 改镜号 / 拆镜 / 并镜，一次改三处：提示词、接线单、分镜稿（+ 投喂稿镜行）。
- 每轮修改记一条「改了什么 + 为什么」，写进内部档案附录（规范复核记录），便于下集复用。

### 6.1 区间替换吞节（2026-10-20 实战 · 一次性删掉整节 P3 清单）

**症状**：用「从 A 段落开头，一直替换到下一个标题 B」的方式改稿，**B 前面夹着的小节被一起吞掉**，交付后人工翻不到、机检也不报。

**实例**：改段6 时按「段6 起点 → `# 附录`」做区间替换，把中间的 `## P3 图形化交付清单`（含故事板格数表 + 剧情分镜格表）整节删了。机检 `validate_prompt.py` 只按【画幅风格】切段跑判据，**不会发现少了一节**；`check_asset_blocks.py` 也不管。发现时已是第三轮交付。

**硬规则**：

1. **区间替换只允许「到下一个同级或更高级标题」**——用 `^## ` / `^# ` 正则定位，不要用「某个字符串」当右边界。
2. **替换前后各数一次节数**：`grep -c "^## " <file>` 与 `grep -c "^### " <file>`，数目变了必须解释。
3. 替换后**必跑一次结构清单**：`grep -n "^#\{1,3\} " <file>`，人眼扫一遍有没有整节消失。
4. 大改前先 `cp <file> <file>.bak`；改完 `diff` 一遍再删备份。

### 6.2 剧本 ↔ 分镜 双向同步（改台词必回写剧本）

**症状**：分镜（第三部分）台词改了，剧本正文（第一部分）还是旧句。用户读剧本以为故事没改，读分镜又对不上。

**硬规则**：台词一改，**两份一起改**，且**剧本是给人读的、分镜是给机器读的**——剧本保留动作与情绪描述，分镜只保留可投喂字段。禁止只改一份。

**自检**：把剧本正文里的台词逐句 `grep` 到分镜里，应全部命中；反向也成立（画外对白除外）。

### 6.3 故事板 ↔ 分镜 同步（分镜动过 = 整份重出）

**症状**：分镜改了镜序/景别，故事板只被人手改了一句，格与镜错位。详见 `sd-storyboard-engine/references/storyboard-sheet-template.md` §十二。

**硬规则**：不许补丁式改字。跑 §12.3 的逐镜检查，`不一致 = 0` 且 `镜数 == 格数` 才算过。

## 七、交付前验收（照这个顺序跑）

1. `python scripts/check_asset_blocks.py <交付稿.md>` → **FAIL 必须清零**（跨条引用 / 格数 / 字段 / 道具）。
2. `python scripts/validate_prompt.py <交付稿.md> --model 2.5 --by-segment` → **FAIL 清零**；WARN 逐条判「真缺陷」还是「口径误报」，真缺陷改稿、误报写理由。
3. `python scripts/audit_contract.py <交付稿.md>` → 契约件核销（内部件缺失属预期，须能指出它在内部档案的哪一部分）。
4. 人眼过三件事：**件数 ≤3**、**正文只有两样（资产提示词 + 分镜提示词）**、**每条提示词单拎出来能独立使用**。
5. 命名检查：目录/文件/标题全中文，无 `EP0xx` 类代号。
6. **故事板逐镜检查**（有故事板时）：跑 `storyboard-sheet-template.md` §12.3 脚本 → **不一致 = 0**、**镜数 == 格数**；再核 `## P3 图形化交付清单` 的「四格覆盖」列是否已同步成「镜N 内容」格式。
7. **节数变动核对**（大改后）：`grep -n "^#\{1,3\} " <交付稿>` 扫一遍，确认没有整节被区间替换吞掉（见 §6.1）。
8. **口型/语序抽查**：随机抽 3 条带台词的镜行，确认 ① 台词按时间顺序内嵌、没堆行尾；② 画面段无声音词（C16a）；③ 说话人嘴唇状态在故事板里有标。
