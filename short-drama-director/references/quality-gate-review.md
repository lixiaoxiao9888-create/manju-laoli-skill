## 一·补、 跨项目污染专检（2026-10-10 并入）

迭代与多项目并行时，最容易把"上一版规则 / 上一个项目的样例"当成通用规则带进新稿。交付前过一遍下表——**这是 P0~P2 之外的独立专检，与 §一 并行生效**：

| 污染类型 | 症状 | 处置 |
|---|---|---|
| **旧时间格式回滚** | 稿中出现 `△0.0-3.0s` 绝对起止时间轴，或省略每镜时长 | 恢复编号镜头 + 整数秒口径；**总时长 = 各镜之和** |
| **占位语残留** | "根据剧情分配 / 待补充 / TBD / XXX / 某角色 / 某地点 / 某道具" | 正式字段内**不得保留**；无法确认则说明缺资料，不用占位语糊弄 |
| **风格 / palette 默认化** | 把某项目的色号、palette、摄影设备名称写成所有项目默认 | **默认不写 palette/色号**；项目明确要求才临时执行 |
| **样例剧情升级为长期设定** | 单集/单场剧情、单张参考图姿态、某段 prompt 的道具，被写进项目长期规则 | 长期设定只来自项目资料或用户明确确认；不确定的保持不确定 |
| **工具 / 元数据泄漏** | 稿中出现 YAML 头、allowed-tools、运行环境或模型能力声明 | 全部剔除，只保留可执行的自然语言规则 |

**原则**：项目长期设定必须来自项目资料或用户确认；**单段剧情不得污染全局**；历史来源与当前规则冲突时，**以当前项目资料与用户当前要求为准**。

## 二、 声音三层架构与混音电平规范

$$\text{第一层：对白清晰度 (0 dB)} > \text{第二层：动作物理音效 SFX (-6 dB)} > \text{第三层：环境声景与 BGM (-14 dB $\sim$ -18 dB)}$$

* 对白必须永远处于最高清晰度优先级，动作音效（骨裂/破风/撞击）不得遮盖人声，BGM 在激烈打斗或对白爆发时自动避让（Ducking）。

## 三、 改动后复验铁律（2026-09-04 新增 · 防"只验改动处"漏检）

> 改稿禁止只复验改动处。改动内容会与剧本其他部分冲突（伏笔/因果/资产/时长/画幅）——典型翻车：改一句台词剧透前文伏笔、改一个场景与《资产图册》锚点冲突，而整片未重跑审核。

### 三步复验闭环（缺一不可）
1. **局部验证（改动处自检）**：改动内容本身达标（台词/画面/锚点/时长）；
2. **联动冲突检查（七项交叉扫描）**：伏笔 → 角色（人设/脸模/服装）→ 信息量（剧透/节奏）→ 因果节拍 → 资产锚点 → 时长预算 → 画幅一致性，逐项确认无冲突；
3. **全量审核**：整片重跑 P0~P2 门禁（本文 §一），不允许以"已检查改动处"豁免。

### 《改动复验报告》交付要求
- 修改类交付物文末必须附：**改动清单 + 联动检查结论 + 全量审核结论**；
- 未附报告 = 视为未完成复验，**禁止交付**（对应 `asset-first-pipeline.md` 门禁 6）。

## 四、 多模态拉片诊改协议（`/拉片诊改` · 成片/废图逆向诊断与 V2 重抽闭环 · 2026-10-14 新增）

> **定位**：出稿机检（`validate_prompt.py`）拦的是「提示词文本结构与语义风险」，而 AIGC 实战的下半场发生在**用户在平台（Seedance 2.5/2.0 / 即梦 / H3）跑出资产图或视频之后**。当用户把跑坏的资产图、关键帧截图或成片视频发回对话（或口述实拍翻车现象）时，必须按本节「**症状 → C 码根因映射 → V2 重抽提示词处方**」执行逆向诊改，禁止盲目让用户“多抽几次”。

### 4.1 十二类实拍高频废片症状 → 根因 C 码 → V2 重抽处方表

| # | 实拍翻车症状（VLM 看图/看片或用户反馈） | 对应规则/C 码根因 | V2 重抽提示词精准处方（只改病灶，不动其余锁定项） |

| 2 | **反光道具变成自发光灯泡/冒火苗**（玉佩、银镯、铜镜在画面里自己发光或着火） | `C18e` / `C19a~d` / `C20d`（写了「不发光」被词根召唤，或写了「举向灯光/映出火苗/光斑」） | 删净一切「光/灯/火/反射/不发光」字眼；只写正向材质本色：「深青色实心哑光石质，玉面呈青玉原色」，且动作远离光源 |

| 6 | **打戏变成两人站桩对放光波，零接触零位移** | `C21a~c` / `C30a/b`（缺位移接触词，或未调用 R1 动力链 / R3 尺度四件套） | R1 补「蹬地→拧胯→转腰→送肩」+「架臂格挡卸力、衣料凹陷滑退」；R3 补「占画框八成+参照物+人物占千分之一」与「主体层/边缘层/表面层」 |

### 4.2 `/拉片诊改` 四步执行序列
1. **视觉取证**：读取用户上传的废片关键帧/资产图（或解析用户描述的翻车点），定位具体发生在哪一段、哪一镜；
2. **C 码归因**：对照 4.1 矩阵指出触发的具体 C 码/闸门病根（禁止笼统归咎于“模型抽卡随机性”）；
3. **生成 V2 重抽稿**：仅针对病灶镜行与对应栏位打补丁，自动重跑 `validate_prompt.py` 与 `gate_check.py` 确保零新增告警；
4. **同步回写台账**：若涉及资产级或状态级调整（如补登记 `CHAR_STATE` 或修正外观三件套），同步更新 `project_state.json` 与《改动复验报告》。
