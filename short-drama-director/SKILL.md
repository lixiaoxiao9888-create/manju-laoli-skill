## ★ 使用入口（先读这条 · 用户视角）

**用户只需要说一句话，剩下全自动。** 例如：

> 「帮我做一集短剧，题材是重生复仇，Seedance 2.5，竖屏」（国内剧）
> 「把这个小说改成 60 集剧本」（国内剧）
> 「这场打戏帮我出分镜和投喂稿」
> 「**对标一下最近红果榜上那部《XXX》，我想做一部同类型的**」（**对标爆款 → 〇·1 定为 ③，先挂载 `sd-recon-engine` 出《对标情报卡》，再进剧本层**）
> 「**这场打戏人物老是站错位、前后对不上**」（**→ 调度环 `blocking-direction.md`：先建场景坐标系与文字平面图，再逐拍走闭环**）
> 「**给我出一版故事板，我要照着它生视频**」（**→ `sd-storyboard-engine` 出的故事板图：每段一张、动作相位拆格、CLEAN_GRID 无文字版**）；「**要实拍式分镜预演卡/走位平面图**」（**→ 同引擎 §十一 SHOT_TEXT 卡：俯视走位图头 + 逐镜线稿卡，只给人看不进投喂**）；「**要剧情推演四宫格/六宫格/九宫格、固定人物的推演图**」（**→ 同引擎 `plot-deduction-grid.md`：每场一张连续叙事宫格，身份锁/场景锁/风格锁**）；「**这段场景复杂，帮我附个预演故事板 / 我想先看看这段戏长什么样 / 这段老是抽卡**」（**→ P4.5 预演故事板 `p45-previs-storyboard.md`：**交付时另附一份 `{项目名}-预演故事板.md`**，里面是一段一份的**叙事体故事板提示词**，你拿去图像平台自己出预演图看戏；**只出提示词、不出图**，不入册、不占参考图槽**）

总控会按管线自动跑完：**素材来源（〇·1）→ 决策（情境锚点）→ 剧本 → 资产 → 调度（站位/权力几何/节拍）→ 分镜 + 故事板图（打戏自动判档）→ 投喂封装 → 质检（P14 一跑到底：投喂层闸门 ＋ C 系机检 ＋ 契约核销，同一判据不重复查）→ 看板（**交付标配：默认另附一份《预演故事板》md · 只出提示词不出图**）**，中途按需向你确认锁与关键节点，**一次对话交付成品**。

**⛔ 用户不需要知道、也不需要手动调用任何子技能。** 下列 10 个子技能（sd-decision-engine / sd-recon-engine / sd-script-engine / sd-asset-engine / sd-storyboard-engine / sd-combat-engine / sd-xuanhuan-engine / sd-real-engine / sd-feed-engine / sd-qc-engine）是**总控的内部专业分工**——拆开只是为了让每块领域规则独立、清晰、互不污染（也让"只要打戏模块"或"只要音乐模块"的人能单独拿走那个包）。**全流程用户：只说需求，其余交给总控。** 子技能既不会要求你手动切换，也不会额外增加操作步骤。

> ⚠️ **执行者必读（这是给 AI 助手看的，不是给用户看的）**：「用户不需要手动调用子技能」**不等于**「总控可以跳过子技能」。子技能里的**固定模板与执行序列是硬规则**——不读＝没有。每个阶段**必须按下节【强制读取清单】显式读取对应子技能文件**，再动手写产物。**禁止仅凭总控 memory 里的印象"代言"子技能**（教训：FJ-1983 资产层只挂了"九宫格"名字，模板要求的 6 个结构化字段一个都没产出）。

> 💰 **【预算铁律：先报账 · 单批 ≤8k · 按结构切批 · 落盘即续】（2026-10-18 新增 · 专治「长流程跑着跑着开始敷衍」）**：
> **病灶先认清（否则会修错地方）**：全包 132 份 md / 118.8 万字符（≈76 万 token 当量），**单是总控本文件就 7.6 万字符（≈4.8 万 token）**。所以「装不下」永远发生在**输入侧**，「敷衍」则发生在**输出侧的第 8k 字以后**——⛔ **别把 128k 当单次输出上限**（那是上下文窗口，读入+历史+输出共用）；⛔ **也别指望模型自己数 token**（中文 1 字 ≈ 1–1.5 token，自估误差可达 50%，算账本身就烧额度）。
> 1. **报账制（开工第一步 · 与五道锁同批完成）**：先报「阶段 → 预计批数 → 每批字数」，由 `python3 scripts/slice_context.py --estimate --stage <P#> --combat <R1~R3> --model <2.5|2.0> --mode <M0~M2>` 出数，**禁止心算**。报完账再动笔；批数与用户预期不符时当场对齐，别写到一半才说"篇幅太大"。
> 2. **读入侧只读切片**：每阶段**只读 `slice_context.py` 切出的清单**，禁止通读全包、禁止一次加载多个阶段原文；同一份原文全文**只载入一次**，下游靠落盘产物 + 《连续性台账》接力，⛔ 不靠"我再复述一遍"接力（复述＝双倍烧 token + 引入漂移）。
> 3. **输出侧单批 ≤8000 token（约 1.2 万汉字）**：越过 8k 后段必然开始套模板——写「同上」「其余同理」「省略若干条」「格式参照前文」，**这就是用户体感里的"AI 偷懒"**。接近上限**主动切批**，不等截断、不等用户发现。
> 4. **按结构切批，不按字数硬切**：**集 > 场 > 段 > 幕**；⛔ **一场戏不许劈两半**（劈开 = 人物状态、站位、镜头逻辑三处同时断链）；跨批只传「已完成清单 + 状态台账 + 本批任务卡」，**不传正文全文**。
> 5. **落盘即验 · 打断不重开**：每批写完立刻落盘 + 回读校验（条数 / 字段 / 机检），不达标**只重跑该批**；⛔ 严禁用「概述」「详见上文」顶替应交付条目——**数量不够就是没交付**。中途被打断后恢复，**先读落盘产物与台账，禁止重放已完成批次**（重放＝白烧一遍额度，还会稀释当前批注意力）。
> 6. **确认策略（开工问一次，二选一，选定后不再逐批追问）**：
>    - **① 自动续跑（默认）**：批与批之间**不停**，只在 **P1 剧本门 / P2 资产门 / P3 分镜门 / P4 投喂前** 四个阶段门停一次——保住「一句话交付成品」的体验；
>    - **② 逐批确认**：每批落盘后停，等用户说「继续」（仅用于长剧集精修、或用户明确要求）；
>    - **强制停的三种例外**（选哪个都要停）：单批实际输出**超预算 1.5 倍** / 机检 **FAIL** / 出现需用户拍板的岔路（改锁、素材来源冲突）。

> 只有一种例外：用户**明确点名**某个子技能（如「用 sd-xuanhuan-engine 出这一段」）时，才直接进入该子技能独立工作——这是给"只要单模块"的进阶用户留的口子，不是全流程的必经之路。

### C · 交付形态三选一（★ 强制锁 · 与 A/B 同规格；未指定 = 停下询问）
- **① 只要离线看板**：项目 md 照常创作（它是看板的唯一编译源，不写 md 就没有看板），但最终**只交付看板 HTML**，md 留作工作底稿；
- **② 只要 markdown 文档**：交付 md，不编译看板；
- **③ 两者都交付**：md + 编译好的单文件离线看板。
- **依赖关系必须向用户讲清**：md 是唯一真相，看板由 md 编译生成——**看板离不开 md，不存在"跳过 md 直接写看板"**；创作耗时在内容本身，C 只决定最后交付哪份文件，几乎不影响出稿速度。
- **交付标配（别名 P4.5 · ★ 默认必出 · CT5-P45 条件门叠加）**：C 锁只管「主交付交哪份」，另有一份**默认必出**的《预演故事板》md——**每次 P4 投喂稿 / 看板交付完成后自动另附**；独立文件 `{项目名}-预演故事板.md`，**只出提示词、不出图**（本包不持有图 · M0/M1），不入册、不占参考图槽。**CT5-P45 硬门**：① 单段【站位声明】具名 ≥3 人同框 ② 全集 ≥2 个不同 `@//scn/` 场景 ③ 单段内跨 2 场——任一命中而不附 = 契约 FAIL。**可免（须在主稿写明理由，⛔ 禁静默跳过）**：单镜过场 / 纯空镜 / 纯字幕段 · 用户明确说不用 · 尚未进入 P4。⛔ 不许合并进主文档，也不许回头改变 C 锁。权威见 `sd-storyboard-engine/references/p45-previs-storyboard.md`；**交付前必跑 `sd-storyboard-engine/scripts/check_p45.py`，FAIL 清零。**
- **交互口径（★ 2026-10-13 用户裁定修订）**：与 A、B 同一句话问清（"模型版本？画幅？要看板、要 md、还是都要？"）——**必须问、必须等到答复**；⛔ **禁止「用户未答就不追问、直接按 ③ 执行」**（用户原话：「**这个还是没有给我选**」——写了默认值也不行，必须给选项让用户勾）。用户明确回「你定 / 按推荐来」才算答复，此时可选 ③ 并说明理由。

#### C·补 · 交付物件数与正文边界（★ 2026-10-19 实战回写 · 硬门）

> **病根（真实事故）**：一次 90 秒单集任务交付了 **15 个文件 / 10 个目录**（IP圣经、故事圣经、分集规划、资产包、导演稿、情绪锚点表、分镜稿、投喂稿、质检报告、台账……），用户质问「动不动就几十个，其他一堆是啥」。根因不是流程需要，而是**把各引擎的中间工作文件当成交付物逐个落盘**——工作文件是引擎间的协作接口，不是给用户的东西。

1. **件数上限 3**：一次任务对外最多 **① 主文档（md 或看板，按 C 锁）+ ② 看板 HTML（仅 C 锁含看板）+ ③ P4.5 预演故事板（默认必出；豁免须写明理由）**。⛔ 超过 3 件 = 交付层违规，中间件必须并入主文档或留内部档案。
2. **md 正文只放两样**：**资产提示词 + 分镜提示词**。**⚠️ 硬要求（2026-10-22 补 · 治「只交投喂稿」）**：只要稿件里出现了 `@//chr/` / `@//scn/` / `@//prp/`（含图号速查、素材接线单），就**必须**同稿带资产提示词段；确需拆册交付时，**主稿必须写一行「资产另册：{文件名}」并在交付清单登记**——否则「另行拆册」与「根本没写」在文字上无法区分。机检：`validate_prompt.py` 新增 **C34**（引用资产但无资产段 → WARN）+ `audit_contract.py` 的 feed-only **不再豁免 CT2-***（未声明另册即 FAIL）+ `check_asset_blocks.py` 零资产块 = **A0 FAIL**。IP 圣经 / 故事圣经 / 世界锚卡 / 人物锚卡 / 分集规划 / 圆桌审核 / 质检报告 / 情绪锚点表 / 导演稿 = **内部档案**（独立文件、文件名前缀 `_内部_`、不放桌面、不进交付包）。⛔ 交付稿里出现「世界锚卡 / 人物锚卡 / 分集规划 / 圆桌 / 质检 / 情绪锚点 / P0A / M1 / C27」这类内部术语即视为泄漏。**出看板时按看板口径承载全貌，此分层不适用**。
3. **命名全中文**：目录、文件名、正文标题一律中文；集数写「第01集」「第01-03集」；技术标识（Seedance 2.5 / 9:16 / M1 / 图号）保留原文以对齐机检指纹。
4. **合并后改引用**：多份中间件并进主文档后，内部交叉引用统一改成「第X部分」，⛔ 不保留下游文件名引用（删中间件即断链）。

> 完整翻车清单与逐条自检见 **`references/delivery-pitfalls.md`（★交付层唯一踩坑权威）**。

> **五道前置锁齐备才动笔（〇·1 素材来源 / A 模型 / B 画幅 / C 交付 / D 段缝·多段任务）**：素材来源 与 A·模型版本 与 B·画幅 与 **C·交付形态** 与 D·段缝衔接方式 **全部锁死**，才允许进入 P1 之后的任何环节（★ 2026-10-13：C 由「可后置」升格为强制锁）；**D·段缝衔接方式仅多段任务适用，未指定 = 停下询问**——**「多段任务」按本文件 §〇 首段判定式（`目标成片时长 ÷ A 锁单段上限 > 1`）在 P0 立项期判死，⛔ 不得挪到分镜/投喂阶段再判**；**I·画风锁为「必弹卡锁」——动笔前必须推送候选卡让用户勾选（卡内必含「按你的推荐走」一项），⛔ 禁止在用户未表态时自行按默认推荐卡执行；选定后即冻结（换风格 = 重开任务）**。素材来源规程见 `sd-recon-engine/SKILL.md`，模型规程见 `references/model-adapters.md` 〇节，画风锁规程见 `references/style-bible/style-lock-protocol.md`（★权威）。

### D · 段缝衔接方式四选一（多段任务与 A/B 同规格）

> **背景（粉丝实测反馈）**：AI 模型每段零记忆——上一段的站位/姿态/互动在下一段全部归零，段缝处必然跳切、动作断层（"段落间衔接生硬"的病根）。把段缝衔接升格为前置锁，四种方案可叠加，规程见 `segment-splicing.md`（★权威）+ ④ 类见 `creative-transition-library.md`（★权威）。

- **用户必须明确选择（多段任务）**；未指定时唯一正确动作是**停下询问，并严格按下方 ① / ② / ③ / ④ 四个独立选项原样弹出让用户勾选**——⛔ **严禁把 ① 和 ② 合并成「①+②」弹出、严禁漏掉第一项「① 末帧定格承接（尾帧锚定法）」**；**单段任务不涉及此锁，不询问**；**「多段任务」唯一判定式见本文件 §〇 首段（`目标成片时长 ÷ A 锁单段上限 > 1`）**——⛔ **禁止以「剧本还没写到分镜」为由把本锁推到后续阶段**（本锁属立项锁，与 A/B 同批弹出）；
- **① 末帧定格承接（尾帧锚定＋段缝画面锁 · 默认推荐 · 第一选项必弹）**：**画面依据按「尾帧锚定法」获取**——**段末镜末 1 秒整秒写「全体人物保持姿态与站位、动作完全静止、画面定格」（前置 0.5 秒为收束窗：镜头运动收束、人物停止大幅动作；末镜景别须装下全员、禁大远景，剪辑时裁掉末 1 秒静止帧），产出可截帧的定格尾帧 → 直接截取该末帧作下一段首帧/参考图依据（替代重新出图，一致性 100%、成本 0），下一段首镜以 0 级同档景别直接承接该末帧**；仅在末帧不合格（模糊/穿帮/带字幕/无人物/朝向不可用）时**回退**到"按结尾状态重新绘制段缝分镜参考图"（依据＝人眼看实际末帧）。平台差异：2.5 模式②截帧作 `first_frame`、模式①作参考图组成员；**2.0 无首尾帧——截帧作单参考图（每段 1 张，占 M 轴名额）**。⚠️ **原「末态双保险」的文字腿（【接续状态】尾行）已于 2026-10-09 废止（用户裁定）**——理由：段尾栏位模型读不到、对段内站位问题零作用、且与 D 锁③ 空镜相冲（空镜结尾时它承接的不是人物）。**本方案现为单锁（图锁）**；如某段确需给下段一句起手语义提示，写进**该段末镜行句尾**，不另起栏位。详见 `segment-splicing.md` §二 §三 §四·补；
- **② 换机位硬切**：不截末帧原位承接，段缝两侧**直接更换机位/视角硬切**（把两段做成两个不同镜头的剪辑关系）——最快、零出图成本；**★2026-10-17 补「接口余量」**：末镜**末 0.5 秒只收势、不写定格**（保留余势），余量由**剪辑端在后段开头**接转场吃掉（叠化/闪白/遮挡/甩镜）；⛔ 选 ② 却写「末 1 秒定格」= 口径混用（那是①的写法，白丢 1 秒）。**适用于「剧情段划分 + 组内多机位」的段缝**（每组 3~5 镜、组间本来就要换机位/换场/换时间）——这类段缝**改走 ② 不需要额外理由**，分流表见 `segment-splicing.md` §四·乙；
- **③ 空镜过渡**：段缝处插 **1~2s 带戏剧任务的空镜**（情绪空镜+BGM 不搭人声 / 音效桥空镜声音先入 / 时空转场空镜，搭声不搭皆可），单集 ≤3 处——情绪段、转场段可选；
- **④ 技巧型转场（★ 2026-10-13 新增 · 用户追问）**：段缝处用一个**有设计感的创意转场**（**相似动作 / 形状匹配 / 前景遮挡 / 甩镜 / 闪白 / 画中画 / J-cut 声先画后** 等——文戏六式 + 大师技巧辑录见 `creative-transition-library.md`（★权威））。⚠️ **按剧情选用，非每段必用**——用户原话：「**我不是每一段都要用这种比较偏特效一点的转场，但其实应该是有的是吧**」；**单集 ≤3 处、同段不连用 ≥2 处**，每个转场必须能说出叙事意图，⛔ 禁"为转而转"。**术语禁裸写进投喂稿**（C12）——投喂稿写"画面怎么接"，术语只在分镜层标注；
- **选择与组合规则（禁弹「①+②」捆绑项）**：弹出菜单时**必须分列 ① 末帧定格承接 / ② 换机位硬切 / ③ 空镜过渡 / ④ 技巧型转场 四项**，首选独立项为 **① 末帧定格承接**（原「①+② 默认绑定组合」已废止——选 ① 时剪辑直接裁掉末 1 秒定格帧后由下段 0 级同档承接，无需强绑换景别）；若全集不同段缝需按剧情混用（如大部分段缝用 ① 末帧承接，个别转场段缝用 ③ 空镜或 ④ 技巧转场），可在选 ① 主导后按段标注；无论选哪种，**段末都不写任何接续尾行**（【接续状态】2026-10-09 废止；机检 C11 已**反转为"残留即 FAIL"**），工作流规则词（末态继承/拼接节点/换机位）禁进投喂正文（C12）。
- **★ 段缝 ①/② 分流口径（2026-10-17 新增 · 治「默认推荐 = 唯一正解」）**：① 是**默认值**，不是**唯一正解**——**跨组长动作 / 长对白跨组 / 一镜到底被切** → ① 末帧定格承接；**剧情段划分 + 组内多机位**（组间本来就要换机位/换场/换时间） → **② 换机位硬切就够**，再上 ① 是**白丢 1 秒 + 白截帧 + 白压景别**（粉丝「森林」2026-10-17 实测口径，裁定见 `segment-splicing.md` §四·乙）。⚠️ 分流不改变锁的性质：**用户仍需在四选项里明确勾选**，本条只约束"勾了 ② 之后不必再补 ① 的三步"；
- **⑦ 分段粒度（与段缝方式同层决定）**：定完接续方式后**必须同时定段长**——**Seedance 2.5 默认 25~30s 吃满上限**（下限 12s；**禁 16~24s 碎段区**，除非打戏快节奏或单段信息量确实小）、2.0 上限 15s。**段数越少、段缝越少、一致性越好**；不要因为「保险」把 30s 内容拆成两个 15s（多一个段缝 = 多一次跳切风险）。机检 **C1b** 兜底告警。

### E · 默认只出提示词，不直接出图 ＋ 素材形态 M0/M1/M2（最高优先级 · 用户确认铁律）

- **本 skill 默认交付形态 = 提示词/文档，一律不调用出图工具（`image_generate` 等）直接生成图片**。
- 资产图/参考图（角色 4 View、场景母版、道具图、分镜关键帧/首帧图等）同理——**默认只给「出图提示词」供用户自行执行，不替用户直接出图**。
- **唯一例外**：用户**明确逐次下达出图口令**（如"出图""生成图片""跑图""把这张图出了"）才允许执行；且仍须遵循 `asset-first-pipeline.md` 门禁——建案清单先确认、分批出图逐批确认。
- **禁止**：禁止把"开始 P2 资产出图"/"开始跑图"当默认动作、禁止未经确认直接发 `image_generate`、禁止以为"用户要完整流程"就等于"用户要出图"。
- 用户在对话里追问"怎么还没出图" ≠ 出图授权；须明确说"出图吧/生成吧"才执行。
- 与 `short-drama-produce`（确认制生产 skill）协作时：出图执行一律走它的确认闸门，本 skill 不自行出图。

#### E.1 由 E 推出的必然结论：图不在本包手里（★权威 = `references/asset-delivery-modes.md`）

> **既然本包不出图，那么"图"这个实体就永远不在本包的上下文里。** 强行要求"图已锁定才准继续"，等于把流程卡死在一个本包无法完成的动作上。

- **素材形态三档（每次交付首行必须声明）**：
  - **M0 纯提示词**——不出现任何图号/参考图槽位；一致性靠**文字锁**（外观档案复述块等）。用户说"我没有图 / 不要图号 / 只要提示词"时使用。
  - **M1 编号占位（默认）**——出现 `图N` 槽位 + **必附《素材接线单》**（图号 → 用途 → "你该挂哪张" → 只控制什么/不控制什么）。**这是绝大多数用户的真实工作流**：拿提示词 → 去平台自己跑图 → 在平台把图挂上，**不需要把图交回本包**。
  - **M2 已入库**——用户**主动**交回图并登记《资产图册》，此时**才**能做图像级核验（门禁 5 原样）。
- **四铁律（不索要 · 不阻塞 · 不假装 · 要声明）**：
  1. **不索要**——禁止把"请把图发我 / 请上传素材"作为继续流程的条件；
  2. **不阻塞**——**禁止因"没有图"阻断 P3 分镜 / P4 投喂 / P5 质检**；门禁 2/3/4/5 按形态**改判**（改判表见权威文件 §二）；
  3. **不假装**——**禁止写不存在的图号当锚点**；**禁止声称"与《资产图册》一致""已核验"而实际从未见过图**（这是本类问题里最严重的一种：把"没检查"说成"检查过了"）；
  4. **要声明**——每次交付首行写明形态，并说明一致性靠什么保障。
- **形态切换规则**：默认 M1；用户说"没有图/不要图号"→ 降 M0；用户把图交回 → 升 M2。**禁止静默切换**（M0 稿里夹带图号、M1 稿里漏掉接线单，都属形态违约，机检告警）。
- **与 A0~A3 的关系（两条正交轴）**：A0~A3（`asset-first-pipeline.md` §〇 第 9 条）管**任务复杂度 → 走不走资产链**；M0/M1/M2 管**图在不在手里 → 门禁怎么判**。**A 轴判不清按 A3，M 轴按用户实际条件，不取最高档**——用户手上没图就 M0，**不得为了"合规"逼用户出图**。

### F · Seedance 2.0 时长分配铁律（用户确认 · 与 E 同级）

- **2.0 单段时长上限 15s，不是 10s，更不是固定值**：段长完全按剧情内容量倒推（台词按 3.5~6 字/s、动作按节拍/信息量），**禁止把 10s 当默认时长、禁止全片统一卡 10s、禁止"段长÷镜数"机械等分**（配合法则 17 镜长节奏铁律）。
- 例：一段戏 7s 讲完就 7s 收，需要 14s 就 14s，15s 是上限不是目标值；只有用户明确指定"就 10s"才用 10s。

### G · 台词/音效默认视频内出（用户确认 · 与 E/F 同级）

- **台词与人声音效默认写入提示词、由视频模型在成片内生成**——台词走声音层锁口型与对白（2.5 用官方 `{}` 台词字符；2.0 以文字描述写入台词栏），**禁止默认"全走后期配音"**；
- **唯一例外 = 用户明确逐次指定「不出台词」/「台词走后期配音」**：此时台词不写入生成或标注后期合成（锁定口型节奏，后期配音）；
- **音效同理**：默认随视频生成（2.5 `<>`/`[SFX:]`；2.0 文字描述写"声音：…"），仅用户明确指定才走后期层；
- **禁止**：禁止把"全段音效/台词走后期配音层"作为默认写法预置进模板与交付物；旧口径"2.0 音效/台词均后期配音"以本条为准作废，不作 CURRENT 调用。

### H · 素材红线边界澄清：禁「真人照片素材」≠ 禁「写实/仿真人风格」（用户确认 · 与 E/F/G 同级）

- **官方红线只约束参考素材来源，不约束输出画风**：Seedance 2.5 / 2.0 **不支持上传含真人人脸的参考图/视频**——即**禁止把现实真人的照片 / 真人脸图**当参考素材投喂；这与画风无关。
- **写实 / 仿真人（次世代 3D / 实拍级质感）风格完全支持，不属红线**：本包「R1 写实克制」动作档、`audiovisual-aesthetic-presets.md` 的「东方诗意写实」预设、角色资产板标准画质词「次世代 3D / 实拍级全身模型拆解」、以及 Seedance 2.5 官方「成片接近实拍影视质感」均为正式支持用法；**严禁把红线解读为「只准二次元」而收紧写实需求**。
- **判定口径一句话**：看**素材来源**，不看**画风**——AI/CG 生成的写实仿真人（超写实渲染）= 可用；翻拍/下载的**现实真人照片** = 红线。
- **禁止误用**：禁止因「禁真人人脸」而拒写写实人物提示词、拒做仿真人风格分镜、或劝用户改二次元；写实需求照常出稿，只在**绑参考图**这一步守住「素材非现实真人照片」。
- 红线四条完整表述见 `references/model-adapters.md` §5（官方限制）；资产侧见 `references/asset-spatial-ledger.md` §二；投喂自查见 `references/prompt-feeding-checklist.md`。

### I · 画风锁（方案文档通称「F 锁」）—— 导演风格选项层 → 参数化交付层（★ 必弹卡锁 · 选定即冻结）

> **别称说明**：外部方案与讨论中的「F 锁」= 本锁。**锁性质（★ 2026-10-13 用户裁定升格）**：**必弹卡锁**——**动笔前必须推送候选卡、让用户在卡上勾选**；卡内**必须包含「按你的推荐走」一项**（用户不想挑时可主动选它，等价于授权用默认推荐卡），⛔ **但禁止在用户未表态时自行按默认推荐卡执行**（用户原话：「**这个还是没有给我选**」）；**选定后即冻结**，与 A/B/C/D 同规格（全流程只读、中途换风格 = 重开任务）。

- **它解决什么**：用户说「要徐克的感觉」，旧流程只能把人名/形容词塞进提示词——人名违反交付层纪律、形容词模型读不懂。I 锁把「选风格」变成**递进式选单 → 选定即转译成 11 槽位量化参数 → 植入段8/段9 → C23 机检兜底**的闭环；首轮徐克版 10 秒实拍已量化验证（画风层 5/5 项通过、动态范围 226/255）。
- **递进式选择（Step1 基底必确认 → Step2 技法族 3 选 → Step3 导演卡 ≤4 张 → Step4 可选辅助）**：每一步都在排除而非增加选项；排除链可追溯；同族 ≤2 张；打斗★/特效★ 为硬门槛。**候选源 = 74 组导演风格库**，题材路由 + 排除引擎可用 `scripts/style-lock-ladder.py`（递进式）与 `scripts/style-lock-recommend.py`（题材→候选池）辅助出卡，D 自定义 = 用户口述建 STYLE_BIBLE。
- **打戏硬门槛**：含打斗的题材**硬排除打戏承载 ≤★1 的风格**（王家卫 ★0 等打戏禁用组）——适配矩阵唯一权威 = `references/style-bible/style-fit-and-combat-matrix.md`。
- **两层架构与零人名**：**选项层可以用名字（徐克/王家卫/MAPPA），交付层绝不出现人名/工作室/影片名**（灵境铁律第 8 条 · 机检 C23d1）——系统负责把选定风格**转译**成 11 槽位参数（参数源唯一权威 = `references/style-bible/director-param-library.md`），组装成段8/段9 成品块（`style-prefix-blocks.md`）**逐字植入**投喂稿。植入规程（两层五段架构 / 渗透机制 / 三条硬规则 / C23 判据）唯一权威 = `references/style-bible/director-to-prompt-protocol.md`。
- **段8/段9 风格专座**：段8【STYLE｜视觉风格 · 全片锁死】（11 槽位写一次）+ 段9【PERFORMANCE｜表演与动作 · 全片锁死】（风格带表演语法时写）——**全片范围参数进段8/9，每镜可变部分仍在段1/4/6，镜头取值必须落在段8 区间内**（C23b 越界兜底）。**包内不提供成稿示例**——段8/段9 一律按选定卡号从 `style-prefix-blocks.md` 逐字取块，禁止拿任何现成稿当参照（P14 起示例整体剔除）。
  > ★ **2026-10-12 用户实测修订（路径变更）**：**用户回「按你的推荐走」/ 未指定具体导演卡的常规稿 → 不写段8/段9**，只把**美学短语 ≤30 字并入【画幅风格】**（★ 2026-10-14 用户修订：15→30 字，放宽后可带光比/镜头/质感三要素）（约省 260 字符/段，全部释放给描述与台词）；**仅当用户明确选定导演卡时才落段8/段9**。用户原话：「这块先把它去掉啊……我只需要它的美学……控制在 15 个字左右，把它附到画面风格那就行了」；「什么机位啊什么节奏啊这些东西，稍微有点多余」。C23 触发门默认 `auto`，无段8/9 即整组不检，**不会制造 FAIL**。

19. **对白三要素·语气位必写（2.0/2.5 同规格）**：官方三要素 = **WHO + WHAT + HOW**，本包统一写 **`台词：【角色（语气）："…"】`**——语气紧贴角色名、写在冒号前括号内（与画外声 `（OS·音色）` 同构），**不新增字段、不新增段**。五条铁律：① **声音词只进语气位，禁写进画面段**（写进画面段会被当视觉信息渲染，画出一张冷笑的脸，C16a）；② 语气按**四维**写（情绪色/力度/音质/节奏），每句 ≤3 词、允许演进 `（压抑→破防）`，**禁空泛结果词**（C16c）；③ 语气是**文本层**信息，**2.0 与 2.5 同样必写**（C16b）——2.0 不支持音色锁 ≠ 可不写语气；④ **音色锁仅 2.5 且可选增强**（投 `reference_audio` 并在【核心人物】行尾标注"锁定音色"），**不做资产体系、不设前置门禁**；⑤ **道具动作与语气一致**——闲适把玩类（把玩/摩挲/拨弄）只配慢悠悠/玩味语气；宣判/一字一顿/嘶吼时必须换成**攥紧/捏住/垂手握着**（实测病灶：宣判台词配"直起身把玩玉佩"）。**声音层（语气位/`声音：`段/【音效】）豁免反形容词规则**（声音没有肌肉动作可写），但同样禁空泛结果词。规程见 `model-adapters.md` §5.2 + §5.0.3，机检 C16a~d 兜底。
20. **人物账连续·摆位必入画（跨段防穿帮）**：模型每段零记忆——**上一段的人这一段凭空消失、下一段又出现，是最典型的跨段穿帮**。六条铁律：① **摆位必入画**：【站位声明】摆了位的每个人，本段镜行**至少带到一次**（正拍/焦外身影/全景/反应镜均算），给不了镜头就在站位括号写 `段末离画 / 退场·去向`（C17）；② **入画要交代**：离场的人重新入画须写 `段初自门口入画`；②b **新面孔首现要交代**——相邻两段在场人物集合不同时，后段新增具名人物必须有①画内入画 / ②画外先声 / ③空镜转场 / ④上段末镜行句尾过渡之一（`（在场）` 静默人物可走软口径），**不补 = 观众读作"跳了一段"**（C17e）；②c **过渡是剧本层的戏点，不是分镜层的补丁**——**过渡必须承载新信息**（加人物状态/情绪/空间），⛔ 默认禁用「随后/接着/转眼」硬接；四类按加戏量排序：**① 动作桥**（一句话不说就把"他迟到"立住）/ **② 空镜叙事**（灵堂扫一下：遗像+白花+没撤的供桌）/ **③ 声音桥**（门外由远及近的脚步声）/ ④ 硬接（须写理由）；**落点必须指定挂在前场末尾还是后场开头**——这正是段1→段2 断层的直接成因（`episode-planning.md` §TRANSITION_AS_BEAT）；③ **站位不漂移**：相邻段没写移动的人，位置/朝向/依托物不得无交代改变（C17d）；④ **（在场）标记口径**：无标记=有台词或明确动作反应，`（在场）`=可见但无台词无反应——两级都必须进站位声明，禁自创其他标记；⑤ **对话戏节奏与台词密度**——切镜点按「**回合**」切（至少换 说话人/景别/角度/主体 之一；⛔"只为这句说完了而切、其余变量全不变"= 废切），同一说话人不得连续 ≥2 镜独占开口；对话段台词密度 ≥2.0 字·秒⁻¹（15s ≥30 字）、开口 ≥6 次/15s；空镜/转场/打斗段**不设下限**。补台词只走四条正路（OS 补位/短句化拆解/加对方回嘴/—），⛔ 禁拉长文采凑字。出稿机检兜底：**`C17a`** 摆位必入画 / **`C17b`** 长对白关系镜缺失 / **`C17c`** 背景锚点缺失 / **`C17d`** 跨段站位漂移 / **`C17e`** 人数变化未交代 / **`C17f`** 单一方位权威；**`C27b`** 对话段台词密度 / **`C27c`** 对话段开口次数 / **`C27d`** 同一说话人连续独占开口。**逐段自查**（多段稿每段都跑一遍，防"B 在下一镜不见了"）。
20·★ **一切节奏类规则服务剧情，不是模板（本条为法则 20/21 及全部节奏类判据的适用前提）**：用户原话——「**你灵活一点，不要说我说啥就把它完全定死了，这个东西它本身是服务着剧情走的**」；「**也不知道你为了切而切，有一些剧情就不适合这种来回的切**」。① 下列指标是"常见毛病别犯"的默认倾向，**不是每段必套的模板**——回合制切镜 / 开口密度（15s ≥6 次）/ 台词密度下限（对话段 2.0 字·秒⁻¹）/ 动静随剧情调配（已废除「15s 运镜 ≤2」死名额）/ 长镜默认拆分 / 站桩三秒铁律；② **剧情该慢的段落（静场对峙/宣判/留白/独白/长镜压迫/情绪积累/回忆）不适用**——须**显式标注段落意图**（如「本段为静场宣判段」），C27 据此跳过；这类戏靠沉默、静止与时序连续更有力，切碎了反而毁掉；③ **空镜带先声是合法且常用的手法**（公园空镜传来人声 → 切对话），"空镜段不设下限"意为"不强制、不考核"，**不是"禁止写台词"**；④ 判准永远只有一个：**这段剧情需要什么节奏**——「为切而切」与「该切不切」是**同一种病**；⑤ ⛔ **禁止把本条的"灵活"读成"可以拍呆"**——用户同时批的是「站桩式对话、过渡少、呆板」，故默认倾向该用的地方必须用，例外**必须写明理由/段落意图**（不写理由的例外 = 违规）；⑥ **⛔ 禁止滥用「段落意图」豁免**——实测翻车：一集 90 秒把六段里的四段标成"展示段／闪回段／独白段"跳过 C27b，整集只有 48 字台词（0.53 字·秒⁻¹），用户连退三次：「**你就在那展示展示展示，其实他根本不知道咱们在干嘛**」。**判定口径**：豁免只给**静场对峙/宣判/留白/独白/长镜压迫**这类剧情本身就是"不说话"的段；**「她一个人在吃／翻／走」不是静场，是缺戏**——必须改成对话场（加对手/电话/门外人声），不得标成展示段逃避密度考核。**短剧安全线：整集台词密度 ≥3.5 字·秒⁻¹**（90 秒 ≥315 字），低于此值无论怎么标都按不合格（四式见 `dialogue-naturalization.md` §九）；⑦ **运镜与镜数的服务剧情原则**——实测翻车：90 秒写了 **24 镜/18 种不同运镜/0 固定**，平均 3.75 秒切一次，实拍**穿帮严重**（背景漂移/人物变形）。根因：**为了过 C18g 给每个镜头都配运镜词**——把「必须标注运镜」错执行成「必须运镜」。四条硬规则：① **切镜 = 一致性重掷**，短剧对话主场**一镜到底优先**，一段能在固定机位内完成的动作与对话不拆镜（90 秒竖屏常规 **2 镜/段**：建立镜头 + 对话主场）；② **固定不是偷懒，是一致性最好的语法**——`固定` 本身即合法运镜词，**不必为过检编花式运镜**；③ **运镜必须有动机**（推=情绪逼近/移=跟随/摇=揭示），没动机就不动；④ **C10（单镜 >6s）与 C18j（固定配额）在「对话密集短剧的一镜到底对话场」按本条豁免**（须书面登记）。
21. **首镜锚定·景别一致·姿态延续·视线指派（单段防废镜）**：① **首镜人物锚**——每段第 1 镜必须让站位人物至少一人入画（人名或注明归属的身体局部），空镜开场须镜行首写「空镜：…」且每段至多 1 镜；首镜无锚，模型渲染出空场景（C18a）；② **景别三一致**——特写/紧特写只承载单一局部主体，空间级事件（暴雨砸漏房顶/全屋火起）由中景以上承载，禁「特写+顶拍+全屋事件」混装（C18d）；③ **姿态延续**——撑起/坐起/起身一旦发生，同段后续镜必须显式「保持撑坐/已坐起」或焦外交代，倒下要写跌回/瘫倒过程，禁无声回退（C18b）；④ **视线指派（★ 2026-10-12 扩写 · 多人同镜硬项）**——说话镜必须写「目光落在 XX 脸上」，手持/把玩道具说话须补「视线不落在道具上」（C18c）；**★ 单镜 ≥2 人时，【站位声明】内每个具名人物都必须写「视线落点：看向 @某人 / 看向某物」**——**身体朝向 ≠ 视线方向**，只写「正面朝左 / 侧身三十度朝右」等于把眼神交给模型，三人以上同镜必然串行（用户实测原话「**三个人以上基本上就是乱了**」）。规程见 `model-adapters.md` §5.0.2，机检 C18 兜底（含 C18f 幅度越界、C18g~l 运镜门）。**拉片增补（§5.0.3）**：道具光效双保险（C18e）/ 表情锚（冷硬台词必写具体面部肌肉动作，模型对年轻女性默认甜笑）/ 外观锚（核心人物行写年龄锚、特写复述"同一张脸"，防换脸）/ 跨镜在场与方位减负（非主体人物镜行内锚依托物即可，**严禁重复段首已声明的画面左右**——双重发位是"东一个西一个、突然出现在身后"的病根，C17f）/ 禁模型自加镜头。
22. **禁令失效三改法 + 栏目纪律**：**视频模型对否定不敏感、对词根敏感**——「禁空镜」里的空镜、「不发光」里的发光、「面无笑意」里的笑，词根留在提示词里（哪怕挂着"不/禁"）就会被当画面词渲染（实测三条否定式禁令两轮全被无视）。高关联视觉概念（光效/表情/开场镜头）必须三改：① **换词**——被禁词根在**任何位置**（含强制禁止项）零出现，改写正向描述（道具→「深青色实心哑光石质，玉面呈青玉原色」**零光效描写**，C20d；表情→「双唇抿紧、嘴角向下压、下颌绷紧」；首帧→「画面主体：<人名>…」单主体开头）；② **主体优先句式**——每段镜1 第一个分句即画面主体，环境前置词开头会诱导空场景（C19c）；③ **触发器移除**——诱发被禁效果的动作/构图换掉（道具不与灯火共现：只把玩/佩戴，不靠近任何光源——旧建议"举到油灯旁侧受光"已废止，实测同样点火）。**栏目纪律**：【强制禁止项】被模型当"规避清单"读，**只装负面清单**（变形/手部异常/服装变化/现代元素/字幕/Logo/水印；文字；音频）——**正向执行指令禁入**（写进去既不当禁令也不当指令），**否定式禁令同样禁入**（被禁词根＝画面词）；正向指令一律回落【时间轴分镜】镜行/【画幅风格】/【站位声明】（C19e）。水印/变形等**低关联瑕疵**仍走否定式兜底。**具象光源映射（C19d）**：反光道具镜行禁写「映出/倒映火苗」——模型会把「映出+光源名词」读成光源出现在道具上，只写材质本色（旧"光斑语言"已废止，实测出片像打火机点了一簇火）。**镜行少形容词**：正向描写每镜只留必要项（主体/动作/材质/光各一处），堆叠会稀释关键信息、拉低服从率。规程见 `model-adapters.md` §5.0.4，机检 C19a~e 兜底。
23. **首镜单主体锚定与具象化（防"两张脸"）**：① **锚定句只许一个具名主体**——**禁「X 与 Y 同框」类并列主体句式**（模型读成"画面里有两个主体"，把同一主体的手与脸渲染成**两个头**；❌「首帧即这只手与她的脸同框」→ ✅「画面主体：林清月蜷卧土炕、病容苍白。她的一只手搭在破被外」）；确需两人同镜由【站位声明】具名双主体承载，**镜行内不写「同框/同在画面/一同入画」**（C20a）；② **指代词必须带归属**——「这只手/那张脸」无先行词时模型会**自己补一个主体**，一律写「她的一只手/他的右手」（C20b）；③ **抽象形态·程度副词一律删**——「成线/成串/如注/轻蜷」描述的是**模型无法命名的过程形态**（❌「漏雨成线砸在手背上」+「手指轻蜷」→ ✅「雨滴砸在手背上溅开」）。**判据一句话：这句里每个词都能画出来吗？画不出来的就是形容词——删掉或换具象动作。** ④ **反光道具零光效描写**——光斑/受光/照射/亮起类从句一律不写，只写材质本色（C20d）。机检 C20a~d 兜底。
24. **示范句验证纪律（治"规则层产毒"）**：历轮废镜的共同源头是**示范句先验创作**——当轮凭理解新造、未实拍验证就写成 ✅ 正例（甚至嵌进机检修复建议文案），产物照抄后成为下一轮翻车源。铁律：**正例只准从实拍通过的产物回收【实证】；新造句必须标【待验证·未实拍】且禁入机检修复建议文案；修复建议只写判据不造句；判据升级必须同轮清扫全部下游文档**。规程见 `model-adapters.md` §5.0.5，包级机检 **⑰ 规则自洽门**兜底。
27. **打斗史诗规程（一镜到底群战）**：**阵营色彩锁**（敌我冷暖两套色全片禁互串）/ **超音速 Z 型移位三件套**（折点残影·轨迹连线·终点凝实 + 音爆锥）/ **群战递增铁律**（敌数单调递增绝不回落、杀伤成片成排）/ **武器形态单次变形**（全片只变一次、五步完整演出、禁凭空换模）/ **蓄力涡旋与尾帧定格** → `sd-xuanhuan-engine/references/epic-battlefield-protocols.md`；**冲击帧分级**（一/二/三级，三级同场只 1 次 + 3 帧白闪）与**战斗负面词库** → `sd-combat-engine/references/impact-frame-and-banlist.md`。**均为打戏可选增强，按场面需要启用。**
28. **画风锁交付纪律（I 锁 · 方案通称 F 锁）**：① **两层架构**——选项层可用导演/工作室名，**交付层（投喂稿）绝不出现人名/工作室/影片名**（C23d1）；② **转译责任在系统**——选定后必须按 `director-param-library.md` 落 11 槽位量化参数、组装段8/段9 成品块**逐字植入**，禁把「徐克风」类模糊词写进提示词（C23d2）；③ **段8 定区间、镜头段落区间**——镜头段光比/焦段/帧率取值必须落在段8 区间内（C23b）；④ **题材硬门槛**——含打斗稿禁用打戏承载 ≤★1 的风格（C23e）；⑤ **单镜纪律**——一镜只建 1 个全身人物（交接拆两镜）、动作意图 ≤2 项（C23f）；⑥ **选定即冻结**——中途换风格 = 重开任务。规程见 `style-bible/director-to-prompt-protocol.md`，交付规范见 `style-bible-spec.md`。

**分级处置（替代"一切 FAIL 一刀切清零"）**：

| 级别 | 范围 | 处置 |
|---|---|---|
| **P0 · FAIL** | 格式错误 / 模型版本错误 / 画幅错误 / 时间轴非整数秒 / 字段缺失 / 2.0 出现首尾帧 | **必须清零才交付**（机械可判定，无解释空间） |
| **P1 · WARN** | 结构缺陷、镜长节奏雷同、分段落在碎段区 | **必须处理，或书面说明为何保留** |
| **P2 · 语义风险** | 空间 / 遮挡 / 轴线 / 动作物理 / 视线 / 情绪 | **必须由 AI/人工复核后放行**——机器不判死，但**必须留下复核记录** |

> **一句话**：「FAIL 清零才交付」**只适用于 P0**；P2 是"必须复核"，不是"必须为零"。

### 套装共享契约（子技能已内置）

> 13 条契约的**权威文件**列在各条内。子技能引用不复述细则——**复述即三套口径**。

1. 锁系统（〇·1/A/B/C/D）**只在总控〇节定义**，子技能引用不重复；
2. 七段式唯一权威 = 总控 `model-adapters.md` §5；子技能禁另立格式；
3. 资产编号「图N」/《资产图册》/《剧组产出册》口径统一走总控；**禁用外部包英文编号前缀（CH/SC/PR/ST/NP）**；
4. 出稿机检 `validate_prompt.py`（C1~C26＋增量主码 C27~C41 / `--plugin` / `--c23` / `--combat`）位于总控 `scripts/`，FAIL 清零才交付；
5. 时间轴整数秒口径；Seedance 2.5 / 2.0 语法彻底分开禁混写；
6. 决策层《情绪锚点表》是分镜层输入依据，其 80% 核心组合为锁死项；
7. **投喂层闸门不是"另一套质检"**（P14 判据级去重）：闸门只管 C 系没有的七类（节奏档位/台词时长/段级字数/交接话术/图号上限/图号越库/素材形态），其余判据一律由 C 系机检唯一实现；出稿**只跑一次** `gate_check.py`（内部自动拉取 C 系结果），不再两套工具各查一遍；
8. **台词承接**：分镜层默认**全量承接**上游台词，需精简必须出清单并经用户确认；投喂层须跑台词完整性对照——**任一层都不得静默删台词**；
9. **素材来源**：〇·1 由用户锁定，采集规程权威在 `sd-recon-engine/`；《对标情报卡》是**来源**不是**设定依据**——进剧本层须保留 T1/T1.5/T2 分级，**禁把 T2 讨论升格为事实**；轻量版边界不得自行扩张（打分/门槛/聚簇/台账/定时抓取均不在本版）;
10. **场面调度与站位分两层**：导演决策层（怎么站、权力怎么用空间说、何时切镜）→ `blocking-direction.md`；投喂执行层（怎么写进提示词）→ `asset-spatial-ledger.md` §三 + `model-adapters.md` §5.0。**图写在导演稿里，字写在投喂词里**——投喂词仍禁任何形式的图（ASCII 草图/坐标表/俯视图/初始图+位移链）。下游只读继承，不得另起一套逻辑；

### 极速直出模式的套装编排

> **前置：两档运行模式（先分清，再执行——治"严格锁 vs 极速直出"的口径冲突）**
>
> | 模式 | 触发 | 〇·1 素材来源 | A 模型 | B 画幅 | C 交付 | D 段缝 |
> |---|---|---|---|---|---|---|
> | **严格模式**（默认） | 普通需求 | **必须用户指定**，未指定 = 停下询问 | **必须用户指定**，未指定 = 停下询问 | **必须用户指定**，未指定 = 停下询问 | **必须用户指定**，未指定 = 停下询问 | 多段任务必问 |
> | **极速模式** | 用户说 `跳过确认，直接出整集` | 允许按需求**软推断**（交付首行写明推断结果） | **仍必须用户指定／确认——不推断、不默认** | **仍必须用户指定／确认——不推断、不默认** | **仍必须用户指定／确认——不推断、不默认** | 多段任务必问 |
>
> **为什么只有素材来源可软推断**：它只决定"从哪起手"，推错可回退；而 **A 模型 / B 画幅是决定下游产物格式的技术锁**（提示词语法、参考图能力、API `aspect_ratio` 回填），推错 = 整包产物作废；**C·交付形态决定最终交付件**（离线看板 / md / 两者 —— ★ 2026-10-13 已由「可默认 ③」升格为强制锁）——替用户猜 = 可能白编译一份他并不需要的看板，**故极速模式也不得替用户猜**。若需求里确无 A/B/C 信息，**极速模式仍须停下来问**——"跳过确认"只跳过过程确认，**不跳过锁**。
>
> **口径优先级**：本表 > 本文件 §〇「任一项未指定 = 任务不开始，禁止默认跳过」。**极速模式是对〇节的明文例外，例外范围仅限〇·1**——〇·1 之外的任何"默认"仍然禁止。

`跳过确认，直接出整集` 时按管线顺序执行，**每阶段仍必须按上方【强制读取清单】显式读取对应子技能文件**（"跳过确认"只跳过向用户提问，不跳过读规则、也不跳过 A/B 锁）：**〇·1 定素材来源**（需求里出现"对标 / 参考某部剧 / 最近什么火"→ ③/④ 并加读 `sd-recon-engine`、先出《对标情报卡》；给的是小说/原著 → ②；否则 → ①；**素材来源推断结果须在交付首行说明**）→ **A/B 锁仍须用户指定或确认**（需求未含模型或画幅信息 → 停下询问，**不得推断、不得默认**）→ ⓪ 读 sd-decision-engine → 出情绪锚点表 → ① 读 sd-script-engine 六阶段编剧链（可跳过：已有剧本时）→ **素材形态默认 M1**（用户没提图：出图号 + **《素材接线单》**；说"没有图/不要图号"→ 降 M0 改文字锁；说"图出好了"→ 升 M2；**形态须在交付首行声明**，见 `asset-delivery-modes.md`）→ ② 读 sd-asset-engine → 三清单+**按形态产出**（M0 外观档案复述块 / **M1 出图提示词+编号+接线单** / M2 分批出图；九宫格按模板字段写全；**核心场景另交坐标系与 SET_STATE 状态变体登记**，见 `asset-spatial-ledger.md` §四）→ **②′ 调度环：读总控 `blocking-direction.md` → 建场景坐标系与文字平面图 → 摆人物初始位 → 逐拍走节拍闭环 → 定权力几何 → 记道具账 → 选唯一镜头策略模式**→ ③ 文戏读 sd-storyboard-engine；**同段若含群像（调度环已标 `群像：A/B`）必加读 `short-drama-director/references/crowd-behavior-direction.md`**——画面里每个可见的人必须派到一件自己的事，`（在场）` 一律升级为 `（在场·事务：）`、站位声明四要素升五要素（机检 C40 只查开（A/B）门，C 类段只查一句「无其他人物」声明）；打戏按档分流——通用武侠读 sd-combat-engine / R3 玄幻读 sd-xuanhuan-engine / R1 真人写实读 sd-real-engine → **③′ 图形化环：读 `sd-storyboard-engine/references/storyboard-sheet-template.md` → 每段一张故事板图（动作相位七态拆格；文戏默认 2×2 四宫格 ≥4 格 / 打戏默认 2×3 六宫格 ≥6 格）→ 出 CLEAN_GRID 无文字版**（跨 2 镜以上叙事段/打戏段/重场戏必出）；**另读 `sd-storyboard-engine/references/plot-deduction-grid.md` 按条件必出规则出场次剧情分镜格**；**两件都逐段/逐场写进 P3 图形化交付清单，不出须写「⛔豁免 + 理由」，禁静默跳过** → ④ 读 sd-feed-engine → 过投喂层闸门并封装 → ⑤ 读 sd-qc-engine → 台账+机检 → ⑥ 总控看板输出。
