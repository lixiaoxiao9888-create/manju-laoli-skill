# 规则三分类与统一裁决（rule-taxonomy-and-verdict）

> 定位：本包规则散落在**总控 + 10 个子技能 + 51 份总控规则库（全包 129 份）**里，数量已过千条。**规则越多，"两条规则打架时听谁的"就越常发生**。本文件只解决两件事：① 给每条规则**定级**（硬约束 / 条件约束 / 创作建议）；② 给每次判定**定态**（PASS / WARN / FAIL）。**不新增业务规则**，只做治理。
>
> 权威边界：本文件是**分类与裁决口径**的唯一权威；具体规则内容仍以各自规则库为准。

---

## 一、为什么必须三分类

现状（治理前的三类典型事故）：

| 事故 | 病根 |
|---|---|
| 执行者被一条"建议"卡住，反复问用户 | 建议**被当成硬约束** |
| 两条规则冲突，执行者自行选了一条，出片才发现选错 | 缺**裁决顺序** |
| 一个必须修的项只报了 WARN，交付后翻车 | 判定**状态用错** |

**三分类解决"该不该停"，裁决顺序解决"听谁的"，三态解决"能不能交付"。**

---

## 二、三分类：定义 · 判定法 · 包内实例

| 级别 | 定义 | 违反后果 | 判定三问 |
|---|---|---|---|
| **硬约束**（Hard） | 不满足即**产出不可用 / 违规 / 不可交付** | **FAIL**，禁止进入下一阶段 | ① 违反它会不会让产物**无法使用**？② 它是不是**前置锁/红线**？③ 它有没有写"禁止/必须/不得"且**无例外分支**？——任一为是 → 硬约束 |
| **条件约束**（Conditional） | **触发门满足时**等价于硬约束；门不满足时**完全不适用** | 门内 FAIL，门外不判 | ① 它有没有明确的**触发条件**（如"仅打戏稿""仅 2.5""仅 M2"）？② 门外出现是否属于**误报**？——两问皆是为是 → 条件约束 |
| **创作建议**（Advisory） | 影响**质量高低**，不影响**能否交付** | **WARN**，可修复也可写明依据不改 | ① 不采纳它产品还能不能用？② 它是不是"推荐/建议/优先"措辞？——皆是为是 → 创作建议 |

**包内实例对照**：

| 规则 | 级别 | 依据 |
|---|---|---|
| 前置锁定 A（模型版本）/ B（画幅）未指定 = 任务不开始 | **硬约束** | 前置锁，无例外分支 |
| 七段式七栏齐备 | **硬约束** | 缺栏则投喂稿件结构不成立 |
| 平台红线（血腥 / 断肢 / 裸露类直白词） | **硬约束** | 违规即不可交付 |
| 打戏激烈度下限（位移 / 接触 / 贴身占比） | **条件约束** | 触发门＝打戏稿；文戏稿完全不判 |
| 画风锁机检 | **条件约束** | 触发门＝稿内含画风锁块或登记了来源风格 |
| 镜长雷同告警（节奏缺乏呼吸） | **创作建议** | 不改也能出片，改了更好 |
| 无台词镜时长上限 | **创作建议** | 属"防拉伸凑时"的优化项 |

> 🔴 **误分级的代价**：把条件约束当硬约束 → 文戏稿被"打戏规则"无谓拦截；把硬约束当建议 → 该停的不停，错误累积到成片。

## 三、冲突裁决顺序（四级优先链）

两条规则打架时，**按序判定，高序胜低序**：

```
① 用户当轮明确指令
       ↓ 无
② 前置锁定（A 模型版本 / B 画幅 / C 交付形态 / D 段缝 + 〇·1 素材来源锁）
       ↓ 未涉及
③ 级别比较：硬约束  >  条件约束  >  创作建议
       ↓ 同级
④ 权威比较：专档 > 总纲；「唯一权威」声明方 > 引用方
       ↓ 仍不可判
⑤ 停下，写进报告，由用户裁定 —— 禁止执行者自行选边
```

**第 ④ 级的操作口径**：
- 文件里写了「**本文件是……的唯一权威**」「以本文件为准」的，是**声明方**，冲突时它胜；其余为引用方。
- 总控与子技能冲突：**术语与口径以总控为准**（机检码 / 时间轴 / 语法分离等），**领域专精规则以子技能为准**（如打戏档位路由、剧本六阶段链）。
- 同文件内条目冲突：以**更具体者**为准（如"共 6 条铁律"与"仅打戏稿生效的 3 档"冲突时，后者更具体）。

> ⚠️ **第 ⑤ 级不是失败**。规则覆盖不到的现实情形，正确动作是**停下来问**，不是挑一条凑合——凑合出来的产物无法验收。

## 四、PASS / WARN / FAIL 三态定义（跨阶段统一）

| 状态 | 含义 | 处置 | 能否进入下一阶段 |
|---|---|---|---|
| **PASS** | 无可执行问题 | 直接放行 | ✅ 可以 |
| **WARN** | 存在风险，但**可控或可豁免** | **逐条二选一**：① 修复；② 写明"不改的依据"（如触发门不适用 / 已在别处满足）。**禁止不写依据就放过** | ✅ 可以（依据必须留档） |
| **FAIL** | 违反硬约束或前置锁 | 必须修复并**复验**；不得带 FAIL 交付 | ❌ 不可以 |

**各阶段三态落点**：

| 阶段 | 主要判什么 | 典型 FAIL | 典型 WARN |
|---|---|---|---|
| 剧本门 | 结构 / 卡点 / 台词念得完 | 剧情矛盾、台词明显超长 | 钩子偏弱、情绪节拍偏平 |
| 资产门 | 三清单齐备 / 编号连续 / 与文字档案一致 | 锚点无对应物 | 资产描述可再细 |
| 分镜门 | 站位 / 轴线 / 景别阶梯 | 轴线未声明、摆位不入画 | 镜长雷同、单镜偏长 |
| 投喂门 | 七段式 / 机检码 / 红线 | 缺栏、平台红线词、**接续状态残留（C11 反转：出现即 FAIL）** | 语气位缺失、否定式残留 |
| 成片门 | 连续性 / 转场 / 声音 | 跨段穿帮、切点非法 | 混音比例可优化 |

**与机检的映射**：`validate_prompt.py` 的 `issues` 对应 **FAIL**，`warnings` 对应 **WARN**，二者皆空即 **PASS**。**注意**：机检只覆盖可机械判定项——机检 PASS 不等于阶段 PASS，语义门（轴线 / 遮挡 / 物理）仍须人工过。

---

## 五、怎么用（执行者三步）

1. **定级**：拿到一条规则，先用 §二 的「判定三问」定级；定不出级别 = 规则本身写得不清，提 issue。
2. **定态**：判定结果按 §四 落成 PASS / WARN / FAIL；WARN 必附依据。
3. **冲突走链**：遇到两条规则打架，按 §三 四级链走；走到 ⑤ 就停下问，别自行选边。

> 🔗 **配套**：机检码的完整说明见 `references/machine-check-manual.md`（判据码清单、触发门、P0~P2 与机检先后关系）。判据的**行为验证**由使用方按需自建回归样本，本包不随带测试资产。
